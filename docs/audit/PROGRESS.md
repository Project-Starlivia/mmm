## 判断ログ

- **フェーズ3のテスト実行系**: 依存を足さずに `node --test` を使う。
  MoonBit コアは JS にビルド済みなので Node から直接 import できることを実測で確認
  (`core/_build/js/release/build/js/js.js` は ESM で clean な named export)。
  `src/relevel.ts` も Node 24 の型ストリップでそのまま import できることを確認。
- **フェーズ3の「往復」の定義**: このアプリはツリーをテキストへ直列化し直さない
  (テキストが保存形式そのもの)。そこで往復を次の 4 種に分解して検査した。
  (a) `initDoc` → `getText` のバイト同一性、(b) 再パースのツリー一致、
  (c) 構造コマンド → undo のバイト復元、(d) hide→show・copy→paste の可逆性。
  素朴な (a)(b) は全て通り、欠陥は (c)(d) と id 層に出た。
- **フェーズ4の計測環境**: Claude_Browser のペインは `document.hidden === true` で
  `requestAnimationFrame` が発火しない(2.5秒で 0 フレーム)ことを実測。
  フレーム計測が成立しないため、**リポジトリ外のスクラッチに Playwright を導入**して
  ヘッドレス Chromium で測り直した。`package.json` / `pnpm-lock.yaml` は無変更。
- **ヒープ計測**: `performance.memory` は Chromium が量子化しており 400 回編集の
  前後で完全同値になったため使用を中止。CDP の `HeapProfiler.collectGarbage` +
  `Runtime.getHeapUsage` に切り替えた。detached ノード数はヒープスナップショット
  解析が必要なため未計測(PERF.md 0 節に必要なセットアップを記載)。
- **MAP.md の未確認事項のうち 3 つは監査本体で解決済み**:
  `moon test` は 44/44 pass(監査中に実行)、`js.d.ts` は生成済みで存在、
  アプリは実際に起動して実機確認済み。MAP.md はフェーズ1時点の記述として残す。

## 再実行を待つ間に追加で確定させたこと

- **F-010(最重大)**: CRLF の .md で md ペインに 1 文字打つと、
  CodeMirror(LF 正規化)とコア(CRLF 保持)のオフセットがずれ、
  **6 文字ずれた位置に書き込まれて表示と保存内容が乖離する**。
  実機で確認: `## gamma` 行末に `Z` → コアは `##Z gamma`、
  マップからノードが 1 つ消滅。コア単体の往復テストは CRLF を通しており
  **コアは正しい**。壊れているのは UI とコアの継ぎ目で、そこを検査する
  ものが 1 つも無い(MAP.md 6.3 の指摘がそのまま顕在化)。
- `audit/identity-matrix.md` を新規作成。19 通りを実測し、
  **id を失うのは「見出し先頭ちょうどの純削除」1 パターンのみ**と確定。
- その結果 **F-004 の記述を訂正**。初版の「outdent は必ず id を捨てる」は誤りで、
  正しくは **「対象が親の最後の子のときだけ」**(後続の兄弟があると
  ブロック移動が走り `move_block` の `at_hs` で復元される)。
- **修正コストも下方修正**。`#` を「削除」ではなく「ハッシュ列の置換」として
