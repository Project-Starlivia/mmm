## 束の増減で、それ以降の左右が入れ替わる（解決）

**方針**: 交互配置はそのまま。ただし **D&D / マップ側の操作では並びのほうを
書き直して左右を保つ**。テキストを直接いじったときは何もしない。

束の左右は「その位置より前にある区切りの本数」の偶奇なので、テキストの並びは
**右の列と左の列を上から交互に差し込んだもの**になっている。

```
テキスト:  束0  束1  束2  束3  束4
右の列:    束0       束2       束4
左の列:         束1       束3
```

この形なら、**保ちたい左右が決まればテキストの並びは一意に決まる**。
なので操作のあとに、その並びへ書き直せばよい（`core/bundles.mbt`）。

出発点を 右[a c] 左[b d] として、実測した比較（新しい束を `新` と書く）:

| 操作 | 直す前 | 直したあと |
|---|---|---|
| b の手前に新しい束 | 右[a b d] 左[新 c] ← b c が反転 | 右[a c d] 左[新 b] ← d だけ移動 |
| c の手前に新しい束 | 右[a 新 d] 左[b c] ← c d が反転 | 右[a 新 c] 左[b d] ← **誰も動かない** |
| d の手前に新しい束 | 右[a c d] 左[b 新] | 同じ（末尾なので元から差が出ない） |
| 束 b を消す | 右[a d] 左[c] ← c d が反転 | 右[a c] 左[d] ← **誰も動かない** |
| 束 c を消す | 右[a d] 左[b] | 同じ（末尾なので元から差が出ない） |

いちばん下の束をいじるぶんには元から差が出ない。差が出るのは**途中**をいじったとき。

書ける形は「右の数 - 左の数 が 0 か 1」まで（先頭の束はルートの見出しを含む
＝必ず右で、そこから交互なので、片側だけ 2 つ多くはできない）。そこをはみ出す
操作のときだけ、**いちばん下の束が 1 つだけ**反対側へ移る。以前はこれが全部の
束に起きていた。

**ついでに直した**: 左へドラッグしたのに右に束ができることがあった。新しい束は
テキストの末尾に足すので、束の数の偶奇で反対側に出てしまっていた。落とした側を
コアに渡して並べ直すようにした（`moveNewGroup(ids, target, side)`）。

**触らない場合**:

- 束が 2 つ以下（並べ替えても同じ形にしかならない）
- 束をまたぐ hide 領域があるとき（並べ替えるとマーカーの対が割れる）
- ルートの範囲の外に区切りが残っているとき（一部しか並べ替えられない）

並べ替えは 1 つの編集としてトランザクションに積むので、**undo は 1 回**。
ノードの id は本文の頭からの距離で拾い直すので飛ばない（選択も折り畳みも残る）。

# `---` の意味論の作り直し（2026-08-14）

グルーピング（束）を第一級の概念から降ろした。設計の経緯は会話ログにあるが、
結論だけ書くと: **「側の自由・順序の安定・導出レイアウト」は同時に成立しない**。
束を単位に側を保とうとすると、並べ替え・最下段の譲り・偶奇の帳尻という
機構が芋づるで必要になり、md も見た目も嘘をつき始める。

## 新しい意味論 — 読みは寛容に、書きは保守的に（Postel の法則）

- **パーサー（読み）**: どの `---` も一律「そこから下のルート直下は左右が
  入れ替わる」。複数あってもそのまま読む（既存文書の表示は不変）
- **道具（書き）**: 区切りを書くのは「空の左側へ最初のノードを置く」1 本だけ。
  他の操作は全部、既存ノードの隣への局所編集。**堆積が構造的に起きない** —
  複数の `---` がある文書は、常に人間が意図して書いたもの
- **掃除**: `---` を 1 本消すと下の左右が全部反転する。だから空いた区間の
  区切りは**偶数本ずつ**消す（中間 = 両脇 2 本 / 末尾 = 手前 1 本だけ /
  先頭の区間が空いて残る「タイトル直後の `---`」は「全部左」の表現なので残す）

## 消えたもの（グルーピングの負債ゼロ）

- コア: `restore_bundle_sides` 一式（bundles.mbt 317 行 → seps.mbt 117 行の
  掃除だけに）、moveNewGroup / moveNewGroupBefore、add 系の split パラメータ
- UI: Ctrl+ドラッグの新束モード、groupSlotAt、needsSplitFor、pos 5、
  自動 split。Ctrl はクリックの選択トグルだけに戻った
- 新設: `moveSideEnd(ids, left)` / `addSideEnd(left)`（ルート脇ゾーンと
  左右 ＋ ボタンの実体）
- ついで修正: ルート脇ゾーンがノードの箱の中まで横取りし得た（best > 0 ガード）、
  区切り掃除の空白行スキャンが CRLF の \r を知らなかった

  漏れない。`Esc` で閉じてフォーカスがマップへ戻る（今日の 2 つの修正が実機で効いている）
- 改行: CRLF の文書を開く→ 追加・改名・側の移動・折り畳み・削除 → 保存、の
  どの段でも LF が混ざらず、全 undo で原文にバイト一致。
  **テストとして残した**（`test/eol.test.ts` の E1〜E3）
- 画像: 未保存の文書では「先にファイルを保存してください」で止まる。
  `![](...)` のプレースホルダとファイル名、インライン SVG の描画も確認

**ディレクトリの整理**: `audit/` は実態がテストスイート本体になっていたので分けた。

| 前 | 後 |
|---|---|
| `audit/tests/*.test.ts` | `test/*.test.ts`（1 階層浅く） |
| `audit/tools` `audit/fixtures` `audit/tsconfig.json` | `test/` 配下へ |
| `audit/*.md` `*.json` `*.html` `raw/` | `docs/audit/`（過去の記録として） |

`docs/audit/README.md` に「ここは過去の記録で、当時のパスと用語のまま」と
明記した（`audit/` も「束」も、もう無いことを含めて）。
`test/tsconfig.json` は playwright を要求する計測ハーネス 3 本だけ型チェックから
外す（理由をコメントに書いた）。

検証: `pnpm test` 41/41 / `pnpm run check` 緑 / `pnpm run build` 緑 /
`gen-load` の出力が移設後も同一バイト。

## md ファイルのライフサイクル（2026-08-15）

「無題／untitled という概念が嫌い。名前は付けるべき」という設計判断から、
**名前を状態ではなく導出に変えた**。`fileName` という変数は消え、
「保存済みのファイル名（無ければ null）」だけが状態として残る。

**命名**（表示にも保存ダイアログの初期値にも同じものを使う。`src/app/name.ts`）:

1. 保存したファイル名 — 以後、見出しを書き替えても追わない
2. いちばん大きい見出しのうち先頭（`#` が最少。同率なら先着。`##` しか
   無ければそれが最大）
3. （2 が整形で空になったら）文書順で最初の見出し
4. `empty`

整形は「使えない文字で分けて `-` で繋ぐ」。空白は残す（ファイル名として
正しいものを削る理由が無い）。長さは **UTF-8 250 バイトで打ち切る** —
`.md` を足しても実際の上限 255 に収まる。日本語 83 文字ぶんで普段は触れない
**安全柵**であり、見た目を整えるためではない。MS-DOS の予約名（`CON` 等）は
末尾に `_` を付ける。原則は「**道具が出す提案は常にファイル名として有効**」で、
失敗してからリトライで拾う案は却下した。

**操作**: `Mod+N`（新規。破棄確認つき。ファイルとフォルダの許可も手放す —
残すと次に貼った画像が前の文書の隣に置かれる）、`Mod+Shift+S`（別名保存。
常にダイアログ）。新規はテキストが空（`# ` を置かない — 置くと新規が即
dirty になり「気軽に扱いたい」とぶつかる）。

**移行**: 既存の localStorage には旧プレースホルダ `"無題.md"` が「保存済みの
名前」として残っている。これは保存された名前ではないので、起動時に空文字と
同じく「まだ保存していない」として読む。

**検証**: `test/name.test.ts` 9 ケース（大きさ優先・先着・整形・切り詰め・
予約名・空）。ブラウザ実操作で、打つそばからタイトルが変わること／保存後は
追わないこと／`Ctrl+S` は上書き・`Ctrl+Shift+S` はダイアログになること／
`Ctrl+N` が確認を出して空へ戻ることを確認。

**ついでに**: ソースに紛れ込んでいた**生の制御バイトを全廃**した
（`\u0000` などのエスケープ表記へ）。ヒアドキュメント経由で書くと制御文字が
そのまま埋まり、grep がファイルを binary 扱いして読めなくなる。
リポジトリ全体の走査で 0 件になっている。

**持たないと決めた**: ファイル名の変更。当初 `FileSystemFileHandle.move()` で
実装できると書いたが、あれは **OPFS 専用**でユーザーが選んだファイルには使えない
（この点は前言の訂正）。代替は「フォルダの許可を取って、新しい名前で作って
古いのを消す」だが、リネームのためだけにフォルダ全体の書き込み許可を要求する
ことになり、しかも**画像を使っている文書では使えて、使っていない文書では
使えない**という状態を生む。見た目と挙動が釣り合わないので、やらない。
名前はエクスプローラで変える。

## localStorage を色とテーマだけに（2026-08-15）

「基本的にはできるだけ使いたくない。使っていいのはブランドカラー、テーマぐらい」
という方針で削った。

| 消したキー | 代わりに |
|---|---|
| `mmm.text` | **持たない**。起動は常にまっさら。続きは `Mod+O` |
| `mmm.savedText` | 開いた内容がそのまま「保存済みの内容」 |
| `mmm.fileName` | ハンドルの `name` から取れる |
| `mmm.eol` | ファイルを読んだときに決まる（セッション内だけ覚える） |
| `mmm.panes` | 毎回、両方表示から始まる |
| `mmm.edgeTune` | tune パネルごと廃止 |

理由は 2 つ。(1) 本文の控えは**ディスクの .md と二重の真実**になる。
(2) `mmm.text` と `mmm.savedText` で同じ文書が 2 部入るので、5MB の枠に対して
2.5MB の md でもう限界。しかも `store()` は容量オーバーを黙って握り潰すので、
大きい文書では「リロードしたら作業が消えていた」が無言で起きていた。

代償は「未保存のスクラッチがリロードで消える」こと。`beforeunload` の警告が
唯一の防波堤になる。

**あわせて**: 起動時に読んでいたサンプル文書も廃止した（毎回のリロードで
戻ってくると、消す手間が要る）。空文書のヒント「Enter で最初のノードを作成」が
そのまま案内になる。旧セッションが残したキーは起動時に片付ける。

**tune パネルの廃止**: `src/edge-tuner.ts`（727 行）と `?tune` の起動、
`MindMap` の `setEdgeParams` / `setGaps` / `tunerEdge`、パネルの CSS、
`edge.ts` の `CARRY_KEYS` / `EDGE_PRESETS` の export を削除。線の値は
ソースに固定されるだけで見た目は変わらない。バンドルは分割チャンクが 1 つ減った。

検証: `pnpm test` 50/50 / 型 OK / ビルド OK / ブラウザで localStorage が
`mmm.color` と `mmm.theme` の 2 つだけになり、起動が空・dirty が立たないことを確認。

### 最後のファイルを開き直す

localStorage を削った直後に「最後に編集していたファイルから始めたい」という
要望が来たので足した。**手戻りではない** — 消したのは本文のコピーで、これは
ディスクへの**指し示し**（IndexedDB のハンドル）。真実は .md のままで、
起動時にそこから読み直す。

- 許可が生きている → そのまま開く。何も聞かない
- 許可が切れている（ブラウザ再起動などでよく起きる）/ ファイルが動いた・
  消えた → **ハンドルを捨ててまっさらから**。聞き返さない
- 読み終わるまでに打ち始めていたら、それを消してまで開かない（読み込みは
  非同期なので、この 1 行が無いと入力を踏み潰す）

問い合わせるのは `read` 権限だけ。保存時の `readwrite` は `Mod+S` 自体が
ユーザー操作なので、そこで改めて要求すれば足りる。

### `Mod+N` はブラウザに吸われる

Chrome は `Ctrl+N`（新規ウィンドウ）をページに渡さないので、`preventDefault`
では取れない（`Ctrl+T` / `Ctrl+W` / `Ctrl+Shift+N` も同様）。**`Mod+Alt+N`**
へ変え、あわせてツールバーに「新規」ボタンを足した（開く・保存と並ぶ位置）。
キーだけだと discoverability がゼロになるため。

## 画像フォルダの明示的な指定

画像フォルダは「初回の貼り付けで黙ってピッカーを開く」形だった。何のための
ダイアログか分からないまま OS の画面が出るうえ、開き直したファイルが別の
フォルダにあっても気づけない。指定を**明示的な操作**に引き上げた。

- `Assets.dirState()` — `none` / `ok` / `mismatch`。`dir.resolve(file)` で
  「このフォルダはこの md を含むか」を見る(許可が無くても答えられる)
- `Assets.chooseDir()` — ピッカーを開いて差し替える。含んでいなければ false
- `showFolderPopup()` — 「フォルダを選ぶ / あとで」＋「次からは表示しない」
- 尋ねる場面は 3 つ: 画像を置く直前 / ファイルを開いた直後 / 別名保存の直後
- 開いた直後だけは `hasLocalImage()` で絞る — 画像を持たない文書に
  フォルダを訊いても意味が無い。判断は文書そのものから導く(状態は持たない)
- 選び直しはツールバーの **フォルダ** ボタン
- 抑止は localStorage `mmm.folderQuiet`(色・テーマに次ぐ 3 つ目の鍵)

`saveToDisk` からピッカーを開く経路は無くなった。フォルダが無い/ずれている
ときは main 側の `askDir` に尋ね、断られたら「画像フォルダが指定されていません」
と伝えて終わる — 道具が勝手に OS の画面を開くことはしない。

### ピッカーを md のフォルダから開く

ブラウザはシステムフォルダ(ドライブ直下・ユーザーのホーム直下など)の許可を
一律で拒否するが、その拒否は**ユーザーがキャンセルしたのと区別できない**
(どちらもピッカー側で完結し、AbortError として返る)。捕まえて案内する道は
無いので、**その状況に入らないようにする**。

`showDirectoryPicker({ startIn: file })` にいま開いている md のハンドルを渡すと、
ピッカーはその md が入っているフォルダを開いた状態で始まる。ユーザーは
そのまま決定するだけで、欲しいフォルダが手に入る — 拒否される場所へ迷い込む
こともなければ、`mismatch` になることもない。

## 画像ファイルの D&D

ブラウザでは「md 一枚の許可」から親フォルダへ辿れないぶん、画像を扱うのに
必ずフォルダの許可が要る。ドロップはこの手間の外側にある唯一の経路 —
落とされたものは `getAsFileSystemHandle()` でハンドルが取れる。

- `Assets.addImage(file, handle)` — 許可したフォルダで `dir.resolve(handle)`
  が通れば、その画像は**既にフォルダの中にある**。複製せず、md からの相対パス
  (`relFrom`)を書くだけで済ませる。外から来たものだけ `saveToDisk` で複製する
- パスの形(`./` か `../`)は assets が決める(`mdPath`)。main は受け取った
  ものをそのまま `![]()` に入れる
- 宛先は `map.nodeAt()` — カーソルの下のノード。外に落ちたものは受け取らない
- 複数枚は同じ tag で挿すので、取り消しは 1 回

`droppedFiles()` は `DataTransferItem` がハンドラを抜けると死ぬため、
**同期的に**ハンドルの promise を掴む。md と画像でこの前処理は共通。

### 「フォルダを選んだのに、指定されていませんと言われる」

`chooseDir()` が、選ばれたフォルダを**含有を確かめる前に**覚えていた。
「画像フォルダ」という呼び方に誘われて `assets/` のような画像用サブフォルダを
選ぶと、そのハンドルが残り、以後ずっと `resolve()` が null を返し続ける。
表示は「画像フォルダが指定されていません」— 選んだ直後なので意味が通らない。

- 含有を確かめてから覚える。含まないフォルダは受け取らない
- 失敗の言い分けを分ける。「指定されていません」と「含んでいません」は別のこと
- 問い自体の言葉を直す。訊いているのは画像置き場ではなく、**md 自身が
  入っているフォルダ**。ボタンも「md のフォルダを選ぶ」に
- 結果を名乗るのは 1 箇所だけ。`pickAssetDir(report)` — ツールバーから
  押したときは自分で名乗り、問いの流れの中では黙って呼び出し元に任せる
  (「設定しました」の直後に失敗が上書きされる、を潰す)

あわせて、貼り付け経路の `try` がクリップボードの読み取りだけでなく画像を
置く処理まで囲っていたのを分けた。フォルダ選択の失敗が「クリップボードが
読めなかった」と同じ扱いになり、黙ってテキスト経路へ落ちていた。

### 保存でフォルダを訊かない

別名保存の直後にもフォルダを訊いていた（「置き場所が変わりうるから」）。
これは筋が悪い — **md の読み書きにフォルダは一切要らない**。要るのは画像を
読む/置くときだけで、保存はそのどちらでもない。訊く場面は 2 つに減った:

- 画像を置く直前（無条件）
- 画像を持つ文書を開いた直後（`hasLocalImage`）

別名保存で置き場所が変わって画像が読めなくなったときは、サムネイルが
プレースホルダに変わることで伝わる。直す道はツールバーの **フォルダ**。
黙って壊れるのは良くないが、要らない場面で訊くのはもっと悪い。

## Tauri へ移行 — 画像/許可問題を環境ごと消す

画像フォルダの許可 UX を何度も設計し直したが、根本はブラウザの制約だった:
`FileSystemFileHandle` から親フォルダへ辿れない(WICG #193 で明示的に却下)。
「md 単体 + 隣の画像を相対パスで読む」を両立させると、必ず 2 つ目の許可が
要る。出荷済みのブラウザ製アプリを調べても、相対パスのローカル画像を出す
ものは例外なくワークスペース(フォルダ)を先にもらう形に倒しており、
「ファイル単体 + 相対画像」を綺麗に解いた前例は無かった。

そこで [Tauri](https://tauri.app/)(WebView + Rust)へ移した。UI と MoonBit
core は 1 行も変えず、**ファイル I/O 層だけ**を差し替えている。

**Rust 本体(`src-tauri/src/lib.rs`)が持つもの**:
- パスの所有(UI はテキストと表示名だけ。パスを一切見ない)
- open/save/save_as/close — 保存は temp→rename のアトミック書き込み
- 起動時に前回のパスを app-config から読み、開き直す(`startup_doc`)
- 画像の解決(`resolve_image` — md の位置を基準に `../` も辿る)と、
  複製せず指す(`relativize`)/ 複製する(`import_image`)/ 書く(`save_image`)
- **外部変更の監視**(notify)。親フォルダを見て temp→rename の挿げ替えにも
  耐え、自分の保存はハッシュ照合で黙らせる。`doc:changed`/`doc:removed` を emit
- CRLF/BOM の吸収(UI は常に LF)

**消えたもの(ブラウザの残骸)**:
- File System Access API 一式(`showOpenFilePicker`/`showDirectoryPicker`/
  `createWritable`/`queryPermission`)、その型シム `fs-access.d.ts`
- IndexedDB のハンドル永続化(`idbGet`/`idbSet`)
- 画像フォルダの許可・含有チェック・`assetSegs`/`relFrom`/`dirState`/`chooseDir`
- フォルダの問い(`showFolderPopup`)、抑止フラグ `mmm.folderQuiet`、
  ツールバーの **フォルダ** ボタン

**新しくできること**: `../` や別ドライブの画像、md をどこにでも単体で置ける、
起動時の無音の復元、外部変更の検知。許可の問いは 1 つも無い。

`localStorage` は当初の狙いどおり色とテーマの 2 つだけに戻った。
