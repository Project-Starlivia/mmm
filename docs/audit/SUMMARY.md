## 全体像

**土台は堅い。** 「テキストが唯一の真実」という主張はコアに関する限り本物で、
実 `.md` + ランダム 400 通り + 病的入力 29 通りで parse→serialize がバイト同一、

markdown 由来のスクリプト実行も、実際に攻撃入力を食わせて閉じている(S-001/S-002)。

## 1. 根本原因

### R0. UI とコアの継ぎ目に、不変条件を検査する仕組みが 1 つも無い 🔴

コアとブラウザ側はそれぞれ独立に正しいのに、**両者が同じテキストを見ている
という前提を誰も確認していない**。`audit/MAP.md` 6.3 が
「両ペインの収束を検証する仕組みは、テストにもランタイムのアサートにも存在しない」
と書いた箇所が、そのまま最悪の欠陥として顕在化した。

**F-010(実測で確定、本監査で最も重い)**:
CodeMirror は読み込んだ文書の改行を内部で **LF に正規化する**が、コアは
生テキストを **CRLF のまま**保持する。`onUserEdits` は CodeMirror の
LF 基準オフセットをそのままコアへ渡すため、**その位置より前にある改行の数だけ
書き込み位置がずれる**。

実測(`# root\r\n\r\n## alpha\r\n\r\n## beta\r\n\r\n## gamma\r\n` で `## gamma` 行末に `Z`):

| 観測点 | 結果 |
|---|---|
| md ペインの表示 | `## gammaZ`(正しく見える) |
| コアの実データ | `##Z gamma` — **6 文字ずれた位置に入った** |
| マップのノード | `[root, alpha, beta, gamma]` → **`[root, alpha, beta]`**(消滅) |

**Windows で作られた .md はほぼ CRLF** なので、対象は例外的入力ではない。
見えているものと保存されるものが食い違うため気づけず、`Mod+S` で
壊れたテキストがディスクに書かれる。ずれ幅は文書の下ほど大きくなる。

なぜ既存テストで見つからなかったか: コア単体の往復テストは CRLF を通しており
**コアは正しい**。壊れているのは継ぎ目で、そこを見るものが無かった。

### R1. 描画が「毎回すべて作り直す」

`applySnap`(`src/main.ts:197`)が無条件に `map.render()` を呼び、
`render()` は `replaceChildren()` で全 SVG 要素を捨てて作り直す。

**実測**: 入力遅延 ≒ `1.11ms + 0.00263ms × SVG要素数`(6 サンプルで良好に当てはまる)。
261 ノードで 4.6ms、2,001 で 25.8ms、**5,000 で p50 70.2ms / p95 100.9ms**。
時間の行き先は JS ではなくブラウザ内部の style/layout。
**5,000 ノードの文書では 400 文字打つのに 80 秒**。

対照: パン/ズームは `transform` 属性 1 つの書き換えで `render()` を通らず、
全サイズで **60fps を維持**(フレーム落ち 0)。遅さは「大きいこと」ではなく
「毎回作り直すこと」に由来する。

ぶら下がり: F-002 / F-003 / F-008(IME 中間候補ごとに全再構築)/
画像 1 枚のロードごとに `render()` / インライン `<svg>` の再エンコードが毎レンダ。

**将来の詰まり**: DOM 同一性が毎回壊れるので、アニメーション・折り畳み・
部分更新・仮想化・フォーカス保持は現状の `render()` の上に載らない。

### R2. ノード同一性が代理キーで、規則が非対称

19 通りを実測(`audit/identity-matrix.md`)した結果、
**id を失うのは「見出し先頭ちょうどの純削除」1 パターンのみ**(17 通りは保存)。
`map_offset` は同じ位置の**置換**なら「行の書き換え」として生存させるのに、
**純削除だけ無条件に破壊扱い**にしている。

そのため outdent は**対象が親の最後の子のときだけ** id を落とす
(後続の兄弟があるとブロック移動が走り `move_block` の `at_hs` で復元される)。
id はユーザーの選択集合の鍵なので、その場で選択が消える。

**この修正は極めて安い**: `#` を「削除」ではなく「ハッシュ列の置換」として
出せば、テキストはバイト同一のまま id が保たれる(実測確認済み)。
コアの同一性機構は無変更でよい。

### R3. 「ルートは最初の `#` だけ」がテキスト側に反映されていない

2 つ目以降の `#` はノード列から外されるが、テキストからは消えず、
**直前のノードの部分木範囲からも除外されない**。

**F-005**: 地図で 1 ノードを選んで `Delete` すると、選択していない `# 見出し` 行ごと
消える。コピーでは逆に混入して増殖し、hide では巻き込んでコメントアウトされる。
**README が「行は保存される」と明記している動作と矛盾する。**

同型の問題が hidden マーカーにもある(フェーズ5 で CONFIRMED):
非表示ノードのカット/コピーで `<!--` と `-->` の対が割れ、
**以降の文書全体が非表示化する**。非表示ノードの削除でも `<!--` が取り残される。

### R4. 永続化に単一の書き手がおらず、書き込みが原子的でない

**F-009**(実機で 2 タブ再現): タブ B の編集がタブ A の編集を黙って上書きする。
A の画面には残っているのに永続層からは消えている。

CONFIRMED で他に 17 件。とくに重いもの:
- `loadText` は `mmm.fileName` / `mmm.savedText` を同期で書くのに `mmm.text` は
  250ms 後 — **この窓で落ちると「別ファイルの中身」を新ファイル名で復元し、
  1 回の保存で別ファイルが失われる**
- 復元した `fileHandle` を**ベース名だけで照合**(`isSameEntry` を使っていない)
  → `README.md` のような同名ファイルを複数ディレクトリで扱うと別の場所を上書き
- `QuotaExceededError` を握り潰し、しかも文書を 2 重に保存していて上限に早く当たる
- 起動時の `localStorage.getItem` だけ try/catch 外 → ストレージ禁止環境で起動不能

### R5. 信頼境界が無い(他人の .md を開く前提が置かれていない)

**スクリプト実行は閉じている**(S-001/S-002、実際に攻撃入力で検証済み)。
だが**ファイル読み出しは閉じていない**。

`parseImage` はスキームの無い相対パスを全て受理する(実測で
`![](secret.txt)` `![](../../.env)` `![](sub/dir/id_rsa)` が受理されることを確認)。
`loadAsset` は MIME も拡張子も見ずに読み、`exportSvg` は `blob:` の中身を
**型を問わず base64 で埋め込む**。
→ 信頼できない .md を開き、フォルダ許可を与え、SVG を書き出して共有すると、
**許可フォルダ内の任意ファイルの中身が SVG に載って外へ出る**。

併せて: CSP が無い / フォルダ許可がオリジン単位で永続化され「最初のクリック」で
無言で復活する / リンクカードが遷移先 URL をどこにも表示しない(表示名詐称が通る)。

### R6. 破壊的操作にガードが無い

フェーズ5 で CONFIRMED になったもの:
- **CapsLock ON で `h`(移動)が `H`(サブツリーをコメントアウト)に化ける** —
  大文字判定が `e.shiftKey` を見ていない
- **`d` を押しっぱなしにすると連続削除される**(キーリピートのガードが無い)
- お絵描きポップアップだけフォーカスを移さず、**モーダルの裏でマップの
  ショートカットが全部生きている**
- **D&D のドロップ先が常に「1 つ前の兄弟」に奪われる**(`BAND=40` が兄弟ピッチを
  丸ごと飲む)。再親付けの中核が壊れている

### R7. 保守性

`src/mindmap.ts:109` の生 NUL バイトで **grep/ripgrep が最大のファイルを
検索から除外する**(F-001、本監査でも実際に踏んだ)。
TypeScript のテストが 1 件も無い(`src/` 全 3,502 行が未テスト)。
`build` が `test:core` を含まない。到達不能コードあり。

## 2. 修正順序

```
R0 (改行の正規化 + 継ぎ目のアサート)   ← 最優先。他の全ての調査の前提
 └─→ これを直さないと「保存が壊れる」系の再現条件が特定できない
R3 (重複ルート / hidden マーカーを範囲の境界にする)
 └─→ F-006 の move ガードは同じロジックの一部なので R3 の後
R4 (永続化を原子的に + 単一書き手)
 └─→ 「保存できないときがある」の調査は R4 の後でないと切り分け不能
R5 (画像パス検証 + エクスポート時の型フィルタ)
 └─→ SVG エクスポートを配る運用を勧める前に必須
R6 (破壊的キーのガード)         ← 独立・全て極小
R1 (render のスキップ → 差分更新)
 ├─→ F-003 は R1 の (1) で自動的に無害化
 └─→ 折り畳み・アニメーションは R1 の (2) の後でないと載らない
R2 (outdent の編集の出し方)      ← 独立・1〜2 行
```

**「A を直す前に B」**:
- **何より先に R0** — 改行がずれたまま他を直しても、症状が混ざって切り分けできない。
- **F-006 を直す前に F-005** — 同じ「重複ルート」ロジック。
- **折り畳み・アニメーションの前に R1 の差分更新** — 全再構築の上には載らない。
- **id にひもづく機能の前に R2** — 段上げのたびに黙って消える。
- **SVG エクスポートを共有機能にする前に R5** — 中身が漏れる。
