# 地図が見せるもの — 単語と絵

## 中身は構造ではない

画像やリンクを 1 つのノードとして木に載せる流儀がある（markmap がそう）。
mmm は取らない。

正直どちらでもよい。ただ、マインドマップは本来**単語と絵**でできているもので、
起源というだけで更新されてはいけない理由は無いが、その考え方が好きなので乗る。
単語があり、その脇に絵が置ける形。

すると md に素直な **ラベル + 中身（カード × n）** がそのまま成り立つ。見出しか
項目の 1 行が単語で、その下の本文が絵。今の置き方が落としどころで、これ以上
崩さない。

## 散文は扱わない

散文は絵ではなく字の情報なので、地図には出ない。

md の記法の大半は、画像を使わずに**グラフィカルに表す**ためのものである
（画像ではない。だが絵である）。**グラフィカルに扱う意思があるものは mmm が
解釈する。** 画像は当然として、SVG・表・HTML がそう。コードブロックとリンクも
グラフィカルである、と mmm は言い張る。これはかなり個人の主張なので、受け
入れられないなら「さすがに欲しい例外」と読んでもよい。

つまり、素の散文は解釈されないが、`<p>散文</p>` は解釈される。線はそこ。

採択の線と実装の優先度は別で、表と引用はまだ原文のまま（下の「いま決めて
いないこと」）。線は今日決まり、描くのはその日が来てから。

**「ここに字がある」の印も出さない。** 出した方が親切なのは分かる。だが、これだけ
何でも解釈するようになった以上、解釈したものとしていないものを地図の上で適切に
切り分けて出す形が思いつかない。出さないで行く。

## そこから自動的に決まること

- **SVG はカードのまま。** 画像とも言えるし何でもない物とも言えるが、線は
  「絵として書かれたか」であって「画像か」ではない。`<svg>` は絵として書かれている
- **`<details>` のカードもそのまま。** HTML なので線の内側。ノリで作ったものだが、
  線に照らして残る
- **境界にならなかった水平線もそのまま。** `---` は罫線という絵
- **散文はカードにも印にもならない。** 帰結として、地図から見えない散文を、
  ノードの Delete が本文ごと消す。これは受け入れる。文章は md ペインで読み、
  md ペインで消す。地図は単語と絵を掴む窓で、文章を読む窓ではない
- **地図から書けるもの（`Shift+L` / `Shift+C` / `Shift+D`）は線と無関係。** 書ける
  から描くのではなく、絵だから描く。書けないものでも絵なら描く

## レンダラは拡張的である

画像のパスを画像として出すのを筆頭に、その場で描く（draw）、mermaid（まだ無い）
など、**純粋に自分が欲しいと思ったものを入れていく。**

JSON や SVG のファイルを勝手に表にする、といった話は言われてやる気が出たら
やるが、基本はやらない。あくまで拡張で、自分がやりたいかどうかだけで決まる。

収拾がつかなくなったら plugin として開き、自由にカスタムしてもらう。それまでは、
入れたいものだけを入れ、食べたいものだけを食べる。

## いま決めていないこと

**表・引用の描き方。** 線の内側だが、まだ描く段が無い。描くまでは読み解かない
原文のまま落ちる。render まで繋がっていないものは、種類を問わず全部そこへ
放り込んでよい。
