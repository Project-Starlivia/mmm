# edit — md と操作の境界 実装計画

**Goal:** `edit(md, op) -> { edits, focus }` を 1 本足し、操作（`core/op`）と反映（`core/tree`）を
繋ぐ。UI には触らない。結合は core の中で法則として固定する。

**Architecture:** `core/edit` が `survey → apply → reflect` を繋ぐ純粋な関数。
`core/tree/js` は JSON を受け渡すだけ。TS 側は `coreApi.ts` に `edit` と `Op` の型が入り、
core の JSON の形（`["Tag", {…}]`）を整えるのはそこ 1 か所。

**Spec:** `docs/superpowers/specs/2026-09-04-op-design.md`「境界（別 PR）」

## Global Constraints

- 木は手で組む。法則の総当たりだけが `parse` を使う（入力が md なので）
- コミットは `<Type>: <Emoji> <Title>` の日本語。末尾に `Co-Authored-By`
- 作業は worktree `.worktrees/feat/edit`（枝 `feat/edit`、feat/tree から）
- Windows: moon を呼ぶ前に PATH を前置する。`.mbt` は Write / Edit ツールで書く
- テスト: `cd core; moon test -p mmm-app/core/edit`。整形: `moon fmt`。型: `moon check`

## ファイル構成

```
core/tree/build.mbt          number(doc, id) — 文書順に振り直したときの番号
core/edit/moon.pkg           @tree と @op を import
core/edit/edit.mbt           Edited と edit
core/edit/edit_wbtest.mbt    手で組む例と、Op を JSON から起こす往復
core/edit/law_wbtest.mbt     見本 × Op の総当たり。読み直せば形が一致、focus は同じノード
core/tree/js/exports.mbt     mmmEdit(md, opJson) -> json
src/coreApi.ts               Op / NodePlace / BlockPlace / Edited と edit
test/coreApi.test.ts         Op の JSON の形と、edit の往復
package.json                 test:core / check:core に edit を足す
docs/core.md                 「境界」の節
docs/spec.md                 「構成」に edit/ を足す
```

## 段

1. `number(doc, id)` — 手で組んだ木（新しいノードが max+1 を持つ）で、文書順の番号を返す。
   知らない id は None
2. `core/edit` — `edit` の手例（Rename / できない操作 / AddNode の focus）と、Op の JSON 往復
3. 法則 — `reflect_law_wbtest` の見本 × `apply_wbtest` の Op の作り方で総当たり
4. js の出口 `mmmEdit` と TS の `edit`。TS の試験は組んだ core を通す（`pnpm test` は core を組んでから走る）
5. docs と package.json
