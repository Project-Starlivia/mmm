# 新 core（MmmTree）実装計画

> **エージェント実行者へ:** 必須サブスキル — `superpowers:subagent-driven-development`（推奨）
> または `superpowers:executing-plans` を使い、タスクごとに実装すること。
> ステップは `- [ ]` のチェックボックス形式で進捗を追う。

**Goal:** md と同型の文書モデル（MmmTree）を MoonBit に新設し、
parse / serialize / 操作 3 種 / 反映 v0 までを、法則のファズで検証しながら作る。

**Architecture:** テキストが真実。`parse` が md を MmmTree（意味と中身。綴りは持たない）に読み、
`serialize` が正規形の md を吐く。操作は MmmTree を直接変異させ、
差分を editSets として返す純関数として境界を渡る。正しさは 4 つの法則が持ち、
実在コーパスとランダム生成の両方で機械検証する。

**Tech Stack:** MoonBit（新パッケージ `mmm-app/core/doc`。外部依存ゼロ）/
TypeScript（vitest。`@lezer/markdown` は法則 4 の外部審判）/ 旧 core とは別パッケージで共存。

## Global Constraints

この節の要求は、全タスクの要件に暗黙に含まれる。

- **パッケージ**: `mmm-app/core/doc`（新設）。旧 `mmm-app/core` は 1 バイトも触らない
- **テスト**: `moon -C <repo>/core test -p mmm-app/core/doc`。
  **`-p` を省くとこの repo では必ず落ち、綴りを間違えると黙って EXIT=0（`Total tests: 0`）になる**
  — 各 Step 4 の Expected には必ず本数を書き、0 でないことを確認する
- **整形**: `moon -C <repo>/core fmt doc` → `moon -C <repo>/core fmt --check doc` の 2 段。
  掲載コードは fmt を通す前の姿なので、当てた差分ごとコミットする（`fmt --check` の失敗は EXIT=127）
- **綴りの規律（実測由来）**: `pub type X = Y`（`typealias` は無い）/ 否定は `!x`（`not(x)` は deprecated）/
  ラベル付きペイロードの呼び出しは `Image(alt="a", src="b")`（`alt~=` は `Error: [3016]`）/
  未定義の値は `Error: [4021] The value identifier X is unbound.` /
  `pub struct` は別パッケージから読めるが構築には `pub(all)` が要る（**境界は struct を跨がせない**。
  木は JSON 文字列で渡す）/ `*_wbtest.mbt` はパッケージ内で名前空間を共有する（同名は `Error: [4051]`）
- **環境変数の前置き（`VAR=値 コマンド`）は使わない** — Windows / PowerShell で構文エラー。
  ファズの回数は定数（`fuzz_seeds` / `RANDOM_CASES` / `DIALECT_CASES` / `CASES`）で切り替える
- **パスは絶対パス**、git は `git -C <repo>` 形。コミットメッセージは
  `<Type>: <絵文字> <日本語タイトル>`（[CLAUDE.md](../../../../CLAUDE.md) の規約）
- **1 ファイルは 1 群が所有する**。表に無いファイル・名前を作らない
  （新設が要るなら着手前に共有する）

## スコープ

**作る**: MmmTree の型 / parse / serialize / 法則 1・2・4 の検証基盤 /
操作 3 種（move・flipSide・delete）/ 反映 v0（全文正規形 → diff → editSets）。

**作らない**（殺す条件の判定後に別計画）: UI 接続 / TS の書き換え / すげ替え v1 /
残りの操作（add・rename・fold・setForm・indent・outdent・content 系）/
convert・format コマンド / project / 旧 core の削除。

**殺す条件**: 法則を守るために操作側の場合分けが増え続けたら、この設計は死んでいる。
判定は Task 50 が行い、結果を文書として残す。

## この計画が仕様を直させた 4 件

計画を実際のコードの粒度まで書き下ろす過程で、憲法の穴が 4 つ見つかり、
いずれも仕様側を改訂して塞いだ（本計画はその改訂後の仕様に従う）。

1. **implied は side を持てない** — `# r` + `#### b` で root 直下スロットを左に振ると、
   トグルの帰属先が再パースで消えて法則 1 が破れる。昇格を伴う flipSide で解決（C16）
2. **`- - -` の裁定** — 旧 core の方言（項目として読む）を捨て、CommonMark の水平線に揃えた
3. **項目の後ろの見出しは Item の子にならない** — 素直に積むと単調性が parse の時点で破れる。
   開いている項目を閉じてから付ける。あわせて implied の位置制約が
   「children の先頭」ではなく「前に見出しが居ない」だと判明（C17）
4. **文書頭の `---` の裁定** — 先頭トグルで始まりトグルをもう 1 本持つ文書が
   封筒に飲まれる。空行規律が封筒とトグルを綴りで分ける
