# タッチデバイス対応

## なぜ

**マップは指で触れる形をしているのに、指では動かせない。**

パンの入り口は中ボタンと `Space`+ドラッグの 2 つしか無く、どちらも指では
出せない。背景を 1 本指でなぞると矩形選択が始まり、地図は 1mm も動かない。
拡大はホイールだけ。つまり**指だけの機械では、最初に見えている範囲から
一歩も出られない。**

そのうえ狭い窓では、ペインを行き来する矢印が分割線ごと消えている
(`#splitter { display: none }`)。切り替えは `Alt+1` / `Alt+2` / `Mod+/` だけが
担っているので、**キーボードの無い機械では md ペインに二度と辿り着けない。**

同時に、ホバーで出る `+` ボタンを捨てる。押しに行くとホバーが外れて押せず、
出せる操作も「子を足す」を頭にした 4 つのメニュー 1 枚きり。**ホバーという
入り口そのものが、指の機械には存在しない。**

## 決めたこと

### 1. モードを持たない — 指かマウスかは、触れた瞬間に決まる

`e.pointerType` を見て、その場で作法が決まる。「タッチモード」は作らない。

Surface のように**両方が刺さっている機械では、モードは必ず壊れる**（キーボードを
外した瞬間に切り替え忘れる）。触れたものが答えを持っているのだから、覚えない。

**唯一の例外が、画面に出しっぱなしになる `+` ボタン。**これだけは「出す / 出さない」を
人が決める（下記 4）。出ているあいだ場所を取り続けるものは、その場の入力から
決めてはいけない。

### 2. 物理キーボードの有無は、Web からは分からない

だから代わりに**「主たるポインタが指か」**を見る。

```
matchMedia("(pointer: coarse) and (hover: none)")
```

`any-pointer` ではなく `pointer` / `hover`（主たるもの）を使う。Surface は
キーボードを外すと OS が主ポインタを指へ切り替えるので、この 1 本で狙いどおりに
振れる。**近似であることは承知の上**で、外れても人が押して直せる形にしておく。

## 1. ホバーの `+` を捨てる

`mindmap.ts` から消えるもの — `plusBtn` / `makePlus` / `updatePlus` / `overPlus` /
`hoverId`、`bindClick` の `pointerover`、`style.css` の `.plus-btn`。

**ホバーという入り口が無くなるので、誰がホバーされているかを追う必要も消える。**
右クリック（と長押し）のメニューが `Add ▸` を持っているので、失われる操作は無い。

## 2. 選択ノードの上下左右 `+` — `src/map/addButtons.ts`

`map/pick.ts`（選んだカードの枠と ×）と**同じ立場**の、world 座標に浮かぶ 1 個の印。
選択の anchor は常に高々 1 つなので、置き場所も 1 つでよい。

| 向き | すること | キー |
|---|---|---|
| → | Child | `Tab` |
| ↓ | Below | `Enter` |
| ↑ | Above | `Shift+Enter` |
| ← | Parent（親との間に割り込む） | `Shift+Tab` |

**マップが左から右へ伸びる向きと、木の意味を一致させる。**右が子、左が親、
上下が兄弟。4 つ揃って初めて、覚えるものが「向き」1 つで済む。

- **ルートには ← を出さない。** `core/add.mbt` の `cmd_add_parent` は深さ 1 を
  弾く（包むともう 1 つの `#` になり、同じ木の親ではなく別の木になるため）。
  押せるのに何も起きないボタンを置かない。
- **出す条件** — 選択がちょうど 1 つ / カードを選んでいない / 編集中でない /
  ドラッグ中でない。
- **大きさは倍率に引きずられない。** `translate(x y) scale(1/k)` で打ち消す。
  world に置きながら、画面では常に同じ大きさ（的は 44px）。`MIN_ZOOM`(0.15) まで
  引いたとき、押せない粒になるのを防ぐ。**見えている丸は的より小さくてよい** —
  ノードの周りに 44px の丸が 4 つ並ぶと、ノードそのものより目立つ。
- `pointerdown` を止める。`.pane-tool` と同じ「**押しても下へ抜けない**」 —
  抜けると、下のキャンバスが矩形選択を始めてポインタを捕まえ、ボタンが効かなくなる。

## 3. 指の作法

`#map-pane` に **`touch-action: none`** を敷く。`.popup-canvas`（その場で描く窓）に
既にある「指やペンでも描けるように、ブラウザのスクロール/ズームへ渡さない」と
同じ理由。**md ペインには敷かない** — CodeMirror のネイティブなスクロールを奪わない。

| 指 | どこ | 何が起きる |
|---|---|---|
| 1 本 | 背景 | **パン** |
| 1 本 | ノード | タップ = 選択 / ドラッグ = 今までどおりノードを動かす |
| 2 本 | どこでも | **pinch ズーム（同時にパン）** |
| 長押し | ノード | 右クリックと同じメニュー |

**指では矩形選択が出せなくなる** — 背景のドラッグをパンに明け渡すため。
地図で「指 1 本 = 動かす」はほぼ普遍の約束で、そちらを取る。指での複数選択は
無くなる（タップで 1 つずつ）。マウスの振る舞いは 1 行も変えない。

### 状態機械への足し方

**`bindPointer` の `pointerdown` に入るのは 1 つの条件だけ。**いまの
「中ボタン or `Space`+ドラッグ → `panning`」に、3 つ目の入り口を同じ形で並べる:

```
e.pointerType === "touch" かつ nodeAt(x, y) === -1 かつ cardAt(x, y) が無い
    → いまの rubberStart ではなく panning へ
```

パンには既に 2 つの入り口がある（中ボタンはマウスだけで完結し、`Space`+ドラッグは
キーボードに手がある時に届く — 担当する手が違うので、片方だけでは塞がる）。
**指はその 3 つ目**で、既存の 2 つは 1 行も変えない。

**2 本目の指は `src/map/gesture.ts` が引き受ける。**生きている指の台帳と
「2 本になったら pinch」の判定だけを持ち、その出来事を消費したかどうかを返す。
既存の 5 状態（`panning` / `rubberStart` / `dragCand` / `dragging` / `cardDrag`）は
増えない。**「いま何本の指か」という新しい次元を、既存の状態と混ぜない。**

**算術は `map/view.ts`**（DOM を触らない層）に置く。

- `zoomAt(view, x, y, deltaY)` を `zoomTo(view, x, y, k)` の上に組み直す
  （ホイールは `k = view.k * exp(-deltaY * ZOOM_RATE)` を渡すだけになる）
- `pinch(view, prev0, prev1, now0, now1)` を足す — 2 点の移動から相似変換を 1 つ出す

**符号を 1 つ間違えても動いてしまい、目でしか気づけない類**なので、
`test/view.test.ts` に値として入れる。既存の `zoomAt` の試験はそのまま通ること。

### 長押しは、まず何も書かない

README が「Chromium 系でしか動かない」と言い切っている以上、長押し →
`contextmenu` はブラウザが出す。`touch-action: none` を敷いた状態で実機で確かめ、
**届かなかったときだけ**自前のタイマーを足す。届くのに書けば、同じメニューが
2 回開く道を作ることになる。

### 指の揺れ

`DRAG_SLOP2`（8px の 2 乗）は、指のときだけ広げる。マウスより揺れるので、
タップが勝手にドラッグへ化ける。

## 4. トグルと保存

- `app/persist.ts` に `LS_ADDS = "mmm.addButtons"` を足し、**`OWNED` に載せる**
  （載せないと `sweep()` が毎回捨てる）
- 値は `"on"` / `"off"`。**無ければ「その機械に従う」** — テーマの
  `saved ?? OS 設定` と同じ形
- `⋯` に 1 行。テーマの「押せばどうなるかを名乗る」流儀に揃えて
  **`Show add buttons` / `Hide add buttons`**。位置はテーマの隣（見た目の好み同士）
- 配線は `main.ts`（束ねる場所）。`MindMap` は `setAddButtons(on)` を持つだけで、
  保存も既定の判定も知らない

## 5. 狭いときは、左右どちらか 1 つに統一する

### いま壊れていること

`panes.ts` は分割線の居場所を 3 つ持つ（md だけ / 両方 / マップだけ）。ところが
狭いときの CSS が `#panes:not(.no-map) #md-pane { display: none }` で
**「両方」を「マップだけ」と同じ絵に潰している。状態が 2 つあって食い違う** —
`goLeft.disabled` も `title` も、画面に無い世界を説明している。

そして `#splitter { display: none }` で、**その分割線に住んでいる `‹ ›` の矢印ごと
消える。**狭い画面での切り替えはキーだけになり、指の機械では md へ辿り着けない。

### 直し方 — `SPOTS` を幅の関数にする

「分割線の居場所」という言い方はそのまま残り、**数だけが変わる**。

| 幅 | 居場所 | 分割線 |
|---|---|---|
| 広い | md だけ / **両方** / マップだけ（3 つ） | 掴んで幅を変えられる |
| 狭い | md だけ / マップだけ（**2 つ**） | 線としては消える |

- **矢印の意味は 1 文字も変わらない。**`‹` はいつでも「分割線を左へ 1 つ」、
  `›` は「右へ 1 つ」。行き先が 3 つから 2 つに減るだけ。
- 既存の **「押せないなら出さない」**（`#pane-switch button:disabled { display: none }`）
  により、居場所が 2 つなら**画面に出る矢印は常に 1 本**になる。`‹` か `›` の
  どちらか — 「向こう側へ行く」ボタン 1 個。**足したのではなく、既存の規則から
  落ちてきた形。**
- どの見え方の要求も**いまの `SPOTS` へ射影する 1 か所**を通す。`Alt+1` / `Alt+2` /
  `Mod+/` は書き換えない — 狭いときは「片方を出す = もう片方が引っ込む」が自動的に導かれる。
- **狭いときは `#panes` に必ず `.no-md` か `.no-map` のどちらかが付く**（両方は
  居場所として存在しないため）。矢印の置き場所を決める既存の 2 つの規則は、
  例外なくどちらかが効く。

### 分割線は「線としての性質」だけを落とす

`display: none` にはしない。`style.css` が理由を書き残している:

> **splitter を隠さない**からこそ、片方のペインを消しても flex がその境目まで
> splitter を押し出し、矢印はいつも同じ 1 か所に居られる（角と角に分けると、
> 片方だけスクロールバー避けの分ずれて見える）

**分割線と矢印は別物で、たまたま同じ場所に住んでいるだけ。**狭いときに嘘になるのは
線のほう（動かせない境目を「掴めます」という顔で見せている）で、矢印の住所ではない。

だから狭いときは `width: 0` / 背景なし / `cursor: default` / `pointerdown` は何もしない。
**見た目の分割線は完全に消える**が、0 幅の要素が flex に縁まで押し出されるので、
`#pane-switch` は既存の `#panes.no-md → left: 8px` / `#panes.no-map → right: 8px` の
1 か所に座り続ける。新しい住所も新しい絵も要らない。

### `720px` を 2 か所に置かない

いまはメディアクエリだけが知っているが、`panes.ts` も知る必要が出る。
**JS の `matchMedia` を唯一の源にし、`<html>` に `.narrow` を付け外しする。**
CSS はそのクラスを見る（メディアクエリでは CSS 変数を使えないので、この向きしかない）。

### 境目をまたいだとき

- **「両方」から狭くなったら、マップを残す。**いまの CSS と同じ結果で、
  この道具がマップのために在るから
- 広くなったら、開いているほうを保つ。勝手に両方は開かない

## 6. 指では致命的な、既存の 3 点

1. **`.pane-tool` は `opacity: 0.5` で、`:hover` でしか起きない。**指にホバーは
   無いので、**触れる手段が無いまま半透明に沈み続ける。**`@media (hover: none)` で
   常時 `1`。ペイン切り替えの矢印・書き方ピッカー（H / n+ / L）・視点を寄せる
   ボタンの 3 つすべてに効く
2. **矢印は 18×18px。**電話ではこれがペインを行き来する唯一の手段なのに、指の的の
   半分以下。`@media (pointer: coarse)` で `.pane-tool` のボタンを太らせる
   （幅ではなく**入力の質**で決まる話なので、`.narrow` ではなくメディアクエリ）
3. md だけを出しているとき、矢印は `right: 8px` に来る。`style.css` が
   「CodeMirror のスクローラは 15〜17px を取り、その帯はブラウザが押下を横取りする
   （`z-index` では前に出せない）」と警告している、まさにその帯の上。md 側の道具が
   `right: 28px` へ逃げているのと同じ理由で、ここも避けさせる

## 7. やらないと決めたこと

### ファイルピッカーの無いブラウザでは、ファイルを開けない・保存できない

> **2026-08-28 訂正**: この節は当初「スマホのブラウザに無い」と書いていた。誤り。
> **Chrome for Android は M132 でピッカーを持っている。** 分断線は「Chromium か
> どうか」で、デスクトップ / モバイルの軸ではない。無いのは Firefox（デスクトップ・
> Android とも）、Safari、および iOS の全ブラウザ。調べ直した結果と、そこで何を
> するかの判断は `docs/browsers.md` に置いた。**この節の実装は影響を受けない** —
> 端末の種類ではなく能力を実行時に見ているため。

`docs/web.md` の「フォールバック（ダウンロードでの保存）は持たない」は覆さない —
2 本目の道を作れば、そちらでは画像が死に「実体はただの .md」が壊れる。

ピッカーの無いブラウザでできるのは「見る・書く・書き出す」まで。
**ただし黙って落ちるのは直す** — `io.ts` の `showOpenFilePicker` /
`showSaveFilePicker`、`assets.ts` の `showDirectoryPicker` は**存在チェック無しで
呼んでいて `TypeError` を投げる**（`isCancel` を抜けて上位の catch に届くだけ）。
無い環境では `Files` の該当行を無効にし、**なぜ押せないかを言わせる。**

### 指での複数選択

背景のドラッグがパンに変わるため、矩形選択は指では出ない。タップで 1 つずつ。
**別の入り口を発明しない** — 要るとわかってから考える。

### iOS Safari

元から対象外（Chromium 系のみ）。
