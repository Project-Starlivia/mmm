# 未処理の指摘 — put ケースカタログへの差し戻し

[put ケースカタログ](2026-08-29-put-cases.md) と 3 本のレビュー（CommonMark 検証 / レッドチーム /
アーキテクチャ批評）に対する指摘の生の記録。**結論を出していない。**
設計そのものの相談が先にあるので、ここでは論点を失わないことだけを目的に書き留める。

---

## A. 出力の形をどこで決めるか（C3 / C4 に共通）

### A-1. C3: h6 の子 → リスト形へ落ちる

md としては正しいが、**mmm 的には無限階層でもいい気がする**。

形の候補（どれも未決）:

- 関数を 2 種持つ（無限 / 特定階層からリスト形）+ フロントから叩き分け
- 全関数にその用の引数を付ける
- **add 系と get/format 系の関数を分けて持ち**、内部変数もしくは format 引数で最終出力が変わる

「全関数に引数」は筋がいいのか悪いのか、判断保留。

### A-2. C4: ルートに枝を足す

**挙動そのものは良い**。関数を分けるか引数にするかだけが論点。A-1 と同じ形の問題。

## B. hidden の方針（C14 / C19 / C21）

### B-1. C14: 畳んだ落とし先は先に開く → **畳んだままでいい**

期待する結果:

```md
# r

<!--

## a

### b

### c

-->
```

（PR #14 から引き継いだ「先に開く」方針を撤回する方向）

### B-2. C19: 畳む — 入れ子の吸収 → **畳まない方針でいきたい**

吸収せず、入れ子の hidden を保ちたい。

### B-3. C21: flesh に生の `-->` があると拒否

「バケモンで草」。ただし**拒否ではなく閉じたい**。案として**コードブロックに畳む**。

> あれ？でもこれ考えるなら階層的な hidden ってもしかしてできんかったりするのかしら

— フェンスは長さで入れ子にできるので、hidden の表現を HTML コメントから変えると
B-2 の「吸収しない」が自然に成立する可能性がある。**未検証の筋**。
CommonMark 検証エージェントの致命 1（hidden = 不透明な HTML ブロック、
中身を見るには二段パース + 座標の足し戻しが要る）とも直結する論点。

## C. 保全の範囲（C16）

### C-1. C16: 階層飛びは触った行だけ正規化される → **階層も残したい**

`####` を触ったときに `###` へ正規化するのではなく、飛びを保ちたい。
A-1 の「無限階層」と同じ方向を向いている可能性がある（深さと `#` の数の関係の再考）。

---

## D. 操作の引数設計（C18）

### D-1. C18: 列内並べ替え

**「a の下」なのか「b の上」なのか**。左右が変わるので、挿入位置の指定方法を
ちゃんと考えたほうがよさそう。位置を「隣人 + 前後」で言うのか「親 + index」で言うのかの選択。

## E. 手つかず（レビューから来た論点、上の指摘とは別口）

全文は [レビュー所見](2026-08-29-review-findings.md)。以下は見出しだけ。

**上の指摘と交差するもの**

- A-1 / C-1（無限階層・階層飛びの保全） ⇔ **N31**「正規の深さ」と「親の実レベル」の衝突。
  階層飛びのある文書では indent が**無編集・無変化で黙って失敗する**。
  かつ **N48**: `#######` は CommonMark では段落なので、`#` による無限階層はそもそも書けない
- B-1（畳んだまま入れる） ⇔ **N34** 畳んだ枝の側は原理的に表現できない
- B-2 / B-3（吸収しない・フェンスで畳む） ⇔ **N37/N38/N47** — HTML コメントが原因。
  フェンス案はこの 3 つを同時に解く可能性がある
- D-1（挿入位置の引数） ⇔ **N30** 側の符号化が 1 ビット足りない。
  枝 N 本に対し隙間は N−1 個なので、**先頭の枝の flipSide は表現不能**、「全部左」は書けない

**構造的な破れ**

- N30 側が 1 ビット足りない / N31 深さとレベルの衝突 / N32 マーカー正規化が content indent の原点を動かす
- N33 リスト形と見出し形の混在で並べ替えが親を変える / N36 根への outdent が後続の兄弟を飲む
- N35 区切り再計算がユーザーの `---` を消す（**憲法第一条への直接の反例**、C27 とも矛盾）
- N39 区切りの有無がリストを併合・分割する / N40 リンク参照定義は文書全域で爆風に距離の上限が無い
- N41 setext の骨格は 2 行 / N42 ラベルは正規形で往復できない / N43 照合の取り違えはテキスト破壊に昇格
- N44 タブ / N45 content の認定範囲 / N46 空行規律の内部矛盾 / N49 コンテナ接頭辞 / N50 BOM・CRLF・span の単位
- N51 同位置への move で骨格行が勝手に整形される（法則 1 の穴）

**アーキテクチャ**

- 「純 CommonMark」は自作パーサを更に大きい自作パーサに置き換える宣言で、自分のカタログとも矛盾
- 照合を捨てる案（ChangeSet の `mapPos` + put が返す旧→新の対応表。`core/move.mbt:172` の `rels` が既にある）
- 法則 1 / 3 が検査になっていない、法則 2 の canonical が未定義
- Model に span が無い / put と CodeMirror の境界（憲法は既に破れている: `src/edits.ts` と `core/heading.mbt` の重複）
- 二重パース / Group 廃止の移行（既存文書の側が反転する）/ 空ラベルの末尾空白規約

**確認できた良い点**

- 全再パースは実測で裏付け（`PERF.md` §6: 5,000 ノード 191KB が 19.1ms、1 打鍵の再描画 44.2ms）
- 「区切りは有無だけ」は `core/seps.mbt` の 135 行を丸ごと殺す、この設計で最も価値のある 1 手
- ファズの材料は既にリポジトリにある（`test/_helpers.ts` の `randomDoc` / `shape` / `corpus`）
