# 境界の読み直し — #312 #315 #319

`---` が左右を裏返す（境界）かどうかを、**見出しの根と項目の根で別々の規則**で決めていた。
その継ぎ目から 3 つの食い違いが出ている。

| 形 | いまの読み | 何が起きるか |
|---|---|---|
| `---` / `- a` | 境界になれない（根が無い）のに、`a` を深さ 2 に置く | 行の無い根が立ち、読んだ直後に `GappedItem`。後ろの段落を抱えて #312 #315 の出どころになる |
| `- a` / `---`（列 0）/ `- b` | 項目の根に「口」があるとして `b` を `a` の左の子にする | 読みが左を作り、検めが `ListSide` で書けないと言う |
| `- r` の中の `---` / `- a` | 項目の中の `---` は常に飾り | 項目の根は左を持てない。#319 は地図の側でその穴を塞いだ |

**直すのは規則の置き場所。** 見出しは文書の段、項目は `<li>` の中、と入れ物で分けていたのを、
**`---` が無かったものとしての読み**と、その上の 3 つの条件で決める。

## 定義（2026-09-15、作者と確定）

0. **水平線かどうかは md が決める。** 段落のすぐ下の `---` は setext の下線で水平線ではない。
   記法（`---` `***` `___`）・本数・空行は条件に使わない
1. **`---` で左右が変わらないものとして読む。** 全部の行の深さと、全部の中身の持ち主はここで決まる。
   - 見出しの深さは `#` の数（項目の中なら項目から数える）
   - 項目の深さは、書かれた入れ物の 1 つ下（`<li>` の中ならその項目、文書の段なら直前に書かれた見出しの節）
   - 中身の持ち主は、`<li>` の中ならその項目（か中の見出しの節）、列 0 なら直前に書かれた見出しの節。
     Implicit は書かれた行ではないので持ち主にならない
   - 水平線もここではただの線で、持ち主の中身に入る
2. **次の 3 つを全部満たす水平線だけが境界。**
   1. 持ち主がノード（文書の中身ではない）
   2. 直後のブロックが骨格の行（見出しか項目）
   3. その行が同じ木に入る（1 の読みで深さ 2 以上）
3. **境界がすること。**
   - 水平線は中身から外れ、根の子の側の変わり目になる。1 本につき、以降の側が 1 回裏返る
   - **境界より後ろの行は、境界より前の行（根を除く）の子にならない。** 深さは 1 のまま保って
     根の下に置き直し、足りない段は Implicit が埋める
   - **それ以外は変えない。** 深さも中身の持ち主も 1 のまま

見出しの根も項目の根も、根でない項目の中も同じ。項目の根の側は項目の中の `---` で書く。

## ほかに決まったこと

- **項目の body。** 項目の段に書かれた、ラベル以外の塊（入れ子の項目の段に書かれたものは入れ子の側）。
  見出しは節として範囲を取る（文書の中でも項目の中でも）。字下げが戻った塊は、そこより深い項目を閉じる（列 0 なら全部）
- **畳みの閉じは境界と違う。** `</details>` は部分木の終わりで、閉じの後ろは行も中身もその部分木の外。
  `---` は中身の持ち主を閉じない
- **表は扱わない。** 列 0 に続けた表が項目の名前になる件はライブラリの読みのずれで、表の issue で扱う
- 捨てる考え: 「口」（深さ 2 の引き出し先があるか）、項目の中に側は無い、項目の根は右だけ（#319 の `two_sided` / `ListSide`）、項目は直に深さ 2

### 決めの経緯

**境界の後ろに残った中身。** 4 案から選んだ（例: `- 買い物` / `(買い物) - 野菜` / `(野菜) ---` / `(野菜) - 肉` / `(野菜) メモ` / `(野菜) - 魚`）。

| 案 | メモの持ち主 | 採らなかった理由 |
|---|---|---|
| 行の無い箱 | 左に立った Implicit | 読んだだけで中身を持つ Implicit が生まれる（#315 の形）。md で野菜の中に書いた字が、野菜でないものに付く |
| **野菜（採った）** | md の持ち主 | — |
| `---` を飾りと読む | 野菜（左右が起きない） | 境界かを決めるのに `---` のずっと後ろまで見る。下にメモを 1 行足すだけで、肉と魚が右へ戻る |
| どこにも属さない | 文書 | 境界の後ろの文章を文書へ回す専用の分岐が要る。字下げされた文章が文書の body に入り、どのノードからも辿れない |

「野菜」は読みの流れのままで例外が無い — 読みは今どの `<li>` の中かを知っており、境界が閉じるのは積んだ行だけ。
代わりに**野菜の地番が、左へ出た肉の行をまたぐ**（メモが肉より下に書かれている）。カーソルの持ち主は
既に区間を割って持つ（#204）ので平気で、md の薄塗りと写す範囲を同じく区間で持つ。

**列 0 に戻った文章**（`## 野菜` / `---` / `- 肉` / `メモ`）も同じ問い。今の読みは開いている一番深い見出しに付けるので、
境界が野菜を閉じた後は行の無い根に付き、読んだだけで `Unmarked` が立っていた（#315 の「本物」の形は全部これ）。
項目の中と同じく「`---` が無ければ誰のものか」で決めれば野菜の節のもので、規則が 1 つに揃う。

**項目の深さ。** 始めは「境界の後ろ、文書の段の項目は、境界が閉じた後に開いている見出しの 1 つ下」
（`# r / ## a / --- / - b` の b は深さ 2）としていた。それだと同じ a の節に書いた `text` は a のもの、
`- b` は r の子と、持ち主と深さで答えがずれる。**深さも `---` が無かったものとして決める**と揃い、
見出しの `## a / --- / ### b` とも同じ形（Implicit → b）になる。これで定義の 1 が 1 つの読みになった。

## 例

`/` は行の区切り。字下げは `(r)` のように持ち主の段で言う。**✱ はいまと答えが変わる形。**

## 読みの結果を使う側

境界の後ろに残った中身で、**持ち主の地番が子孫でない行をまたぐ**ことが初めて起きる。
地番を 1 本の範囲で使う所は、カーソルの持ち主（`core/read/caret.mbt` の `owns`）と同じく区間を割って持つ。

| 使う所 | いま | 直す |
|---|---|---|
| カーソルの持ち主 | 子の後ろに書かれた中身を別の区間で持つ（#204） | そのまま |
| md の薄塗り（`ranges`） | 地番 1 本（子孫込み） | 自分の区間と子孫の地番 |
| 写す（`Mod+C`） | 地番 1 本 | 同上 |

## 編集（2026-09-15、作者と確定）

大原則: **書いた md を定義の 1〜3 で読み直すと、操作の後の木になる。**

### 1. `---` を書く場所

| 変わる子 | 書く場所 | md |
|---|---|---|
| 見出しの根の子 | 変わる子の直前、文書の段 | `# r` / `## a` / `---` / `## b` |
| 項目の根の子 | 変わる子の直前、**根の項目の段** — 手前の子の中身には触らない | `- r` / `(r) - b` / `(r) ---` / `(r) - c` |
| 境界の後ろの `Implicit → x`（深いノード） | **手前の兄弟の中の最後** — 深さを保てるのはそこだけ。兄弟に残る子を先に書き、x はその後ろへ移る | `- r` / `(r) - b` / `(b) - y` / `(b) ---` / `(b) - x` |

`<li>` の中の `---` は前後に空行を置く。空行が無いと直前の段落の setext の下線になり、段落が見出しに化ける。

### 2. 左右が戻ったとき — 操作は選んだものだけを動かす

- **`---` は物ではない。** 木は側だけを持ち、側が変わる所にだけ書くので、側が戻れば `---` は消える
  （b を右へ戻す・左の b を消す → `---` が無くなる）
- **消すのは `---` の行だけ。** 今の合流は根ごと正規形で書き直して消しているので、境界の行を合流の要素にして、
  要らなくなった行だけを消し、要る所にだけ足す（「触った所だけ正規形」）

| 動かしたもの | 行き先に `---` が書かれる | 行き先に `---` が書かれない |
|---|---|---|
| x だけ（Flip side・D&D） | Implicit を立てて深さを保つ | Implicit は立てず、深さのまま md の読みどおりの親の下（右の最後の子 b の下）。元の側の Implicit は子が居なくなれば消える |
| Implicit そのもの | Implicit ごと、境界の後ろへ | Implicit ごと。行の無いままでは書けないので空の行として綴る（`mend` のまま） |

`- r` / `(r) - b` / `(b) - y` / `(b) - x` の x を左へ出して右へ戻すと、元の木に戻る。
「x だけ」は `haul` の中で決め、`mend` は変えない。

### 3. 線のカードが境界に化ける操作 — md の読みどおり

中身を消す・線を動かす・最後に線を持つノードの後ろへ動かす、で線の直後に同じ木の行が来れば、
その線は境界になり後ろの行が置き直される（`# r` / `## a` / `---` / `メモ` / `## b` のメモを消すと b が左）。
操作はそのまま行い、読み直した形を見せて undo に任せる — md ペインで同じ行を消したときと同じ結果。
断る案（普通の削除まで止まる）と、線も消す案（選んでいない線が消える）は採らない。

### 4. 境界の後ろに残った中身の書き直し

`- 買い物` / `(買い物) - 野菜` / `(野菜) ---` / `(野菜) - 肉` / `(野菜) メモ` の、肉より下のメモ。

| 操作 | 書き直す範囲 | メモ |
|---|---|---|
| 野菜の名前・中身を足す・メモを書き換える | 触った所だけ | その場（肉の下）に残る |
| 野菜を畳む・動かす・種類を変える | 野菜の部分木ごと | 野菜の直下（`---` の手前）へ移る。`---` と肉はそのまま |

合流は持ち主の範囲を 1 本で持つので、部分木ごと書き直すと範囲に挟まった `---` と肉まで上書きする。
読みを使う側と同じく、区間に分けて持つ。

### 5. 貼り付けの `---` — いったん md の読みどおり

貼った `---` は md と同じ意味（#158）のまま。深い所に左右の境目を含む断片を貼ると、境目の後ろが根の反対側へ出る。
「字を打つのか形を運ぶのか」は #370 でまとめて考える。
