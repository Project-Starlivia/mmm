# paste — 貼る解釈を core に（設計）

issue #117。**断片が持ち込むのは形だけで、綴りと深さは行き先が決める。** 貼り付けの字は
raw のまま `Graft` に渡し、何を貼るかの判定は Graft の読みに 1 つ置く。TS に残るのは
クリップボードを読むこと・画像・宛先の 3 つ。

## いま何が苦しいか

貼り付けの判定が TS（`app/paste.ts`）と core（`Graft`）に割れていて、綴りの規則が
2 つある。

| 来た字 | 判定 | 綴り |
|---|---|---|
| 骨格の無い字 | `AddNode(labels)` | 隣に従う |
| 骨格のある md | `Graft(md)` | 断片のまま |

Graft が断片の綴りを保つので、項目 `- x` を子が見出しの見出しへ貼ると、項目が
見出しの後ろに付き、md では直前の見出しに飲み込まれる（check の `Swallowed`）。
`mend` は Implicit しか綴れないので `apply` が None を返し、「Couldn't do that
here」になる。子が見出しの親へ項目を貼る・落とす操作が全部断られる（2026-09-06
に実測。`MoveNode` も同じ穴）。

ほかにも 2 つ食い違う。カード 1 枚の原文（`![](…)`）は骨格が無いので labels に
落ち、画像の md がラベルの字になる。断片の先頭の散文は Graft では貼り先の body
に入り、labels では行ごとにノードになる。

## 決め

- **字は raw で core へ。** TS は画像か字かを分け、字は `Graft(In(anchor), clip)`
  にそのまま渡す（空なら黙る）。判定は Graft の読みに 1 つ。`app/paste.ts` と
  `test/paste.test.ts` は消える。画像は「貼り付けの判定」ではなく画像の経路
  （`attachImage`。投下・お絵描きと同じ入口）なので TS に残る
- **断片が持ち込むのは形。** ラベル・中身・子の列・畳み・飛び（Implicit）。`#` の
  本数、`-` か `*` か `1.` か、先頭の飛びは書き方なので捨てる。**行の字下げは形**
  （2026-09-11 に改めた。下記「字下げの梯子」）
- **綴りは行き先が決める。** 規則は `AddNode` のもの（「新しいノードの綴りは隣に
  従う」）: `Before` / `After` は隣の綴り、`In` は末尾の子の綴り、子が無ければ親
  （項目なら項目、それ以外は見出し）、`In(doc_id)` は最後の根。その下は、親が項目
  なら全部項目（型が決める）、親が見出しなら見出しで続け、天井を越えた所から
  `cap` が項目にする。Reform（モード b）が来たらこの規則が置き換わるだけで、
  置き場所は変わらない
- **散文は「一番外の段落だけ行ごとにノード」。一番外は順に読む。** 断片の一番外の
  列にある段落（mdAst の Paragraph）は行ごとにノードにし、それ以外の中身（画像・
  リンク・フェンス・`---`・details・表・引用・HTML）は**直前に生えたノードの中身**に
  入れる（無ければ貼り先の中身）。文書の読みと同じ — 骨格の行の後ろの中身はその行の
  もの。貼った順が崩れない（表 → 段落 → 表 なら、後ろの表はその段落のノードの中身）。
  貼り先が文書（anchor 無し）で、直前にノードの無い中身は**文書の散文**（最初の骨格
  より前）へ入る — マップには出ないが、手で md の頭に書いたのと同じ形。見えないことは
  地図の都合で、断る理由にしない（2026-09-07 に「断る」を改めた）。
  ノードは自分の中身を持ったまま運ぶ（見出しの下の段落はその見出しの body）。「mmm は散文を編集する道具ではない」の帰結
- **貼る側は行で切る。読む側と違っていい**（2026-09-11、#118）。md を読む側は改行を
  段落の中の折り返しと見るが、マップへ貼るのは字を構造にしたいからで、貼る側は
  1 行を 1 ノードにする。**空行は単に空行** — 段落の区切りも空行として扱うので、
  `a / b` と `a / 空行 / b` は同じ木になる。URL は 1 行なら中身（リンクカード）、
  2 行以上なら段落なので 2 つ以上のノード
- **字下げの梯子**（2026-09-11、#118）。行の**桁**が深ければ手前の行の子になり、
  同じか浅ければ一番近い手前の段の隣になる。タブは 4 桁（CommonMark のタブ幅で、
  `undent` が置いている 4 と同じ）。段の数に上限は無く、天井を越えた所は `cap` が
  項目にする。
  - **桁は原文から測る。** 塊が持つ原文（`Block.source`）では測れない — `carve` が
    1 行目の桁を引いて塊ごとに基準を戻すので、1 行目より浅い行は 1 行目と同じ桁に
    見え、空行の後の塊は左余白を失う。だから `graft` は `parse` ではなく `build` を
    通し、地番と原文から測る
  - **断片の左余白は落とす**（`@tree.dedent`）。断片に容器は無いので、左余白は
    切り出した**先**の容器であって中身ではない。落とさないと、同じ外形の outline が
    「文書のどこから写したか」で違う木になる
  - **字下げコードは段として読む。** 断片の入った字は outline の深さであって
    コードの記法ではない。読まないと、枝の途中から写した断片がまるごと 1 枚の
    コードになりノードが 1 つも生えない。**囲んだコード（```）は中身のまま** —
    書いた人がコードと言っているので。代償は、字下げだけのコードを写したときに
    それもノードになること
- **`---` は md と同じ意味。** 断片の側（根の子の `---`）は捨てず、境界として運ぶ —
  側が変わる手前の子の部分木の最後の行の中身の尻に、読んだ字（`___` なら `___`）の
  ままで水平線を置く。一番外の `---` も直前のノードの中身の尻。書けば md が境界と
  読む: 席が深さ 2 なら次のノードから側が反転、深ければ次のノードは深さ 2 へ
  引き出されて反対側（md ペインに同じ字を打ったのと同じ形）。次に骨格が来なければ
  ただの水平線のカード。mmm はどこから来た字でも同じ解釈をする — 貼り付けだけの
  独自解釈は持たない。apply の門は `BorderBreak` を断らず（docs/core.md「操作」）、
  形は読み直しが決める。そのとき focus は無い
- **URL 1 行は特別扱いしない。** 読み（`content.mbt` の `bare`）が素の URL 1 行を
  既に Link の中身と読むので、上の規則でそのままリンクカードになる。2 行以上の
  URL は段落なので行ごとにノード。断片の中の URL（見出しの下の 1 行）はその
  見出しの body のままでカードにしない
- **飛びは形なので運ぶ。** Implicit は「行を省いた空の見出し」で、マップにも出る
  ノード。読めない席に来れば綴る（#100）— 見出しの列では空の見出し `######`、
  **項目の列では空の項目**。`cap` の「天井より深い Implicit は消えて子が
  繰り上がる」（#108）は「空の項目に綴る」に替える。空の項目に子を持たせる
  書き方は `- - b`（マーカーの直後にマーカー。中身がリスト 1 つだけの項目）で、
  Tab で空の項目を作りその下へ足したときに core が既に書いている形。詰めて
  `-` 1 本を置く形はラベルの setext の下線に読まれる（#109）ので使わない
- **先頭の飛びは剥がす。** `##` から始まる断片の Implicit は切り出した場所の名残で
  形ではない（#98。今の Graft の決めのまま）
- **frontmatter は捨てる。** 画像フォルダの宣言は貼り先の文書のもの
- **MoveNode も同じ規則に揃える。** 「動かすノードは綴りを保つ」（docs/core.md）
  を「形だけ運び、行き先が綴る」に書き換える。ドラッグが同じ穴に落ちるため。
  実装は別 PR

## 型

```moonbit
// core/op — Graft の型は変わらず、意味が「md を読んで形にし、席の綴りで差す」になる。
// Op も境界の入口も増えない
Graft(at~ : NodePlace, md~ : String)

// 席の綴り（AddNode の規則を名前にしたもの。Graft / MoveNode も使う）
fn sign_at(doc : Doc, at : NodePlace) -> Sign?

// 部分木を綴り替える。形は保ち、項目の列では Implicit を空の項目に綴る。cap もこれで書く
fn respell(n : Node, sign : Sign) -> Node

// core/tree — 原文のまま持つ中身が段落 1 つなら、その行の列。段落かどうかは mdAst しか知らない
pub fn lines(text : String) -> Array[String]?
```

TS は `#` も URL も見ない。空のクリップボードだけは「何も無い」なので TS が黙る。

## 例（2026-09-06 に合意した形）

貼り先の子の列の末尾に差す。`+` が増える行。

**項目を、子が見出しの見出しへ**（今回の穴）
```diff
 ### シナリオ
 #### 開始 …
+#### {product.feature}！？…
```

**見出し + 項目を、子が項目の見出しへ**
```diff
 ##### 商品紹介
 - つかみ
+- 特徴
+  - あり得るんですか
```

**項目の列を、子の無い見出しへ** — 隣がいないので親に従い見出し（Tab と同じ答え）
```diff
 ### 目的
+#### a
+##### b
```

**深い所へ**（天井）— 6 段目まで見出し、7 段目から項目
```diff
 ##### 特徴
+###### a
+- b
+  - c
```

**散文と骨格が混ざった断片**（`前置き` / `# a` / `a の中身` / `- b`）
```diff
 ### シナリオ
+#### 前置き
+#### a
+a の中身
+##### b
```

**カード 1 枚**（`![](x.webp)`）— 貼り先の body の末尾に画像カード

**途中の飛び**（`# a` / `#### b`）— 着地の深さで見え方が変わるが、飛びは全部運ぶ

| 貼り先 | 結果 |
|---|---|
| 根（子が `##`） | `## a` / `##### b`（飛び 2 枚は省いたまま） |
| シナリオ（子が `####`） | `#### a` / `######`（6 段目の Implicit は綴られる） / `- b` |
| 6 段目の `###### tip` | `- a` / `  - - - b`（飛び 2 枚は空の項目） |
| 項目の列 | `- a` / `  - - - b` |

**anchor 無し**（根が見出しの文書へ `- a`）— 最後の根に従い `# a`

## 規則の置き場所

| 規則 | 場所 |
|---|---|
| 形にする（段落 → 行ごとにノード、中身 → body、根の綴り替え） | `core/op/apply.mbt` の `graft` |
| 字下げの梯子（桁 → 親子） | `core/op/apply.mbt` の `grow` |
| 段落かどうか、行の桁 | `core/tree/content.mbt` の `rungs` |
| 断片の左余白を落とす | `core/tree/text.mbt` の `dedent` |
| 桁の測り（タブは 4 桁） | `core/tree/text.mbt` の `inset` |
| 綴りの規則（隣に従う） | `sign_at`（`AddNode` / `Graft` / `MoveNode` で共有） |
| 綴り替え | `respell`（`cap` もこれで書く） |
| 天井と飛びの綴り | `cap`（Implicit → 空の項目） |
| 読めない席の Implicit を綴る | `mend`（見出しの列。変わらない） |
| 画像・クリップボード・宛先・空 | `src/main.ts` の `paste()` |

書き換える文書: docs/core.md「操作」の決め（動かすノードは綴りを保つ → 形だけ
運ぶ / cap の Implicit の行）、docs/spec.md の `Mod+V` の段落、
`2026-09-04-ops-design.md` の D の表はこの文書が上書きする。

## 試験

- `apply_wbtest.mbt` — Graft: 上の例を全部固定（項目 → 見出し、見出し → 項目、
  子の無い見出し、天井、散文 + 骨格、中身だけ、飛び 4 通り、anchor 無し）。
  cap: 天井より深い Implicit が空の項目になる（focus も残る）
- `edit_wbtest.mbt` — 上の例を md の入出力で固定（貼り付けの見本）。MoveNode の
  綴り替えも 1 本
- `content_wbtest.mbt` — `lines`（段落は行の列、表・引用・HTML は None、CRLF）
- `law_wbtest.mbt` / `apply_wbtest.mbt` の総当たり — Op に項目の断片と中身だけの
  断片を足す
- TS — `test/paste.test.ts` は消える。`main.ts` の配線は `pnpm run check` と実機

## 範囲に入れないもの

- 混ざった断片の順序（body は子の前に書かれるので、字・画像・字は画像が前に出る）
- 押す前に沈める判定（貼れないことは貼ってから分かる。綴り合わせで断る場面が
  ほぼ無くなるので、後回しでよい）
- Reform（モード b）
