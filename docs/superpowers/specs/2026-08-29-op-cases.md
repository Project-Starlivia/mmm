# 操作ケースカタログ

[文書モデル設計](2026-08-29-doc-model-design.md)（意味保全 + 綴りの所有）の語彙による
挙動の固定。形式は **元 md / 元 map (mermaid) / 操作 / 新 md**。

- 反映は**すげ替えが既定**: 新 md で正規形になるのは操作が書いた範囲
  （+ 検証が正規化を要求した範囲）だけで、触っていない綴りは手書きのまま残る。
  全文を揃える例は format（C9）
- map は `graph LR`（root 中央・左右に枝）。content・散文はノードの箱に `<br>` で積む。
  畳みは `〔畳〕`
- 操作は **実行の関数 + 日本語の説明** の 2 行

---

## C1: add — 形は正規形が決める

### 元 md

```md
# r

## a

- b
- c
```

### 元 map

```mermaid
graph LR
  r((r)) --- a
  a --- b
  a --- c
```

### 操作

`add(a)`
a に子を追加する。

### 新 md

```md
# r

## a

- b
- c
- 
```

備考: **兄弟の真似**（form 決定の優先順位 ③）— 最後の子 c が Item form なので
新しい子も Item。継ぎ目は tight のまま詰める。

## C5: move — 散文は中身ごと運ばれ、level は付け直される

### 元 md

```md
# r

## head

content01

***

content02

## head2
```

### 元 map

```mermaid
graph LR
  r((r)) --- head["head<br>content01<br>content02"]
  r --- head2
```

### 操作

`move(head, head2, 0)`
head を head2 の先頭の子へ移動する。

### 新 md

```md
# r

## head2

### head

content01

***

content02
```

備考: Opaque（散文・飾りの `***`）は中身ごとノードに付いて旅する。
head の level は移動先の深さ（親 + 1）に付け直される。子孫がいれば相対差を保って追従。

## C6: 階層飛びは構造なので正規形でも残る

### 元 md

```md
# r

## a

#### b
```

### 元 map

```mermaid
graph LR
  r((r)) --- a
  a --- g(("(implied)")) --- b
```

### 操作

`rename(a, "a2")`
a のラベルを打ち替える。

### 新 md

```md
# r

## a2

#### b
```

備考: level は構造（疑似階層）。`####` の飛びは正規化の対象ではなく、飛びからは
implied（暗黙ノード）が導出されて map に居る（md には何も書かれない — 飛びが綴り）。
rename は b に一切影響しない。

## C7: 飾りの水平線 — すげ替えは手書きを狩らない

### 元 md

```md
# r

## a

text

---

more

## b
```

### 元 map

```mermaid
graph LR
  r((r)) --- a["a<br>text<br>(水平線)<br>more"]
  r --- b
```

### 操作

`flipSide(b)`
b を左側へ移す。

### 新 md

```md
# r

## a

text

---

more

---

## b
```

備考: 元の `---` は後ろに more が居るので隙間ではなく a の body（Opaque = 飾り）。
すげ替えにより a の body は無傷 — **手書きの飾りは `---` 綴りのまま生きる**。
新しく書かれたトグルだけが正規の `---`。チャンネル分離（飾りは `***`）は
「mmm が書くとき」の規則であって、手書きを狩りには行かない。
もし後の操作で飾りが隙間の位置に落ちて意味が化けそうになったら、
検証がそれを検出し、その範囲だけ `***` に正規化される。

## C8: fold — details で畳む。ネストは保存される

### 元 md

```md
# r

## a

### b

<details>

#### c

</details>
```

### 元 map

```mermaid
graph LR
  r((r)) --- a
  a --- b
  b --- c["c 〔畳〕"]
```

### 操作

`fold(a)`
a を畳む。

### 新 md

```md
# r

## a

<details>

### b

<details>

#### c

</details>

</details>
```

備考: 骨格行 `## a` は外、details は本文と子だけを包む。内側の c の畳みは**吸収されず残る**
（HTML コメントと違い details はネスト可能）。開けば c は畳まれたまま出てくる。

### 操作

`format()`
文書全体を正規形に整形する。

### 新 md

```md

```

```
```

備考: setext → ATX、閉じ `#` と余白の除去、インデントコード → フェンス。
すげ替え既定の世界では**勝手には起きない**整形を、明示の 1 操作でまとめて適用する

## C13: 読みの道 — 文字列は md として解釈される

### 元 md

```md
# r

## a
```

### 元 map

```mermaid
graph LR
  r((r)) --- a
```

### 操作

`rename(a, "1. x\ny")`
カードの入力欄に複数行のテキストを打つ。

### 新 md

```md
# r

## 1. x

y
```

備考: 一言語原則 — rename は読みの道を通り、入力は md として解釈される。
見出し行の中身として `1. x` が書かれ、続く `y` は a の flesh（Opaque）になる。
エスケープも拒否も無い: md ペインで同じ内容を打った場合と完全に同じ結果。
（リスト形のノードに `1. x` と打てば入れ子リストが生える — それも同じ原則の帰結）

## C14: form は行き先に従う — Item を節の間へ drop

### 元 md

```md
# r

## a

- x

## b
```

### 元 map

```mermaid
graph LR
  r((r)) --- a --- x
  r --- b
```

### 操作

`move(x, r, 1)`
a の子 x を、a と b の間（r の 2 番目の枝）へ移動する。

### 新 md

```md
# r

## a

## x

## b
```

備考: 順序法則（同じ親の子は Item が先、Heading が後）により、Heading 兄弟の間に
Item は書けない。**form は行き先に従い**、x だけが自動で Heading 化する
（x に子が居れば子は Item のままで合法 — 単調性は Heading 下の Item を許す）。
逆向き（Heading サブツリーを Item 親の下へ）はサブツリーごと Item 化。

## C15: 全リストの map — Item root と content indent のトグル

### 元 md

```md
- center

  - a

  - b

  ---

  - c
```

### 元 map

```mermaid
graph LR
  c --- ce((center))
  ce --- a
  ce --- b
```

### 操作

（読みの確認。操作なし）

### 新 md

（同一 — 無操作は無編集）

備考: top-level の Item は level 1 の root。中心も枝も左右も、`#` を 1 本も使わず書ける。
side トグルは root の content indent（2 スペース）に置いた `---` — 子リストがそこで
割れるのは md の仕様どおりで、読み書き一意。より深い位置の `---` は子の body の飾り。
