# カードをノード並みに扱う

## なぜ

マップ上のカード（リンク / 画像 / SVG / コード）は、いまのところ**見るだけ**の
ものだった。画像にだけ後から選択と削除が付いたが、他の 3 種には無く、
移動も並べ替えもできない。

ノードに対してできること（選ぶ・動かす・並べ替える・その場で直す）が
カードにも要る。**形式の違うノードとして揃える**のが目的。

## 決めたこと

### 1. カードは「ノード id + 何枚目」で指す

```ts
type CardRef = { node: number; index: number };
```

**コアは変えない。** コアが知っているのは見出しの構造だけで、カードは本文の
行にすぎない。本文の行に id を配ると、構造と内容の境目が無くなる。

代わりに、文書上の位置（`from`/`to`）で直に指すのもやめる。位置は**別の
ノードを 1 行編集しただけでずれる**ので、選択がすぐ外れる。ノード id は
コアが編集をまたいで維持するので、`{node, index}` なら**別ノードの編集では
外れない**。壊れるのは同じノードの中でカードが増減したときだけで、そこは
自分が出した編集なら新しい index が分かるので付け替えられる。

**代償**: MD ペインで人が同じノードの本文を打つと、選択は外れる。
アプリが勝手に別のカードを指すことは無い（index が範囲外なら選択を落とす）。

### 2. `CardRow` の 4 種すべてが元の行の範囲を持つ

いま `from`/`to` を持つのはコードと画像だけ。これをリンクと SVG にも広げ、
**どのカードも「自分がどの行から来たか」を知っている**状態にする。

これがこの設計の土台で、以降の操作は全部これ 1 つに乗る。

| 操作 | 実装 |
|---|---|
| 編集 | `replaceText(from, to, 新しい本文)` |
| 削除 | 行ごと `replaceText(…, "")` |
| 移動・並べ替え | 元と先を含む範囲を **1 回**で書き直す |

移動を 1 回の `replaceText` に落とすのは、**Undo を 1 回にする**ため。
2 回に分けると、戻すのに 2 回押すことになる。

### 3. 選択は main.ts が一括で持つ

いま「ノードの選択」は `main.ts`、「画像の選択」は `mindmap.ts` にあり、
持ち主が 2 か所に割れている。片方へ寄せる。

```ts
let selection: Set<number>;  // ノード（複数可）
let picked: CardRef | null;  // カード（1 枚だけ）
```

**不変条件: どちらか一方だけが空でない。** 片方を選ぶともう片方は外れる。
これで `Delete` / `Alt+↑↓` / `Mod+C` が「何に効くのか」で迷わなくなる。

カードを複数選べるようにはしない。まとめて動かしたい場面がまだ無い（YAGNI）。

`mindmap.ts` は選択を**持たず**、`host.pickedCard()` を見て描くだけになる。

副産物として、カードを選ぶと **MD ペインでもその行が光る**。ノードの選択と
同じ扱いになるので、対応が目で追える。

### 4. 操作の割り当て

| 操作 | カードを選んでいるとき |
|---|---|
| クリック | 選ぶ / もう一度で外す |
| ダブルクリック・`Mod+Enter` | その場で編集（4 種とも） |
| `Delete` / `Backspace` | 削除（× と同じ） |
| `↑` `↓` | 同じノード内で隣のカードへ |
| `←` | 持ち主のノードへ戻る |
| `Alt+↑↓` | 並べ替え（端で止まる。ループしない） |
| ドラッグ | 別ノードへ移動 / ノード内で順番変更 |
| `Esc` | 選択を外す |

**並べ替えは `Alt+↑↓`。** ノードの並べ替えを `Alt+↑↓` にしたばかりなので、
同じ意味には同じキーを当てる。`Mod+矢印` はどこにも割り当てない。

並べ替えは端で止まる。ノードの `↑↓` 移動はループするが、あれは
「選択を動かす」操作で、こちらは「文書を書き換える」操作。書き換えが
黙って端から端へ飛ぶと、何が起きたか分からない。

### 5. その場で編集する入力欄は 1 つを使い回す

コードカード用に作った入力欄（裏に色付きの層、表に透明な textarea）を
そのまま 4 種に使う。中身はそのカードの**元の行**。

- コード: ` ``` ` の開きから閉じまで（囲いは保護、言語名は打てる）
- リンク: `[題](URL)` の 1 行
- 画像: `![](パス)` の 1 行
- SVG: `<svg>` から `</svg>` まで

囲いの保護（`touchesFence`）はフェンスのときだけ効く。他の 3 種は素の 1 行
なので守るものが無い。

**結果がそのカードで無くなったら、カードは消えて本文に戻るだけ。**
（既にコードで決めた振る舞いをそのまま広げる）

### 6. 掴み方

**選んでいるカードの上からのドラッグだけ**がカードを動かす。
選んでいないカードの上からは、従来どおりノードが動く。

カードはノードの面積の大半を占めることがある（画像・コード）。無条件に
カードを掴ませると、そこでノードを掴めなくなり、既存の D&D が痩せる。
クリックで選んでから掴む 2 手間と引き換えに、**今できることを何も奪わない**。

落とし先は「どのノードの、何枚目と何枚目の間か」。線で示す。

## 触るもの

| ファイル | 何を |
|---|---|
| `src/map/cards.ts` | 4 種すべてに `from`/`to` を持たせる |
| `src/map/cardEdit.ts`（新設） | 移動・削除のオフセット計算（純粋） |
| `src/main.ts` | 選択の持ち主・カードのコマンド |
| `src/mindmap.ts` | 選択の描画・ドラッグ・キー・入力欄の一般化 |
| `test/cardEdit.test.ts`（新設） | オフセット計算の単体テスト |

`core/`（MoonBit）は**一行も変えない**。

## 検証

移動と削除は「どの範囲を何で置き換えるか」に尽きるので、**純粋関数に
切り出して単体テストする**。ここが合っていれば、あとは配線。

配線（クリック・ドラッグ・キー）はブラウザで確認する。過去に
「要素へ直接 dispatch して通ったが、実際はポインタキャプチャで
イベントがペインへ付け替わって届いていなかった」ことがあるので、
**実際に通る経路（ペイン）で試す**。

## やらないこと

- カードの複数選択（まとめて動かしたい場面がまだ無い）
- ノードとカードを同じ集合に混ぜること
- コアにカードの概念を入れること
- カードのコピー / 貼り付け（`Mod+C/V`）— 選択の共存が固まってから
