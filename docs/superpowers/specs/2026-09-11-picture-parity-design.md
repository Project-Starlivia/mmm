# 画面と書き出しで同じ絵になるための定義（#292 の前段）

#292 は 3 つの症状（角が四角い / コードの字が 1.36 倍に伸びる / ラスタで字が落ちる）を挙げている。
**症状を 1 つずつ塞ぐ前に、寸法と見た目の持ち主を決める。** 決めないと、CSS に見た目を足すたび
書き出しだけが黙って古くなる。

## 今の仕組み（読んで測った事実）

**数の唯一の定義は `core/map/metric.mbt`。** 字の大きさ・余白・行の高さ・隙間は全部そこにしか無い。
外から受けるのは**字の幅 1 つだけ**。

```moonbit
pub type Measure = (Font, String) -> Double     // 実体は canvas の measureText
pub type SizeOf = (@tree.Node, Array[Card], Int) -> Size
pub fn node_size(measure : Measure) -> SizeOf
```

`family`（綴り）は core が持たない — `app/mindmap/measure.mbt` が CSS の `--font` / `--mono` を
読んで `13px <family>` に組み直し、canvas で測る。だから **箱の寸法は「この機械のこの字」で決まる。**

`metric.mbt` は「ラベル行の寸法は 3 者（レイアウト・SVG の描画・編集用の `<input>`）が同じ値を
見なければならない」と書き、そのために **`font-size` は CSS ではなく属性で入れる**と決めている。

`src/style.css:707` は逆向きの決めを書いている。

```css
/* 角丸は「状態で変わるだけの定数」なので CSS が持つ（SVG2 の geometry
   property。属性より CSS が勝つ）。TS が出すのは、レイアウトが計算した数だけ */
```

書き出し（`app/mindmap/svg.mbt`）は DOM の写しに**計算済みスタイルを 11 個だけ焼き**、
`<text>` ごとに `getComputedTextLength()` を `textLength` + `lengthAdjust="spacingAndGlyphs"` として
焼き、**`class` を外す**。

## 3 つの面が、それぞれ何をできるか

| 面 | 字を測れるか | CSS が効くか | 字が在るか |
|---|---|---|---|
| 画面（DOM） | 測れる（canvas） | 効く | 在る（`@font-face`） |
| 書き出した SVG | **こちらは測れない**（相手の機械の字で描かれる） | **効かない**（`class` を外している） | 相手次第 |
| ラスタ（WebP / PNG） | 同上 | 同上 | **無い** — `new Image()` に `data:image/svg+xml` を食わせるので、ページの `@font-face` を引けない |

## 破れの根は 2 つ

### 根 1 — 見た目の持ち主が 2 つある

「状態で変わるだけの定数は CSS」は画面では正しい。**写しが `class` を外す**ので、書き出しでだけ消える。
焼く 11 属性は**数え上げの表**なので、CSS に足すたび書き出しが黙って古くなる。

いま CSS だけが持っている、幾何を決めるもの（地図の節、12 宣言）:

| もの | 宣言 | 効き |
|---|---|---|
| `rx` | 5 か所（箱 8px / 画像の場所取り 6px / コードの地 5px / 畳んだ箱 4px / ほか） | 角が四角くなる |
| `white-space: pre` | 4 か所（ラベル / コード行 / details 行） | 空白が畳まれる |
| `font-size` | 1 か所（`text.link-open` 13px） | **`metric.mbt` の決めに反して CSS に数字が居る**（焼く 11 属性に入っているので書き出しは無事） |
| `text-decoration` | 1 か所（画像の繋ぎ直しの下線） | 下線が消える |

**`rx` / `ry` は SVG2 の geometry property で、CSS が属性に勝つ。** だから
「`class` も `<style>` も連れて行く」と「属性で焼く」は**両立しない** — どちらが持つかを決める必要がある。

### 根 2 — 箱は測った字に従うのに、測り方が面ごとに違う

箱の寸法は字の実測から出る。相手は**測り直せない**（数は焼かれていて、字も違う）。
だから今は**字を箱に合わせて潰している**（`textLength` + `spacingAndGlyphs`）。

そのうえ、`white-space` が落ちた面では **`pre` で測った幅を、空白の畳まれた字に当てている**。
#292 の実測で 1.36 倍。**これは字が同じ機械でも起きる** — 測った対象と当てる対象が違うから。

## 定義の候補 — 誰が誰に従うか

| | 何が真実か | 画面と書き出しの一致 | 代償 |
|---|---|---|---|
| **A 字が箱に従う**（今） | 箱（こちらの実測） | 字形が崩れる | 相手の字が違えば潰れる。ラスタは字ごと落ちる |
| **B 箱が字に従う** | 字（相手の実測） | 箱の寸法が面ごとに変わる | `core/map` の「寸法は実測で固定」を崩す。レイアウト（隙間・折り返し）も面ごとに変わる |
| **C 測る入力を同じにする** | 字（埋めた woff2） | 一致する | 書き出しが約 57 KB 増える。`#126`「伸び縮みは字が負う」を引き戻す |

**C の大きさは測った。** `src/fonts/` の woff2 は 6 つで 43,144 バイト、base64 で約 57 KB。

## 実機で測った（Chromium 148、`<img>` + `data:image/svg+xml` の道）

どちらの道が成り立つかは**当て推量では決まらない**ので、`<img>` に食わせた SVG で測った。

| 試したこと | 結果 |
|---|---|
| 埋めた woff2（`<style>` の `@font-face` に `data:font/woff2;base64,…`） | **効く** — 埋めた絵と埋めない絵でピクセルが違う |
| `white-space="pre"` を**属性**で | **効かない** — 属性を付けない絵と 1 ピクセルも変わらない（先頭の空白が畳まれたまま） |
| `xml:space="preserve"` | 効く（SVG2 では非推奨） |
| `style="white-space:pre"` | 効く |
| `rx="16"` を属性で | 効く |
| `<style>` の `rx:0px` + 属性 `rx="16"` | **CSS が勝つ**（角が四角い）— style.css の但し書きどおり |
| `<style>` の class 選択子（`.b{rx:16px}`） | **効く** — `<img>` 経由でも CSS は生きている |

**ここから 2 つ言える。**

1. **「幾何は全部属性で」は成り立たない。** `white-space` に属性の形が無いので、
   そこだけ `xml:space` か inline style の特例になる — **殺したかった数え上げが残る**
2. **`<style>` と class は 3 面すべてで効く。** ラスタの道（`<img>`）でも生きている

## 提案する定義（測った結果で入れ替えた）

**1. 焼くのをやめ、`class` と `<style>` を連れて行く。**

写しから `class` を外すのをやめ、**地図の CSS を `<style>` としてそのまま持たせる**。
`var(--…)` は書き出しの時点で解いた値を `:root` の 1 ブロックに入れて一緒に運ぶ
（変数は `getComputedStyle` で読める）。すると:

- **数え上げの表が消える。** 焼く 11 属性も、幾何を属性へ移す作業も要らない
- CSS に見た目を足しても書き出しは古くならない（**同じ規則を両方が読む**）
- `white-space` の特例も要らない（CSS のまま効く）
- 状態の見た目（選択・落とし先・掴み中）は**いま既に落としている**（`transient`）ので、
  その 3 つの class を写しから外すだけで足りる

代償は **書き出しがスタイルシートに依存すること**。これは欠点ではなく**定義**で、
「画面と書き出しは同じ規則を読む」がそのまま一致の保証になる。持ち込む量は地図の節だけ
（`style.css` 全体 58,898 バイトのうち、`.node` 以下の節）。

**2. 字は埋める。`textLength` / `lengthAdjust` はやめる。**

箱が字に従うのでも字が箱に従うのでもなく、**測る入力を同じにする**。
`src/fonts/` の woff2 は 6 つで 43,144 バイト（base64 で約 57 KB）。埋めれば
**ラスタの道も直る**（上の実測）。`#126`「伸び縮みは字が負う」は要らなくなる。

**3. `metric.mbt` の「数は core、CSS に同じ数字を持たせない」は変えない。**

レイアウトが計算する数（位置・大きさ・font-size）は今も属性で出る。CSS が持つのは
**状態で変わるだけの定数と色**で、`style.css:707` の決めがそのまま正しい。
#292 が壊れていたのは、その決めと**写しが `class` を外すこと**が食い違っていたからで、
決めを変える必要は無かった。

## 決めてもらうこと

1. **`<style>` を連れて行く形にしてよいか。** 書き出しが `style.css` の地図の節に依存する
   （＝画面の見た目を変えると書き出しも変わる）。**それが狙い**だが、「書き出しは焼き付けた
   もので、あとから変わらないほうがよい」という考え方も在りうる
2. **字を埋める先は書き出した SVG だけか、ラスタも同じ道を通すか。** ラスタは SVG を
   食わせているので、埋めれば自動で直る。大きさの上限（#172）には 57 KB 効く
3. **`#126`（伸び縮みは字が負う）を引き戻してよいか。** 2 はその決めを置き換える

## やらないこと

- **B（箱が字に従う）は採らない。** レイアウトの数まで面ごとに変わると、地図の隙間・折り返し・
  当たり判定の前提（`core/map` の「寸法はこちらの実測で固定」）が全部揺れる
- 角丸だけを足して閉じることはしない（#292 の「表で持ち続ける限り漏れは再発する」がそのまま残る）
- **幾何を全部属性へ移すことはしない。** `white-space` に属性の形が無く（実測）、
  そこだけ特例になるので、殺したかった数え上げが残る
