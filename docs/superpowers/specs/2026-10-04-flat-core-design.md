# 変換コアの作り直し — 切れの木

2026-10-04。**妄想の段**（実装の計画はまだ無い）。今の規則を新しい構造の言い方へ置き換え、
判断の要る所を末尾に残す。

## なぜ

今の木は md の綴りを**属性**で持ち（`Mark` の欄・`Block.source`・`Root.rules`）、中身（`body`）と
子（`children`）を**別の配列**に分ける。そこから 3 つの苦しさが出ている。

- 中身と子の前後を木が持たないので、木から md を書き直すと中身が子の手前へ寄る（#377 #378 #386-3）
- 木から md を作り直す段（`unbuild`）と、部分で写せないときの全文の書き直しが要る
- 「書けるか」を check・書く側・操作の 3 か所で言い、ずれる（#382）

md と左右の地図を、どちらも綴りまで失わずに真実として保つ先例は無い（Org-mode・ProseMirror・
recast・lens はどれもどこかを諦めている）。諦めずに、**持ち方**を変える。

## 構造

**切れ** — md を AST で切ったもの。項目の中まで降りる。**属性は持たず、字だけ。**
`##` の数も、マーカーも、閉じの本数も、切れの字そのもの。深さや種類は字から毎回読む。

- 行頭の字下げは、その行の切れに含む（入れ子の項目の 1 行目の `␣␣` も）。切れは自分の全部の
  行の字下げを持つ
- リンクの定義行のように AST の子に入らない字も、範囲を見て列に差し戻す

**持ち主** — どの切れも、前にある一番近い「特殊なもの」に従属する。

| 特殊なもの | 持つ範囲 |
|---|---|
| 見出し | 次の同じか浅い見出しまで、後ろを全部 |
| 項目 | 自分の字下げの範囲だけ（列の外へ出た字は持たない） |
| コード | 開きが、中身の行と閉じを子に持つ |
| `<details>` | 開きが、閉じまでを子に持つ |
| 文書 | 最初の特殊なものより前 |

空行・`---`・段落・画像などは子を持たない。**子は 1 本の並び** — 空行も中身も子の見出しも、
書かれた順のまま同じ列に入る。

**md は切れを順に連結したもの。** 触っていない切れの字は 1 文字も変わらない。

```md
# root

## abc

### fafa

---

### hogehoge
```
```
# root
├ ⏎
└ ## abc
   ├ ⏎
   ├ ### fafa
   │  ├ ⏎
   │  ├ ---
   │  └ ⏎
   └ ### hogehoge
```

## 流れ

```
1. 読む     md → 切れ → 構造。md の素直な読みで階層を作る（`---` は階層を変えない）
2. 操作     構造の上で動かす・足す・消す。木の位置が真実で、切れの字は古いまま運ぶ
3. md 化    読み直して狙った階層になる分だけ、切れの字を綴り直す（必ず通る）
4. 拡張     継ぎ目で読みが変わるなら空行の切れを足す（アプリは既定で有効）
5. 連結     → md。CodeMirror への編集は、変わった切れの範囲から作る
描く        構造 → 地図。空行は落とし、Implicit は深さの飛びから描く。
            `---` が左右の分かれ目か装飾かも、ここで解釈する（境界は描く段のもの）
```

- **階層は構造が持ち、記法は階層を持たない。** md → 構造のときだけ記法を見る
- **基本構造は自分から切れを足さない。** 意味を守るために足すのは拡張（4）。
  ただし操作が意味として持つもの（左右の `---`、畳みの開き・閉じ）は操作が足し引きする
- **md 化で読み直しても合わなければ、md の読みが勝つ。** 操作は文字通り行い、結果を見せて
  undo に任せ、focus は外す（今の決めを引き継ぐ）

## 規則の置き換え

左が今の規則、右が新しい言い方。**引き継ぐ**は言い方だけ変わるもの、**消える**は構造が
自然に満たすので規則として要らなくなるもの。

### 文書モデル（spec.md「文書モデル」）

| 今 | 新しい言い方 |
|---|---|
| 意味を 1 ビットも失わない。記法は mmm が所有する | 引き継ぐ。md は切れの連結なので、触っていない字は構造上変わらない |
| 読んだ綴り（マーカー・setext の下線・閉じの `#`・境界の線・表・フェンス・定義行の位置）は保つ | **消える。** 綴りは切れの字そのもので、保つ仕組みが要らない |

## 判断待ち

### J1 — 境界の後ろの中身の持ち主（決めた）

```md
# r

## 野菜

---

- 肉

メモ
```
**構造は md の素直な読み。** `---` は節を閉じない（HTML の `<hr>` は節の中の話題の転換）ので、
`---` も肉もメモも野菜の子で、書かれた順に並ぶ。連結の原則は崩れない。
```
# r
└ ## 野菜
   ├ ---
   ├ - 肉
   └ メモ
```
**境界は描く段の解釈。** `---` が装飾か左右の分かれ目かは、md の字からは分からない（書いた人が
線を引きたかったのか、左へ出したかったのか）。深さの違いではなく、1 つの記号に意味が 2 つある
ことが本質。地図は今と同じ規則（直後が同じ木の見出しか項目なら、どの深さでも左右）で推測する —
書き心地を取った（複雑なのは承知）。この例なら肉は根の左に描かれ、メモは野菜のまま。

**その代わり、地図の見た目と構造がずれる。** 深い境界の後ろの行は、構造では元の親の子、地図では
根の反対側。地図の操作をその行に当てるときは、描く段の解釈を逆にたどって構造の操作に直す。
この翻訳と描く段の解釈は**境界の部品 1 か所**に閉じる（今は 9 段に散っている）。

### J2 — 畳みが立つ条件（決めた）

② をやめ、① だけ残す。`<summary>` は必須にしない。複数のノードを包む `<details>` は今と同じく
Details カード（地図に「まとめて畳んだもの」の見せ方が無いので）。

### J3 — 深い見出しの名前に改行（決めた）

断らない。`### 果物と` / `野菜` と書き、読み直すと 2 行目は中身になる。名前を `---` に変えたときと
同じ 1 本の規則（md の読みが勝つ、undo に任せる）で、例外が消える。
