# 変換コアの作り直し — 塊の木

2026-10-04。**妄想の段**（実装の計画はまだ無い）。今の規則を新しい木の言い方へ置き換え、
判断の要る所を末尾に残す。

## なぜ

今の木は md の綴りを**属性**で持ち（`Mark` の欄・`Block.source`・`Root.rules`）、中身（`body`）と
子（`children`）を**別の配列**に分ける。そこから 3 つの苦しさが出ている。

- 中身と子の前後を木が持たないので、木から md を書き直すと中身が子の手前へ寄る（#377 #378 #386-3）
- 木から md を作り直す段（`unbuild`）と、部分で写せないときの全文の書き直しが要る
- 「書けるか」を check・書く側・操作の 3 か所で言い、ずれる（#382）

md と左右の地図を、どちらも綴りまで失わずに真実として保つ先例は無い（Org-mode・ProseMirror・
recast・lens はどれもどこかを諦めている）。諦めずに、**持ち方**を変える。

## 言葉

**和名 first。** 設計書・図・会話は和名で書き、英名はコードの識別子として対で持つ。和名と英名は
同じものを言う。木のたとえは木のたとえで揃える。「md」は記法の名前（Markdown）としてだけ使う。

### 木

| 和名 | 英語 | 意味 |
|---|---|---|
| **原文** | `source` | 書き手が書いた字そのもの。木の外にあり、真実はここ |
| **塊** | `Block` | md を AST で切った 1 つ。字だけを持ち、属性は持たない。塊を順につなぐと原文に戻る（隙間なく覆う）。行頭の字下げはその行の塊に入る |
| **木** | `Tree` | 塊の木。md の素直な読みで親子を決めたもの |
| **親 / 子** | `parent` / `children` | 塊は、その位置を範囲に含む一番内側の持ち主の子になる。子は書かれた順の 1 本の並び |
| **持ち主** | `Owner` | 子を持てる塊と、その範囲。見出しは次の同じか浅い見出しまで、項目は字下げの範囲、コードのフェンスと `<details>` は閉じの行まで。木そのものも最初の持ち主より前の塊を持つ |
| **葉** | `Leaf` | 子を持たない塊。段落・画像・線・空行など |
| **深さ** | `depth` | 木の中の段。塊の字（`#` の数・字下げ）からは読むだけで、持たない |

### 流れ

| 和名 | 英語 | 意味 |
|---|---|---|
| **読む** | `read` | 原文 → 木 |
| **操作** | `Op` | 木の上で動かす・足す・消す。操作の間は木の位置が真実 |
| **席** | `Place` | 操作が塊を置く所。隣の塊で言う |
| **綴り直す** | `respell` | 操作の後、読み直して狙った木になる分だけ塊の字を書き換える（`#` の数・字下げ・置いた場所の記法）。必ず通る |
| **継ぎ目** | `seam` | 塊と塊の境。そこで読みが変わるなら空行の塊を足す（アプリは既定で有効） |
| **書く** | `write` | 木 → 原文。塊を順につなぐだけ |

### 地図

| 和名 | 英語 | 意味 |
|---|---|---|
| **描く** | `draw` | 木 → 地図 |
| **地図** | `Map` | 描いた姿。木と違う姿になる所（境界・飛び）は描く段の読み替え |
| **根** | `Root` | 地図が 1 本の木として描く単位。木の直下の持ち主で、木の中では特別な型を持たない（描く段が親が木かで見分ける）。左右は根の子にある |
| **ノード** | `Node` | 地図が箱として描く塊（見出しと項目）。持ち主かどうかとは別の、描く段の役 |
| **カード** | `Card` | 地図がノードの中に描く塊（画像・リンク・コード・svg・線・立たなかった畳み）。コードのように持ち主でもカードになる |
| **境界** | `Border` | 描く段が左右の分かれ目と読む `---`。読み替えと、その逆に操作を木へ直す翻訳は、この部品 1 か所に閉じる |
| **側** | `Side` | 根の子が右か左か。値は持たず、境界から読む |
| **飛び** | `Skip` | 描く段が、深さの飛びと境界の後ろの段に描く空の箱。木には居ない。操作されたら塊を足して見出しにする |
| **場所** | `Spot` | 塊が原文のどこにあるか |

## 木

**塊** — md を AST で切ったもの。項目の中まで降りる。**属性は持たず、字だけ。**
`##` の数も、マーカーも、閉じの本数も、塊の字そのもの。深さや種類は字から毎回読む。

- 行頭の字下げは、その行の塊に入る（入れ子の項目の 1 行目の `␣␣` も）。塊は自分の全部の
  行の字下げを持つ
- リンクの定義行のように AST の子に入らない字も、範囲を見て並びに差し戻す

**親子** — どの塊も、前にいる一番近い持ち主の子になる。

| 持ち主 | 子に持つ範囲 |
|---|---|
| 見出し | 次の同じか浅い見出しまで、後ろを全部 |
| 項目 | 自分の字下げの範囲だけ（並びの外へ出た字は持たない） |
| 開き（コード・`<details>`） | 閉じまで |
| 木 | 最初の持ち主より前 |

葉（空行・`---`・段落・画像など）は子を持たない。**子は 1 本の並び** — 空行も葉も子の見出しも、
書かれた順のまま同じ並びに入る。

**md は塊を順につないだもの。** 触っていない塊の字は 1 文字も変わらない。

```md
# root

## abc

### fafa

---

### hogehoge
```
```
# root
├ ⏎
└ ## abc
   ├ ⏎
   ├ ### fafa
   │  ├ ⏎
   │  ├ ---
   │  └ ⏎
   └ ### hogehoge
```

## 流れ

```
1. 読む       md → 木。md の素直な読みで親子を決める（`---` は親子を変えない）
2. 操作       木の上で動かす・足す・消す。木の位置が真実で、塊の字は古いまま運ぶ
3. 綴り直す   読み直して狙った木になる分だけ、塊の字を書き換える（必ず通る）
4. 継ぎ目     継ぎ目で読みが変わるなら空行の塊を足す（アプリは既定で有効）
5. 書く       塊を順につなぐ → md。CodeMirror への編集は、変わった塊の範囲から作る
描く          木 → 地図。空行を落とし、深さの飛びと境界の後ろに飛びの箱を描く。
              `---` が境界か装飾かも、ここで読み替える
```

- **親子は木が持ち、記法は親子を持たない。** md → 木のときだけ記法を見る
- **操作は自分から塊を足さない。** 意味を守るために足すのは継ぎ目（4）。
  ただし操作が意味として持つもの（左右の `---`、畳みの開き・閉じ）は操作が足し引きする
- **綴り直しても読み直すと合わなければ、md の読みが勝つ。** 操作は文字通り行い、結果を見せて
  undo に任せ、focus は外す（今の決めを引き継ぐ）

## 規則の置き換え

左が今の規則、右が新しい言い方。**引き継ぐ**は言い方だけ変わるもの、**消える**は構造が
自然に満たすので規則として要らなくなるもの。

### 文書モデル（spec.md「文書モデル」）

| 今 | 新しい言い方 |
|---|---|
| 意味を 1 ビットも失わない。記法は mmm が所有する | 引き継ぐ。md は塊の連結なので、触っていない字は構造上変わらない |
| 読んだ綴り（マーカー・setext の下線・閉じの `#`・境界の線・表・フェンス・定義行の位置）は保つ | **消える。** 綴りは塊の字そのもので、保つ仕組みが要らない |

| ラベルに改行がある見出しは setext。深さ 3 以上は断る（`DeepSetext`） | setext は引き継ぐ。**深さ 3 以上でも断らない** — そのまま書き、md の読みが勝つ（2 行目は中身になる）。undo に任せる |

| 今 | 新しい言い方 |
|---|---|
| 全部の記法・本数が同じ意味。何が水平線かは md の文法が決める | 引き継ぐ |

## 判断待ち

### J1 — 境界の後ろの中身の持ち主（決めた）

```md
# r

## 野菜

---

- 肉

メモ
```
**構造は md の素直な読み。** `---` は節を閉じない（HTML の `<hr>` は節の中の話題の転換）ので、
`---` も肉もメモも野菜の子で、書かれた順に並ぶ。連結の原則は崩れない。
```
# r
└ ## 野菜
   ├ ---
   ├ - 肉
   └ メモ
```
**境界は描く段の解釈。** `---` が装飾か左右の分かれ目かは、md の字からは分からない（書いた人が
線を引きたかったのか、左へ出したかったのか）。深さの違いではなく、1 つの記号に意味が 2 つある
ことが本質。地図は今と同じ規則（直後が同じ木の見出しか項目なら、どの深さでも左右）で推測する —
書き心地を取った（複雑なのは承知）。この例なら肉は根の左に描かれ、メモは野菜のまま。

**その代わり、地図の見た目と構造がずれる。** 深い境界の後ろの行は、構造では元の親の子、地図では
根の反対側。地図の操作をその行に当てるときは、描く段の解釈を逆にたどって構造の操作に直す。
この翻訳と描く段の解釈は**境界の部品 1 か所**に閉じる（今は 9 段に散っている）。

### J2 — 畳みが立つ条件（決めた）

② をやめ、① だけ残す。`<summary>` は必須にしない。複数のノードを包む `<details>` は今と同じく
