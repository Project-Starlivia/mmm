# 画像フォルダの場所を .md の頭に書く

## なぜ

「実体はただの `.md`」と言い切っているのに、**その md の画像がどこにあるかだけが
ブラウザの中にいる**。いまは `window.prompt` で聞いた宣言パスを、フォルダ
ハンドルと一緒に IndexedDB へ置いている（`app/handles.ts` の `AssetBinding`）。

だから別マシンで開くと宣言が消える。md をそのまま渡された人には、そこに画像が
あったことすら分からない。`![](./img/a.webp)` という行だけが残る。

宣言を md の頭に書けば、**md 自身がそれを知っている**。

```
---
image-folder: ./img/
---

# 設計メモ

![](./img/a.webp)
```

## 頭 — 先頭の `---` … `---`

**先頭行がちょうど `---` で、後続にちょうど `---` の行があるとき**だけ頭になる。

- **先頭限定**。2 行目以降の `---` は今までどおりただの区切り線
- **閉じが要る**。閉じないまま文書が終われば頭ではない
- 開きも閉じも**ちょうど 3 本**。`----` も `...` も閉じない（Jekyll と同じ）
- 中は**一切走査しない**。見出しもリスト項目も作らず、`list_from` にも数えず、
  フェンスや hide の状態も持ち込まない

**不変条件: 頭の中の行は、何を書いてもノードにならない。**

これが今回いちばん効く。他ツール（Obsidian / Jekyll / Zenn）が書いた frontmatter の

```
tags:
  - 設計
  - web
```

は、いまの mmm ではマップに**ノードとして生えてくる**（`^\s*[-*+]\s` はリスト
項目なので — `core/parser.mbt`）。頭を非構造区間にすると、これが消える。

**割り切り**: 先頭が `---`（区切り線のつもり）で、後ろにもう 1 本 `---` がある
文書は、頭として吸われる。Jekyll も Obsidian も同じ挙動なので合わせる。

## 設定の名前 — `image-folder`

値は `.md` から見た**フォルダの相対パス**。

`images` ではない — それは「画像の一覧」に読める。名乗らせたいのは 1 つの
フォルダの場所なので、主名詞は `folder`、修飾は `image`（英語の複合名詞は修飾語が
単数： `image folder` / `file manager`）。

`mmm:` の入れ子にもしない。設定 1 つに名前空間は大袈裟で、増えてから考えれば
いい。綴りは kebab — frontmatter は md の世界のものなので md の慣習に寄せる。

## 誰が何の真実を持つか

ブラウザは**パス文字列からフォルダハンドルを作れない**。だから宣言と許可は
どうしても 2 つに分かれる。分かれること自体は避けられないので、**どちらが
何の真実なのかを言い切る**。

| | 持ち主 | 何 |
|---|---|---|
| 宣言 | **.md の頭** | md から見て画像がどこにあるか |
| 許可 | IndexedDB のハンドル | そのフォルダを読み書きしてよいという承諾 |

`AssetBinding` から `path` が落ちて `{doc, directory}` になる。宣言を失うことは
もう無く、**フォルダを選び直せば復帰する**。

## core の変更

### `parser.mbt` — `Head` 区間

`scan_doc` に 1 区間足す。`Fence` と同じ形。

```
priv struct Head {
  start : Int      // 開き `---` 行の行頭
  end : Int        // 閉じ `---` 行の行末（改行の手前）
  body_start : Int // 中身の最初の行頭
  body_end : Int   // 中身の最後の行末。中身が無ければ body_start より手前
}
```

`Scan` に `head : Head?` を足し、走査の最初に決める。頭が成立したら、以降の
行走査は `end` の次の行から始める。

### `api.mbt` — snapshot に `head`

```json
"head": { "from": 0, "to": 25, "bodyFrom": 4, "bodyTo": 24 }
```

頭が無ければ `null`。**位置だけで、中身の解釈はしない** — `image-folder` という
綴りを core は知らない。

`src/coreApi.ts` には `FenceSpan` と並べて `HeadSpan` を足し、`Snapshot.head` と
`DocView.head` に載せる。テキスト・ノード・フェンスと**必ず同じ rev の組**で
持ち回る（`main.ts` の `applySnap` が組む `doc` に 1 つ増える）。

### 副産物 — 貼り付けにも効く

`has_headings` / `relevel_text` は `scan_doc` を通る（`core/relevel.mbt`）。頭の
判定をそこに置くので、**frontmatter 付きの md を丸ごと貼り付けても頭は構造に
数えない**。規則を 2 つ持たないことの見返り。

## TS の変更

### `src/app/head.ts`（新設）— 文書の頭の設定

純関数だけ。DOM もコアも知らない。

```ts
/** 頭から `image-folder` の値を読む。無ければ null */
imageFolder(text: string, head: HeadSpan | null): string | null

/** 値を差し替える編集を 1 つ返す */
setImageFolder(text: string, head: HeadSpan | null, value: string): TextEdit

/** 宣言の綴りを決める唯一の場所。相対でなければ null */
normalizePath(value: string): string | null

/** 宣言フォルダの引っ越しに、本文の画像リンクを追従させる */
retarget(doc: DocView, from: string, to: string): TextEdit[]
```

`setImageFolder` は 3 つの場合を持つ。

| 頭の状態 | 書き方 |
|---|---|
| キーがある | **その行だけ**差し替える |
| 頭はあるがキーが無い | 閉じ `---` の直前に 1 行足す |
| 頭が無い | 文書の先頭に `---\nimage-folder: …\n---\n\n` を作る |

**YAML パーサは入れない。** 依存が増えるからではなく、読んで書き戻すと他ツールが
書いたコメント・引用符・キーの順序が消えるから。「未編集行のバイト列は決して
再整形されない」という core の約束を、TS 側で破ることになる。読むのは 1 キー、
書くのも 1 行。

`normalizePath` は `app/assets.ts` からここへ移す。値の綴りを決める場所は 1 つ。

### 値の引用符

フォルダ名に空白は普通にある（`./My Images/`）。YAML では `#` の手前に空白が
あるとそこからコメントになり、`:` の後に空白が続く綴りも曖昧になる。

- **読むとき**: 前後の `"` か `'` で囲まれていれば剥がす
- **書くとき**: 値に空白・`#`・`:` のどれかが含まれるなら `"` で囲む。
  含まれなければ裸で書く（`./img/` を `"./img/"` とは書かない）

囲むのは `"` だけ。中の `"` と `\` は `\` で逃がす。

### `src/map/cards.ts` — `parseImage` が位置も返す

いま `parseImage` は正規化済みのパスだけを返す（`./` を剥がした形）。書き換えは
**行の中のその destination だけ**を差し替えたいので、生の綴りとその範囲も返す。

```ts
{ path, name, raw, from, to }   // from/to は行頭からのオフセット
```

`![](…)` という綴りを知っている場所は、これで引き続き 1 つ。

## 本文の一括書き換え

`retarget` は文書の全行を走査し、

1. **頭とフェンスの中は飛ばす**（`doc.head` / `doc.fences`）
2. `parseImage` が通る行だけ見る（外部 URL は既に弾かれている）
3. その destination が `from` の下にあるものだけ、**接頭辞を `to` に差し替える**

適用は**後ろから**、全部同じ tag で `core.replaceText`。`apply_sets` は同じ tag の
エントリをまとめるので、**Undo 1 回で全部戻る**（`core/history.mbt`）。

### 巻き込みの柵

柵を張っているのではない。**接頭辞の置換だから、そうなる**だけ。`./img/` から
動かすなら `./other/b.webp` はそもそも一致しない。

例外は `./` ひとつ。`./` は全ローカルパスの接頭辞なので、`./` **から**の移動は
必ず全掃きになる。それは「画像は md と同じ場所にある」と宣言していた状態からの
引っ越しなので意味的には正しく、掃かれて困るのは**宣言の外に置いたパス**だけ。

そして宣言の外は、mmm では元から映らない（`assetTarget` が弾く）。だから
巻き込みの実害は「他のツールでは映っていた .md を mmm が黙って壊す」に限られ、
`Mod+Z` 1 回で戻る。**末尾から消して打ち直せば `./` を通る**が、その代償で
待ち時間を買うほどではないと判断した。

読めない値（`/` 始まり・`http://`）では**何もしない** — 書き換えも、フォルダの
結び付けも。`normalizePath` が既に null を返す。

**空（trim 後が空文字）も null。** 空値は宣言ではなく書きかけの行なので、
そこで全掃きが走らないのは単純に正しい。

## 発火 — 打鍵のたび、その打鍵に相乗りして

追従は `onUserEdits` の末尾で走る。頭を打った直後に本文が追いつく。

1. いまの宣言値 `next` を読む（読めなければ何もしない）
2. `applied`（本文がいま映している値）と違えば `retarget(applied, next)` を適用
3. `applied = next`。**フォルダは結び直さない** — 同じハンドルのまま
   `assets.clear()` で読み直すだけ（フォルダ名が変わったわけではなく、
   md から見た相対の綴りが変わっただけなので）

**待たない代わりに、その打鍵が使った `tag` をそのまま渡す。** コアは同じ tag の
編集を 1 エントリに併合する（`core/history.mbt`）ので、頭の打鍵と本文の書き換えは
同じ Undo に入り、打鍵が続くかぎり増えない。`Mod+Z` 1 回で打った分ごと戻る。

そのために 2 つ足りなかった:

- **`origin` に `follow` が要る。** `applySnap` は「打鍵以外」で打鍵の連なりを
  切るが、追従で切ると連なりが毎打鍵途切れて Undo が細かくなる。書き換えは
  頭より後ろにしか起きず CM 側の挿入位置はずれないので、切る理由が無い
- **空の `tag` では併合されない**（`history.mbt` が `tag != ""` を要求する）。
  選択を置き換える打鍵は tag が空だったので、頭と本文が別エントリになり、
  1 回戻すと食い違った。他と重ならない名前を配れば、前後と連ならないまま
  追従だけが同じエントリに入る

`applied` は「打鍵のとき」だけ据え置き、それ以外（読み込み・undo/redo・
フォルダ選択）では `applySnap` が宣言に揃え直す。だから開いた直後も戻した直後も、
本文が勝手に動くことは無い。

編集が複数になっても `applySnap` は 1 回。各回の `editSets` を繋いで最後に渡す
（そうしないと画像の枚数だけ再描画が走る）。

## 入口 — メニューは許可だけ

`Images Folder` は**フォルダを選ぶだけ**。`window.prompt` は消える。

頭に宣言が無い状態で選んだときだけ、そこで書き込む。

- `directory.resolve(mdハンドル)` が非 null → **正確に逆算**できる。返るのは
  フォルダから md までの断片なので、**末尾のファイル名を除いた数**だけ
  `../` を積む（`["a.md"]` → `./`、`["notes","a.md"]` → `../`、
  `["a","b","c.md"]` → `../../`）
- null → `./<フォルダ名>/`。md の隣に `img/` を置く、いちばん普通の形

caption は**宣言と許可の 4 通りを言い分ける**。食い違っていることが、そこだけで
分かるように。

| 宣言（頭） | 許可（ハンドル） | caption |
|---|---|---|
| 無 | 無 | `none` |
| 有 | 無 | `folder not linked` |
| 有 | 有 | `<フォルダ名>` |
| 無 | 有 | `<フォルダ名>, not declared` |

最後の 1 行が移行のための欄。`AssetBinding` から `path` が落ちたので、頭を持たない
既存文書は宣言が `./` に倒れ、以前 `./img/` で結んでいた人の画像は探し先が外れて
黙って空になる。**結び付いているのに映らない**という一番分かりにくい状態なので、
caption がそう名乗って「フォルダを選び直せ」へ誘導する。

## 移行

古い IndexedDB レコードは `path` を持っているが、`isBinding` からその検査を
落とせばそのまま読める（余分なフィールドは無視される）。宣言は次にフォルダを
選んだとき頭へ書かれる。

`README.md` の構成表に `app/head.ts`（文書の頭の設定）を 1 行。

## やらないこと

- **YAML パーサ** — 上記のとおり
- **頭の色分け** — md ペインでは普通のテキストのまま。読めないわけではない
- **設定を増やす** — テーマも書き出しの向きも頭には来ない。いまの要求は
  `image-folder` 1 つ
