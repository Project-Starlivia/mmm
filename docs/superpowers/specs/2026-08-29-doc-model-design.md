# 文書モデル設計 — 同型 Model と投影

2026-08-29。バグ 22 件修正（PR #14）から始まった core 再設計の記録。
「md エディタとしての作り直し」→「B 憲法（モデルが真実・md は鏡）」→「レンズ + 局所パッチ」を経て、
クリーンセッション 3 本のレビュー（[所見](2026-08-29-review-findings.md)）で局所パッチ案の
致命傷が確定し、**同型 Model + 投影**で確定した。実装はこのブランチで進める。

## 0. 自己定義

> **mmm は md を所有しない。自由な md の上に住むマインドマップのレンズである。**

md の存在理由は可読性ではなく**自由**（読むだけなら画像で足りる）。
正規形しか許さない md は md の皮を被った独自フォーマットであり、それなら JSON でよい。
散文・崩し記法・mmm が解釈できないものも、テキストにある限り消えない。

## 1. アーキテクチャ

```
md ⇄ Model                 … 同型。write(read(md)) = md がバイト単位で全域成立
        │ project          … 非可逆な簡約。落とし・整列はここだけ
        ▼
   ViewModel ─ render → map
```

- **Model は md と同型**。mmm の語彙（骨格・flesh・隙間・side・hidden）で構造化するが、
  余白・改行・綴りの揺れ・解釈できないものまで全部を持つ。
  解釈できないものは**不透明な葉**として運ぶ — 持たなければ同型が崩れる
- 忠実さは**特徴の列挙ではなくバイトの参照**で稼ぐ（かつて修飾子保存を却下した理由は
  「綴りの特徴を列挙して保存する」無限スケールだった。スパンで原文を指せばスケールしない）
- **ViewModel は Model の純関数**。map への矢印は ViewModel からの 1 本だけ。
  上流の層が map を直接触る抜け道を作らない。ゆえに md / AST / Model / ViewModel の
  どこを起点にしても同じ絵になる（可換図式は規律の帰結）
- AST（CommonMark のブロック木）は read の中間表現。AST も Model も md と 1:1 で、
  違いは母語だけ（AST = CommonMark の語彙、Model = mmm の語彙）

### 操作と反映

```
操作:   Model のフィールドを直接変異（木の語彙: move / add / delete / flipSide / fold / …）
write:  変えていないノードは原文バイトを再利用、変えた所だけ新しく綴る（保全印字 / recast 方式）
反映:   write(M') と旧 md の diff → エディタへ編集集合
打鍵:   テキストが変わる → read し直す
```

- 操作の道に**再パースも照合も無い**。id は変異する Model が運ぶので死なない
- 打鍵の道の id 継続は**推測ではなく写像**: 骨格スパンの先頭を編集の ChangeSet で
  写した位置で同定する（CodeMirror の `mapPos`）。スパンが本当に消えたら id は死ぬ —
  それが正しい答えで、「消えた id を指したままドロップすると無関係なノードが動く」への
  既存の見張り（`src/mindmap.ts:413`）がそのまま生き続ける
- 旧設計の「照合 = 唯一の推測地点」は廃止。推測地点はゼロ

### 前例

GitLab Content Editor（全文再生成で作り、「未接触ブロックは原文保持」に作り直した）、
recast（JS リファクタリングツールの保全印字）、rowan/CST（無損失構文木）。
学術的には双方向レンズ（BX）。一方向ツールが多いのは put が難所だと知る者の撤退。

## 2. なぜ作り直すのか（病理と処方）

22 件のバグは 1 つの病気の症状: **規則を構造でなく注意力で守る設計**。

| 病理 | 処方 |
|---|---|
| 1. 座標が前提を隠し持つ | スパンは Model が持ち、編集をまたぐ写像は ChangeSet に任せる。手計算オフセット禁止 |
| 2. 同じ規則が複数の場所に書かれる | バイトを書くのは write 1 人。操作は Model の語彙で意図を言うだけ |
| 3. 位置の記憶が書き替えを生き延びられない | 操作は Model を変異させる（テキスト位置の記憶を持たない）。打鍵側は写像で運ぶ |
| 4. 後始末アーキテクチャ | write は触った範囲を綺麗に綴る。ゴミを書いてから掃除する層を持たない |

なお「局所パッチ + 触った行は正規形」の前設計は、行単位の正規化が原因で
N32（マーカーの綴り替えが flesh の意味を変える）・N51（同位置ドロップで勝手に整形）を
生んでいた。同型 Model では変異が**フィールド単位**なので、この類は構造ごと消える。

### 役割の線引き

> **ts はテキストを 1 バイトも選ばない。mbt は 1 ピクセルも読まない。**

- mbt = 意味の層。read / Model / 操作 / write / project。ヘッドレスで網羅検証できる
- ts = 見せ方と入力。render・DOM・寸法実測・ポインタの解釈
- **バッファ・undo 履歴・選択・位置写像の所有者は CodeMirror**。write は編集集合を返す
  純関数で、ts はそれを 1 トランザクションに詰めるだけ（バイトを選ばない）。
  undo の通貨はテキスト差分 = CM の history そのもの。自作しない
  （旧 `core/edit.mbt` / `core/history.mbt` / tag 機械は引き継がない）

## 3. Model

具体型は実装で確定するが、骨は:

```
Model    … 木の列 + 木の外の領域（封筒 head・木間の隙間）も全部持つ
Node     { id, level, 骨格スパン, label, fold, contents, flesh, children }
隙間     … 兄弟サブツリーの間の空白・区切り行を所有するオブジェクト
不透明葉  … 解釈できない記述。バイトのまま運ぶ
```

- **id はセッション限り**（テキストに書かれない）。操作中は Model が運ぶ
- **level をそのまま持つ（疑似階層）** — `# root` 直下の `### head` は
  「空スロットを挟んだ 3 階層目」。深さ→レベルの写像を持たないので、
  「正規の深さ」と「親の実レベル」の衝突（N31: indent が無編集・無変化で黙って失敗）が
  起きない。階層飛びは正規化すべき崩れではなく**構造そのもの**
- **side は根の枝スロットの属性**。区切りの有無はその投影（§5）
- **fold（旧 hidden）はノードの属性 + 綴りは §6**。入れ子を許す
- Group という概念は無い（欲しかったのは左右の任意分岐だけ）

## 4. 法則

```
法則 1: write(read(md)) = md          … 全域・バイト同一。任意のコーパスでファズ可能
法則 2: read(write(M')) = M'          … 操作が変異させた M' に対して。ここが本丸
法則 3: map への矢印は project 1 本    … 規律。コードレビューで守る
法則 4: read の骨格判定 = @lezer/markdown のブロック木 + 方言表   … 突き合わせテスト
```

- 法則 1 は同型の定義そのもの。`canonical` 述語なしで全域検査できる（前設計からの最大の改善）
- **難しさの住所は法則 2**。操作が「書いて読み直すと違う意味になる Model」を作りうる
  （N33: リスト形の枝を見出し形の兄弟の前へ動かすと、書いた md が別の親子に読まれる /
  N41: setext の骨格は 2 行）。操作は変異後の Model が法則 2 を満たすことに責任を持ち、
  満たせない変異は**転形するか拒否する**（§7）。機械検査可能: 変異 → write → read → 比較
- 無操作 → 無編集は、フィールド無変異 + バイト再利用から自動で出る（N51 が構造的に消滅）
- 検証材料は既にある: `test/_helpers.ts` の `randomDoc` / `shape()` / `corpus()`

### 方言表（read が CommonMark と異なる点の公式定義。法則 4 の期待差分）

| 項目 | 裁定 |
|---|---|
| setext 見出し | CommonMark どおり読む。骨格は **2 行**（N41） |
| `#######`（7 個以上） | CommonMark では段落。**方言として見出しに読むか**は旗 3 |
| 封筒 head | 先頭の `---` 対は parse の**前段**で切り出す（CommonMark に frontmatter は無く、
  素直に読むと setext 化して幽霊ルートが生える — I-2。旧 core の `Head` を引き継ぐ） |
| `<!---` / `--->` | 許容して読む |
| 区切り | 隙間に**有るか無いか**だけ。本数・空行・銘柄は無関係 |
| blockquote・table・その他 HTML | 当面**不透明な葉**（解釈しない。バイトのまま運ぶ） |
| BOM | 封筒として parse 前に切り出す（N50） |

- **スパンの単位は UTF-16 コード単位**（CodeMirror・lezer と一致。N50）
- **EOL は原文の流儀を保存**して書く（CRLF 文書に LF を混ぜない）

## 5. 隙間と side

> **側の列が意味、区切りはその投影。** ただし投影の適用先は
> **同じ根の枝スロット間の隙間だけ**（N35 の教訓）。

- 隙間 = 兄弟サブツリーの間の、空白と区切り行しか無い**末尾区間**
  （C10 と C24 の定義矛盾は末尾定義で解消。I-4）
- 隙間は Model 上のオブジェクトで、自分の行を**所有**する。触った隙間の区切り再計算は
  「トグルに使う 1 本の有無」だけを合わせ、他の行は荷物として保全する
  （ユーザーの `---` を巻き添えで消さない — N35）
- 根の枝でない隙間・木と木の間・封筒直後は側の意味を**持たない**。再計算の対象外 = 常に保全
- **先頭の枝の前の隙間もトグルを持つ**（有れば左開始）。これで側の列 2^N が全部書け、
  N30（1 ビット不足 — 先頭の枝の flipSide が表現不能・「全部左」が書けない）が解ける。
  代償: `# タイトル` 直下の飾りの `---` が左開始と読まれる。方言表に載せて引き受ける（旗 4）

## 6. fold（旧 hidden）の綴り — 旗 1

コメント包み `<!--`〜`-->` は**中身が AST から消える**（HTML block type 2 は最初の `-->` まで
不透明。I-1）。二段パース + 座標の足し戻しが必要になり、処方 1 を hidden 経路が踏み抜く。
ネストも不可能（吸収しか無い）。`-->` の飲み込み事故（C21/N38）も構造的。**廃止する。**

乗り換え先の候補（**推奨は details**）:

| | `<details>` 包み | `<!-- #region -->` 対 |
|---|---|---|
| 中身 | 最後まで md（I-1 消滅） | 同左 |
| ネスト | 可能（タグ対応） | 可能（対の対応） |
| GitHub | **畳まれて見える**（意味まで一致） | 全部見える |
| 新しい語彙 | HTML タグ 1 種（コメントも既に HTML なので異物度は同等） | コメントのまま |

- 綴りは「**骨格行は外、details は本文と子だけを包む**」。ラベルは見出し行に残り、
  `<summary>` は使わない（ラベルの二重管理を作らない）
- 既存文書の `<!--` 包みは不透明な葉として読まれる（fold ではなくなる）。
  移行コマンドを用意するか、読みだけ両対応にするかは旗 2

## 7. 操作

操作は Model の変異。テキストの知識は write（綴り）と read（解釈）に閉じ、操作は持たない。

- **新しく書くものだけ**綴りを決める: 形は兄弟の真似（居なければ親から導出）、
  空行規律（区切り・見出しの継ぎ目に空行 1 本 / リストは兄弟の間隔）。
  空行規律は作法ではなく安全装置（段落直後の `---` は setext 化する — C24）
- **触っていないものの綴りは動かさない**（マーカーのパディング含む — N32）
- **転形と拒否**: 変異が法則 2 を破る場合、転形（リスト形 ⇄ 見出し形。flesh の一様
  字下げを伴う）で救えるなら転形し、救えないなら**拒否して理由を map に出す**。
  拒否リストは仕様の一部として 1 か所に列挙する（循環 move / タブ字下げ flesh の
  再インデント（N44）/ 往復不能なラベル（N42）/ 形の混在で置き場が無い並び（N33）/ …）
- ラベルは**生ソース文字列**（inline 解釈しない）。正規形で往復できない文字列
  （末尾 `#`・改行など）はエスケープか拒否（N42）
- content はブロックレベルのみ認定（inline 画像は flesh。N45）。
  含まれる散文は直前の content に接着して動かない（C22 / S11 は破れとして明記）

### 既知の爆風半径（保全と引き換えに引き受ける、意図とのズレのカタログ）

- tight リストへのブロック挿入は空行を伴い、リスト全体が loose 化する（C23。空行は必須 —
  無いと遅延継続でラベルが壊れる。I-6）
- 区切りの増減はリストを分割・併合し、tight/loose と序数が変わる（N39）
- リンク参照定義を含む部分木の fold/delete は、文書の遠くの参照を壊す（N40。
  距離に上限が無いので吸収せず、カタログで引き受ける）

## 8. map

- ViewModel = project(Model)。落とすもの（不透明な葉・封筒）、整えるもの（空スロットの表現）は
  project だけが決める。映らないテキストはノードに件数の気配を出す
  （受け皿は `src/map/layout.ts` の `buriedCount`）
- render は毎回全量導出。DOM 差分は速度の都合であって意味論ではない

## 9. 検証

- 法則 1: 実在コーパス + `randomDoc` で write∘read = id をバイト比較
- 法則 2: ランダム操作列で read∘write = id を `shape()` 比較（side/fold/contents を拡張）
- 法則 4: lezer との骨格突き合わせ（方言表が期待差分）
- 性能予算: 全再パースは実測で安い（`docs/audit/PERF.md` §6: 5,000 ノード 191KB が 19.1ms）。
  ただし操作の道は再パース不要になったので、律速は project + render + 境界。
  境界の JSON が 28.4ms/窓の実測があるので、Model の受け渡し形式は平坦化を検討（S7）

## 10. 未決の旗

1. **fold の綴り** — details 推奨 vs region 対（§6）
2. **旧 `<!--` 包みの移行** — 読み両対応か、一括変換コマンドか
3. **`#######` の扱い** — CommonMark どおり段落（不透明な葉）か、方言として見出しか。
   疑似階層により見出し 7 段以上の需要は減っている
4. **先頭隙間トグルの採用**（§5）と飾り `---` の衝突の告知方法
5. **拒否リストの確定** — §7 の列挙を実装前に固定する
6. **投影の仕様** — 空スロットの絵、映らないテキストの気配、整列
7. **format コマンド** — `write(M, canonical: true)` として糖衣分類表
   （スタイル糖衣 8 種 / 構造糖衣 3 種）を任意適用。critical path 外
8. **Group 廃止の移行告知** — `---` ×1 で節分けしていた既存文書は側が反転する（S9）

## 11. 移行と最初に作るもの

- バグ修正（PR #14）は main へ merge 済み — 完成までの現行製品を守る
- **最初に作る（最短の反証、S 批評の提案を継承）**: read/write の同型（法則 1 を
  コーパスで通す）→ move / flipSide / delete の 3 操作 + 法則 2 のファズ。
  PR #14 のバグの本丸（区切り算術）をこの 3 つが正面から踏む
- **殺す条件**: 法則 2 を満たすために操作側の場合分けが増え続けたら、この設計は死んでいる
- **最初に作らないもの**: CommonMark 完全準拠パーサ（既存スキャナを read の下敷きに据え置き、
  lezer は計測ハーネス）、format、UI の削除作業
- put ケースカタログ（[2026-08-29-put-cases.md](2026-08-29-put-cases.md)）は局所パッチ世界の
  記述を含むため要改訂。挙動の期待値（何が保全され、何が書かれるか）は大半がそのまま生きる
