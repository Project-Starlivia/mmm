# 文書モデル設計 — 意味保全と綴りの所有

2026-08-29。バグ 22 件修正（PR #14）から始まった core 再設計の記録。
「B 憲法（破棄あり）」→「レンズ + 局所パッチ」→「同型 Model（バイト保全）」→
「Mmmd/Mmmap 2 層」と振れた末、**綴りのバイト保全を手放し、意味の保全に絞る**ことで確定した。
経緯の詳細は [レビュー所見](2026-08-29-review-findings.md) と
[未処理の論点](2026-08-29-open-questions.md)（いずれも歴史的記録）。

## 0. 自己定義

> **mmm は意味を 1 ビットも失わない。綴りは mmm が所有する。**

- **守るもの: 構造・順序・中身。** 散文も謎の記法も消えない・並べ替えられない。
  「勝手にソートされたり削除される」は原理として起きない
- **手放すもの: 綴りのバイト保全。** マーカーの銘柄・パディング・空行の数・setext は
  serialize の正規形に置き換わる。Prettier がコードを所有するのと同じ姿勢 —
  整形は決定的・冪等で、意味は不変
- md の自由は**入力の自由**（どう書いても読める）。綴りの永続ではない
- 手書きの崩れた文書は、開いて最初の操作で全文が正規形になる（**初回スナップ**。
  文書につき 1 回きり、undo で戻る）

## 1. なぜ作り直すのか（病理と、経緯の要約）

22 件のバグの病名は「規則を構造でなく注意力で守る設計」。処方の変遷:

- バイト保全（局所パッチ・同型 Model）は 3 本のレビューで値札が確定した —
  マーカー綴りの副作用（N32）・タブ再インデント（N44）・形の混在（N33）・
  勝手整形（N51）は、すべて**バイト再利用が前提の病気**
- 綴りを手放した瞬間、これらは病気ごと消滅する。残った守るべき価値は
  「意味を消さない・並べ替えない」だけであり、それは正規形でも完全に守れる

## 2. 構造

```
mmmAst {                          // 意味と中身。綴りは持たない
  head:  String?                  // frontmatter 区間まるごと（中は解釈しない）
  roots: [Root]
}
Root { id, level, label, body, branches: [(side, Node)] }
Node { id, level, label, folded, body: [Block], children: [Node] }
Block = Content(Image | Code | Svg | Link)   // 認定ブロック（ブロックレベルのみ）
      | Opaque(text)                         // 散文・table・引用・HTML・謎。中身は逐語

Map構造木 = project(mmmAst)       // ghost 実体化・side/folded の絵・Opaque の気配化
```

- **id はセッション限り**。操作中は mmmAst が運ぶので、操作の道に照合は存在しない
- **level は疑似階層** — `# root` 直下の `### head` は空スロット（ghost）を挟んだ
  3 階層目。level は構造なので正規形でも保存される（階層飛びは消えない）
- **side は Root のスロットの属性**（場所の属性。深い階層には書けない）
- **folded** は意味のフラグ。綴りは details（§4）
- **Opaque の中身は逐語** — 例外は単独の水平線だけ（§4 のチャンネル分離）

## 3. 変換と法則

```
md ─ parse → mmmAst ─ project → Map構造木 ─ render → map
md ← serialize ┘

法則 1: parse(serialize(M)) = M     … モデルの完全往復。ファズの本丸
法則 2: serialize(parse(md)) は冪等  … 2 回目から不動。これがフォーマットの定義
法則 3: map への矢印は project 1 本  … 上流が map を直接触る抜け道を作らない
法則 4: parse の骨格判定 = @lezer/markdown のブロック木 + 方言表
```

- serialize は正規形をちょうど 1 つ吐く決定的関数。**mmm のフォーマッタそのもの**
- 検証: 実在コーパス + ランダム生成で法則 1・2 をバイト/構造比較。
  期待出力の手書きは方言表のテーブルだけ（アダプタは作らない。lezer は外部の審判）

## 4. 正規形（serialize の規則の要点）

| 項目 | 正規形 |
|---|---|
| 見出し | 常に ATX。level をそのまま `#` の数に（階層飛びも保存） |
| 深さ 7 以上 / リスト形 | `list_from` ダイヤル（文書単位。parse で検出し保存）で
  深さ N からリスト形。h6 が上限なので N ≤ 7 |
| 区切り | **`---` はトグル専用**。スロットの side の変わり目にちょうど 1 本。
  飾りの水平線（body 内の Opaque）は **`***` に書き替える**（チャンネル分離 —
  綴りを所有したことで初めて合法になった手。位置による誤読が構造的に消える） |
| 先頭トグル | 文書（木）の先頭スロットの前に `---` があれば左開始。
  これで側の列 2^N が全部書け、N30（1 ビット不足）が解ける |
| 畳み | `<details>` 〜 `</details>`。骨格行は外、本文と子だけ包む。
  `<summary>` には label を書く（GitHub で「▶ Details」ではなく「▶ ラベル」と映るため。
  serialize が毎回 label から生成する装飾であり、真実は見出し行 — 手で書き替えられても
  parse は無視し、次のスナップで揃い直す）。ネスト可。中身は最後まで md。
  旧 `<!--` 包みは対応しない（ユーザー 0 人の互換性は持たない） |
| コード | 常にフェンス（インデントコードは読めるが書かない）。
  中身に応じてフェンス長を伸ばす（エスケープは serialize の責務） |
| 空行 | 継ぎ目に 1 本の規律。安全装置（段落直後の `---` は setext 化する） |
| EOL | 原文の流儀を保存するダイヤル |
| frontmatter | head 逐語。parse の前段で封筒として切り出す |

方言表（read が CommonMark と異なる点）: setext は読む・`<!---`/`--->` 許容・
`#######` は段落（読まない）・blockquote/table/一般 HTML は Opaque。

## 5. 操作の流れ

```
1. UI (ts)   ポインタ解釈 → Map構造木の言葉で命令を発話
2. 翻訳      id 素通し / index 読み替え（Opaque を飛ばした分）/ ghost の裁定
3. core      mmmAst を意味で変異（reshape / reject の判定込み）
4. serialize 正規形の md 全文 → 旧 md と diff → editSets をペインへ
5. project → render で map 更新
```

- **Map構造木は絶対に変異させない**（React と同じ一方向ループ。投影の逆写像を作らない）
- **再パースなし**（法則 1 が保証。debug で assert は自由）、**照合なし**（id は mmmAst が運ぶ）
- diff は「間違えても壊れない」部品（正しさは serialize が保証。最悪カーソルが跳ぶ）
- 読みの道（打鍵・rename・カード編集・貼り付け）だけ逆向き: テキスト → parse → 新 mmmAst。
  **id の継ぎ目は世界でここ 1 か所**、被害は選択ズレ止まり

### 入力の裁定 — 二本の道

> **構造を変える者は文字列に触れず、文字列に触れる者は必ず解釈を受ける。**

- **木の道**: move / indent / outdent / delete / flipSide / fold — 木の語彙で mmmAst を
  直接変異。parse を通らず、id は mmmAst が運ぶ
- **読みの道**: 打鍵・rename・カード編集・貼り付け — 文字列を運ぶものは例外なく
  テキストに書かれて parse を通る。**一言語原則**: カード入力も md を話す。
  エスケープ・trim・改行拒否といったラベル専用の裁定は存在せず、md 文法が唯一の裁定者。
  `1. x` と打てば入れ子が生え、`# foo` と打てば見出しになる — 文法に逆らわないことが正しい。
  md ペインで打っても カードで打っても、同じ入力は同じ結果になる
- 構造系の拒否: 子孫への move（循環）/ root より浅い outdent。同位置への move は許可・編集ゼロ
- **ghost**（階層飛びの空位）は「穴」— 操作は**埋める**か**閉じる**の 2 択:
  add / drop / rename は**実体化**（空ノードを生やす・打った文字で空位を埋める）、
  **delete は段差詰め**（その空位の下の全住人が 1 段浅くなる。ghost 2 段なら 1 回で 1 段）、
  fold は実体化してから、move は掴めない。
  root の上に ghost は無い（木の頂点は level がいくつでも root — Root が level を持つ理由）。
  id は Map構造木だけの合成 id で、翻訳層が「実体化 + 本命の操作」へ展開する

### 反映の機構（生成は全体、適用は差分）

```
1. serialize(mmmAst) で全文の正規形を生成（正しさは常に全体で持つ。境界問題が存在しない）
2. 旧全文との純粋な文字列 diff:
   同一なら編集ゼロ → 共通接頭辞・接尾辞を刈る（行境界に揃え、サロゲートを割らない）
   → 中央部を行単位 Myers で複数ハンクに分解
3. editSets = [{from, to, insert}]（旧文書上の UTF-16 オフセット）だけが境界を渡る
4. ts は 1 個の CodeMirror トランザクションに詰めて dispatch
   — 適用・カーソル写像（mapPos）・履歴記録はすべて CM の仕事
5. 自己検査: apply(旧全文, editSets) == 新全文 を dispatch 前に確認。
   不一致なら全文置換 1 ハンクへフォールバック（正しさは保たれ、カーソルだけ跳ぶ）
```

初回スナップ以後の文書は正規形なので、diff は自然に操作箇所へ収束する（法則 2 の帰結）。

**確保済みの席 — 検証つきすげ替え**: 反映を保守的にする差し替え戦略。
意味の変わっていないノードの旧原文範囲をスパンで再利用して R を組み、
`parse(R) == M'` を検証、不一致なら canonical へ段階フォールバック。
触っていない範囲の綴り（崩れた記法・空行の数）が操作後も生き残る。
正しさは検証が持つので**ドロップインで後付けできる** — 憲法の変更ではなく反映戦略の交換。
ただしどの戦略でも、**操作された継ぎ目の綴りは必ず正規化される**
（空行の本数はモデルに存在しない情報なので、復元の材料が無い。
継ぎ目の空白を意味に昇格させる案は検討の末に却下 — 誰も求めていない）。

## 6. 消えた病気と、残る課題

**消滅**（バイト保全の放棄による）: N32 マーカー綴りの副作用 / N44 タブ再インデント /
N51 勝手整形（正規形の再 serialize は無変化 = 法則 2）/ N33 形の混在（正規形に混在が無い）/
隙間の定義問題・触った隙間の境界・blast radius カタログの大半 / Mmmd 層と Gap 型。

**残存**:

- **N42 ラベルの往復** — 問題ごと消滅（§5 入力の裁定）。一言語原則により
  「ラベル」という特別な文字列カテゴリが無くなった。文字列は常に md として解釈される
- **N40 距離問題** — 参照定義・脚注を含む部分木の delete は遠くの参照を文字列化する
  （消失はしない。ユーザーの削除の帰結として引き受ける）
- **reshape / reject** — 変異が法則 1 を破る場合の救済と拒否。リストを仕様に列挙する
- **アンカー注意** — GitHub は見出しから anchor を生成するので rename は外部リンクを壊す
  （md の宿命。docs に注意書き）

## 7. 技術スタックと責務

| 層 | 持ち物 | 責務 |
|---|---|---|
| **MoonBit core** | mmmAst / parse / serialize / 操作 / diff | 意味の全て。純関数で、editSets（値）だけを返す。ヘッドレスで網羅検証 |
| **CodeMirror** (ts) | バッファ・undo 履歴・選択・位置写像 | `ChangeSet` / `history` / `mapPos` を使う。自作しない。
  旧 `core/edit.mbt`・`core/history.mbt`・tag 機械は引き継がない |
| **map** (ts) | render・寸法実測・ポインタ解釈 | Map構造木の毎回全量導出。DOM 差分は速度の都合 |
| **@lezer/markdown** | — | パイプラインの段ではなく法則 4 の外部審判（CM が既に毎打鍵パースしている） |

- 「ts はバイトを選ばない」— editSets を作るのは mbt、運ぶのが ts
- undo の通貨はテキスト差分 = CM の history そのもの
- 全再パース性能は実測済みで安い（`docs/audit/PERF.md`: 5,000 ノード 191KB が 19.1ms）
