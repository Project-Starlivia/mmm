# 文書モデル設計 — core の作り直し

2026-08-29。D&D・コメント・グルーピング周りのバグ 22 件を修正したセッション（PR #14）の
後半で、「点の修正では病気が治らない」という結論から始めた再設計の記録。
実装はこの文書と同じブランチ（feat/doc-model）で進める。

## 0. なぜ作り直すのか

22 件のバグは個々の不具合ではなく、1 つの病気の症状だった。診断:

1. **座標が前提を隠し持つ** — 全コマンドが `nd.from`/`nd.to` から挿入点を計算するが、
   オフセットは「自分がコメント領域の内側か」を知らない。前提が破れても使用箇所では検出できない
2. **同じ規則が複数の場所に書かれ、片方だけ直されてきた** — 「畳んだ落とし先は先に開く」は
   add にあって move に無い、の型が 6 件以上
3. **位置の記憶がブロック書き替えを生き延びられない** — 掃除の目印・editSets・id 写像は
   「編集前の位置を後へ写す」機構だが、移動（削除+挿入）で写像が切れる
4. **後始末アーキテクチャ** — コマンドがゴミ（死んだ `---`、空マーカー、空行の山）を合法的に
   書けてしまい、掃除係が後から「ゴミとユーザーの記述の区別」という難問を背負う

つまり「規則を構造でなく注意力で守る設計」が病名。修正はすべて点であり、
明日 5 個目の入口が生えたら同じ穴が開く。

## 1. 役割の線引き

**core = 意味の層。ts = 見せ方の層。** 判定基準は 2 つの禁止に畳む:

> **ts はテキストを 1 バイトも書かない。mbt は 1 ピクセルも読まない。**

- ts が書かない ⇒ 意味と綴りの正しさが全部 mbt に集まり、ヘッドレスで網羅検証できる
- mbt が読まない ⇒ core は UI を作り替えても生き残る（Tauri→Web で実証済み）
- 境界を渡るのは値（コマンド引数と snapshot）だけ。会話（往復）はしない
- **mbt は持つが、解釈しない**（label / contents / head は不透明な積み荷）。
  **ts は解釈するが、持たない**（カード種別・サイズ・見え方は導出で、真実を持たない）

## 2. 文書モデル（正規構造）

md という記法から独立した、mindmap そのものの構造。AST ではなく文書モデルと呼ぶ
（構文の木ではなく、記法に先立つ構造だから）。

```
Doc     { head, trees: Root の列 }

Node    { id, label, contents, hidden }     … 共通の実体。定義は 1 回だけ
Root    { node: Node, branches: (side, Branch) の列 }
Branch  { node: Node, children: Branch の列 }
Content { id, text }
```

不変条件は 2 つだけ:

1. **id は文書内で一意**（Root / Branch / Content 共通の採番器。テキストには保存されない、セッション限り）
2. **hidden の入れ子は吸収** — hide するとき子孫の hidden フラグは消す。
   HTML コメントは入れ子にできない（最初の `-->` で必ず閉じる）ので、md に保存できない状態を
   モデルに持たない

聖域（モデルが中を解釈しないもの）: **head / label / Content.text**。
コード・散文・崩し記法はここに置かれた限り 1 バイトも触られない。

### 形の決定と理由

- **depth を持たない** — 深さは木の中の位置そのもの。持つと「位置と番号」という真実が 2 つになる。
  挿し直せば全員の深さが自動的に新しい位置のものになり、「`#` を数え直す」仕事が消える
- **parent ポインタを持たない** — 親は children で子を持つ片方向。双方向は「相互整合」という
  不変条件を 1 個増やすだけ
- **共通化は型の括り出し（合成）で、表は作らない** — labels/hidden/contents を id→表 で外に出す案は
  検討の末に却下。表は「宙ぶらりんの id・孤児プロップ」を表現できてしまい、参照整合という
  守るべき不変条件を自前で発明することになる。Node 型を 1 回定義して Root/Branch に埋め込めば、
  label の欠けたノードは構文的に書けない
- **side は Root の列のスロットに付く** — 枝という物の属性ではなく、ルート直下という場所の属性。
  Branch は自分の側を知らないので、深い階層に側が付く状態が書けない。外部表にもしない（同上）
- **Group という概念は廃止** — 同じ側の中の節分け（継ぎ目の線・束の壁・×1 の純分割）は
  「×2 に意味を与えたら ×1 にも要る」という記法の対称性から逆算された機能で、欲しかったのは
  一貫して左右の任意分岐だけだった。機能で記法を選ぶべきで、逆ではない
- **hidden はフラグ、マーカーは綴り** — `<!--`/`-->` はモデルに存在せず、印字機だけが書く。
  未閉じマーカーが構文的に書けなくなる

なお「2 次元の配置を 1 次元のテキストに書く」という根本の苦しさは消えていない。
この設計はそれを Root の列という 1 か所に封じ込めただけ（治療ではなく封じ込め）。

## 3. 読み書きの法則

```
印字 print : Doc → md    … 全域・決定的。正規形をちょうど 1 つ出す
読み parse : md → Doc    … 全域・多対一。エラー無く、1 バイトも捨てない

法則 1: parse(print(doc)) = doc          … 意味の往復。ファズで機械検証できる唯一の契約
法則 2: print(parse(md)) = md の正規形    … 冪等。2 回目からは不動
```

- 読みが多対一である以上、**綴りが保存されないのは方針ではなく数学的必然**。
  保存されるのは聖域に乗ったものだけ
- **順序は意味**（読み順）。印字機の権限は綴りだけで、並べ替えは正規化の越権。
  `a ---(左)b ---(右)c` を `a c --- b` に並べ替えることはしない — それは別の文書
- 構造の語彙は 5 つ（`#` 見出し・`-` リスト項目・`---` 区切り・`<!--`/`-->`・frontmatter）。
  どれとしても読めないもの・読む位置に無いものは、定義により content（逐語保存）。
  「解釈できない記述」は存在しない

### 方言表（CommonMark との差分の公式定義）

| 項目 | 裁定 |
|---|---|
| setext 見出し（`===`/`---` 下線） | **読む**（CommonMark 準拠に変更）。印字は常に ATX。従来の「本文直後の `---` ガード」は不要になる |
| `#######`（7 個以上） | 見出しとして読む（意図した方言。CommonMark では段落） |
| `<!---` / `--->` の余分なダッシュ | 許容して読む。印字は `<!--`/`-->` |
| 区切り `---` | **隙間の有無だけを読む**。本数・空行・銘柄（`***` `___`）は無関係。×1/×2 の区別は廃止 |
| 綴りの文書単位ダイヤル | `list_from`（書き方モード）と EOL のみ。個別箇所の綴り保存は原理的に不可として切り捨て |

CommonMark 実物（`@lezer/markdown`、node_modules に既在）との行分類突き合わせテストを作り、
この表を実行可能な仕様にする（宿題）。

### 左右分岐の記法

- 読み: 枝と枝のあいだの「構造の隙間」（空白と区切り線しか無い区間）に区切りが**有れば**側をトグル。
  先頭は右、最初の枝の前に区切りがあれば左から始まる
- 印字: 側の変わり目に**ちょうど 1 本**。どんな側の列（R,L,R,L も R,R,L,L も）も 1:1 に書ける
- 堆積が構造的に不可能: 何本積もっても読みは 1 境界、次の印字で 1 本

## 4. 命令の 2 レーン

| レーン | 命令 | 性質 |
|---|---|---|
| **モデルの道** | move / interpose / indent / outdent / add(枝) / delete / flipSide / toggleHidden / moveContent | payload の文字列に触らない ⇒ 記法の注入が原理的に不可能 |
| **読みの道** | 打鍵・rename・カード編集・addContent・断片貼り付け | 文字列を運ぶ ⇒ 必ずパーサを通る |

「構造を変える者は文字列に触れず、文字列に触れる者は必ず解釈を受ける」。
カードに `# foo` と打てばノードが生えるのは正の挙動（md の文法がそう言っている。
パーサに文法へ逆らう自由は無く、逆らわないことが正しい）。

ルート直下へのドロップは全部 **(挿入位置, 側)** の 1 規則に潰れる。
位置はポインタの y、側はポインタの x。区切りの出現・消滅・移動はすべて印字の帰結で、
コマンド側に場合分けは無い。flipSide はスロットの side を書き換えるだけ。

## 5. 反映（md ペインへ）

```
開く:        T を読む → Doc。書き込みしない（開いただけで dirty にならない）
打鍵:        T が変わる → Doc を作り直す。印字しない
構造コマンド: Doc を操作 → T' = reflect(T, Doc') → diff(T, T') を editSets としてペインへ
undo:        T をバイト単位で戻す（崩し字も含め完全復元）
```

- **reflect は 1 部品として切る**。初版は `reflect = print(Doc')`（全文印字）。
  変わっていない範囲は diff がゼロに落とすので、エディタへの適用は最小差分になる
- 差分計算は「間違えても壊れない」部品（最悪カーソルが跳ぶだけ。テキストの正しさは印字が保証済み）。
  旧 editSets（間違えたら文書が壊れる・検証手段なし）と責任の重さが逆転する
- **初回スナップ**: 手書きの崩れた文書は、最初の構造コマンドで全体が正規形になる。
  冪等なので文書につき最大 1 回、以後は静か。undo で完全に戻る
- これはトリレンマ（ゴミを作らない / バイトを尊重 / 機構が単純 — 2 つしか選べない）の
  「正規化」側の選択。**スプライス**（触った範囲だけ印字して元テキストに継ぎ込む =
  外科手術のまともな版）は同じ座席への後付け最適化として設計上の席だけ確保。
  trivia 方式（綴りを別データで保存）はスプライスに支配されるので却下
- 全文を明示的に正規化する **Tidy** 相当の操作を別途置ける（reformat が前例）

## 6. map への反映

- **毎回全量導出**。差分は DOM への適用だけ（速度の都合であって意味論ではない）。
  22 件のバグの間、map が一度も嘘をつかなかったのはこの性質による
- map は文書の**非可逆な投影**: 側をまたぐ読み順は絵に出ない（R,L,R,L と R,R,L,L は同じ絵）。
  読み順は md ペインが受け持つ — 二画面の役割分担として引き受ける

## 7. 未決の旗

1. **列内並べ替え → 読み順の割り付け** — map の右列で c を a の上へ動かしたとき、
   反対側のスロットとの相対位置をどう決めるか（候補: 同じ側の兄弟との相対だけ動かし、
   交互関係は最小変更）。コマンド章で 1 規則
2. **打鍵経路の id 照合** — id はテキストに書かれないので、再パース時の旧 Doc との対応付けは
   推測のまま（旧世界の根因 3 がこの 1 継ぎ目に幽閉されている）。被害は選択の取り違えで済み、
   文書は壊れないが、設計は要る
3. **undo の統一** — 打鍵の undo（テキスト差分）とコマンドの undo が 1 本のスタックに混ざる形
4. **CommonMark 突き合わせテスト** — 方言表の実行可能化。旧 core に対して先に作ってもよい
5. **スプライス** — reflect の差し替え。初版で初回スナップが痛いと体感してから
6. **静止状態の真実** — 上記ライフサイクルは事実上「静止時はテキスト、コマンド中はモデル」。
   id 照合（旗 2）の設計次第で再訪
