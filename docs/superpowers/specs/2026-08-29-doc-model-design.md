# 文書モデル設計 — レンズ憲法

2026-08-29。バグ 22 件修正（PR #14）から始まった core 再設計の記録。
「md エディタとしての作り直し」→「B 憲法（モデルが真実・md は鏡）」を経て、
**md の自由を殺す設計はすべて破棄**し、レンズ憲法で確定した。実装はこのブランチで進める。

## 0. 自己定義

> **mmm は md を所有しない。自由な md の上に住むマインドマップのレンズである。**

md の存在理由は可読性ではなく**自由**（読むだけなら画像で足りる）。
正規形しか許さない md は md の皮を被った独自フォーマットであり、それなら JSON でよい。
ゆえに:

- **真実はテキスト**。散文・崩し記法・mmm が解釈できないものも、テキストにある限り消えない
- map は解釈できるものだけを映す**投影**。映らないものは絵に出ないだけで、文書に居続ける
- map からの操作は**テキストへの局所パッチ**。結果の意味は再パースが定義する
  — 崩れた綴りの近くで意図とずれたら、それは md がそう言っている

### 破棄した B 憲法（なぜ死んだか）

「真実はモデル、write が全文生成、扱えないものは破棄」は機構が最も単純だが、
**勝手にソートされたり消されたりするツールに意味はない**。保全と所有は両立せず、保全を取った。

トリレンマの決着: **無傷の保全 ○ / 意図どおりの操作 △（丸める）/ 単純な機構 ×（払う）**。

## 1. なぜ作り直すのか（病理の要約）

22 件のバグは 1 つの病気の症状: **規則を構造でなく注意力で守る設計**。

1. 座標が前提を隠し持つ（手計算オフセットは自分の文脈を知らない）
2. 同じ規則が複数の場所に書かれ、片方だけ直されてきた
3. 位置の記憶（掃除の目印・id 写像）がブロック書き替えを生き延びられない
4. 後始末アーキテクチャ — ゴミを合法的に書けて、掃除係が難問を背負う

処方は地形（テキスト編集）を変えることではなく歩き方を変えること:

1. 手計算オフセット禁止 → **本物の CommonMark AST のスパン**だけを使う
2. 規則の分散禁止 → **バイトを書くのは put 1 人**。コマンドは木の語彙で意図を言うだけ
3. 位置の記憶禁止 → パッチ後は**必ず全再パース**。古い座標が構造的に即死する
4. 後始末禁止 → put は触った範囲を綺麗に書く。ゴミを書いてから掃除する層を持たない

## 2. アーキテクチャ

```
put   : (md, 操作) → 編集集合   … 唯一の書き手
get   : md → Model             … 毎回全量導出。Model は使い捨ての読み取り結果
照合  : (旧Model, 新Model) → id/選択の引き継ぎ … 唯一の推測地点。被害は選択ズレ止まり

操作 → put(md) → 再パース → get → 照合 → map 再描画
```

- **Model には put しない**。model への差分更新を作った瞬間「md と model の整合」という
  不変条件を自前で守る羽目になる。作らなければ存在しない
- get の内訳は parse（純 CommonMark、span 付き）∘ interpret（mmm の解釈）。
  表記ゆれ対応は**読み側だけ**が背負う
- 曖昧さは照合の小部屋に全部閉じ込める。put でも get でもない第 3 の仕事として隔離

### 役割の線引き

> **ts はテキストを 1 バイトも書かない。mbt は 1 ピクセルも読まない。**

mbt = 意味の層（parse・interpret・put・照合）。ts = 見せ方と入力（layout・DOM・寸法実測）。
境界を渡るのは値だけ。ただし put の実装者は未決の旗 1 参照（CodeMirror 案はこの禁止と衝突する）。

## 3. put の方針

- **書く語彙は常に正規形**。多対一の parse に逆関数は無いので、
  表記ゆれを維持して書き戻す逆変換は誰にも作れないし、作らない
- 「差分」とは綴り維持の器用さではなく**書く範囲の狭さ**:
  触った骨格行（見出し・リストマーカー・区切り・コメントマーカー）は正規綴りで書き直し、
  触っていないバイトは 1 バイトも動かさない
- **爆風半径**（md は文脈依存なので、編集が範囲外のバイトの意味を変えうる）:
  操作対象の骨格 + 近傍の隙間を正規形に書き直す局所スナップで吸収し、
  残った縁は「再パースが真実」で受ける

## 4. Model（get の出力の形）

```
Model   { trees: Root の列 }
Root    { node: Node, branches: (side, Branch) の列 }
Branch  { node: Node, children: Branch の列 }
Node    { id, label, hidden, contents: Content の列 }
Content = Link{url} | Image{path} | Code{lang, body} | Svg{body} …
```

- id は文書内で一意・セッション限り（テキストに書かれない）。depth・parent は持たない
- side は Root のスロットに付く。Group という概念は無い（欲しかったのは左右分岐だけ）
- hidden の入れ子は吸収（HTML コメントは入れ子にできない）
- 区切り `---` は枝間の隙間に**有るか無いか**。本数・銘柄は無関係、×1/×2 の区別は廃止
- setext 見出しは parse が CommonMark どおり解決（区切り判定より前段）

## 5. 法則と検証

```
法則 1: 無操作 → 編集ゼロ                 … 全域。任意の md でファズ可能
法則 2: get(put(md, op)) = op_model(get(md)) … 可換性。正規形の文書で全域成立。
        崩れた文書では破れうる — 破れ方を仕様に書き、再パースが真実で受ける
法則 3: パッチ範囲外のバイトは不変          … 編集集合しか出さないので構造上自動
```

- **op_model はテスト専用の実行可能仕様**（参照実装との突き合わせ）。
  「move = 木から抜いて挿す」数行で、読む＝妥当性確認になる大きさに保つ。
  製品コードに入れない — 入れると model 同期の近道に誘惑され、閉じた曖昧さが裏口から戻る
- 検証と妥当性の溝（op_model が人間の期待に合うかは証明不能）は消せない。
  証明できない核を数行に縮めることだけが処方
- property-based testing: ランダム md × ランダム操作列 → 法則だけ検査。期待出力を人間が書かない
- CommonMark 実物（`@lezer/markdown`）との parse 突き合わせテスト

## 6. undo・map

- **undo の通貨はテキスト差分**（真実がテキストなので）。崩し字も含めバイト正確に戻る
- map は Model の毎回全量導出。DOM 差分は速度の都合であって意味論ではない
- md ペインは真実の表示そのもの（鏡ではない）

## 7. 先例（この道が実在する証拠）

| 方式 | 実在例 | 対応 |
|---|---|---|
| 投影エディタ（モデル真実） | JetBrains MPS | = 破棄した B |
| 読み取り専用レンズ | markmap, Obsidian/VSCode の map 系拡張 | put を捨てた撤退形 |
| 破壊的入出力 | XMind, Pandoc | 開いたら別文書 |
| **保全印字 / 局所パッチ** | **GitLab Content Editor**（全文再生成で作り→「未接触ブロックは原文保持」に作り直し）, mdx-formatter | **本命。同じ道の実証**|
| 単一バッファ+装飾 | Obsidian Live Preview (CodeMirror 6) | view=バッファで put 問題自体を消す |

学術的には双方向レンズ（BX）。法則 1 は `put(get(s), s) = s` と同型。
一方向ツールが多いのは怠慢ではなく、put が難所だと知る者の撤退。

## 8. 未決の旗

1. **put の実装者** — mbt に自作するか、CodeMirror のトランザクション機構に乗るか
   （後者はスパン・差分・undo が基盤から貰えるが「ts は書かない」の禁止と衝突）
2. **映らないテキストの見せ方** — 完全に不可視か、ノードに気配（ぶら下がり）を出すか
3. **解釈範囲の確定** — 見出し・リスト・区切り・コメントマーカー + どこまでを絵にするか
4. **id 照合の設計** — 旧 Model との突き合わせ規則
5. **局所スナップの範囲定義** — 「操作対象の骨格 + 近傍の隙間」の正確な境界
6. **法則 2 の破れ方の仕様化** — 崩れた文書での挙動カタログ
7. **糖衣分類表** — スタイル糖衣 8 種（一般 lint/format で正規化可能）と構造糖衣 3 種
   （階層飛び・見出し⇄リスト形・tight list）。任意の Tidy コマンドの素材
