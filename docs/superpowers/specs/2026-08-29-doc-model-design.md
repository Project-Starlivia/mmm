# 文書モデル設計 — core の作り直し（B 憲法）

2026-08-29。D&D・コメント・グルーピング周りのバグ 22 件を修正したセッション（PR #14）の
後半で始めた再設計の記録。議論の末、当初の「md エディタとしての作り直し」案を破棄し、
**mmm の自己定義そのものを転回**して確定した。実装はこのブランチ（feat/doc-model）で進める。

## 0. 自己定義の転回

> **mmm は md エディタではない。md を直列化形式に使うマインドマップツールである。**

- **真実はモデル（Doc）**。静止時も作業中も。テキストはその投影にすぎない
- **mmm が扱うものだけが文書である**。map に写らない幽霊データ（プレーンな散文、
  帰属しない切れ端、対にならないマーカー）は、モデルに登録されず、以後一切関与しない
  — 保存もされない。両ペインは常に完全一致する
- 外部の md を開くことは**破壊的インポート**である。mmm が扱えない内容は取り込まれず消える
- 散文が欲しくなったら、`Text` という Content 型を足して**カードとして map に昇格**させる。
  「扱わないものは持たない」の原則のまま復活できる（幽霊としての復活はさせない）

### 正規化の原則

> **正規化は変換ではなく、構成による性質である。** モデルは崩れた状態を表現する
> フィールドを持たないから、印字は正規形しか出力できない。
> もし綴りや落とされるものを残したくなったら、それは**核を汚さず、別の層**
> （差分修正・修飾子としての別保管/補完）で行う。核に例外を持ち込まない。

## 1. なぜ作り直すのか（病理の要約）

22 件のバグは 1 つの病気の症状だった: **規則を構造でなく注意力で守る設計**。

1. 座標が前提を隠し持つ（オフセットは自分がコメント領域内かを知らない）
2. 同じ規則が複数の場所に書かれ、片方だけ直されてきた
3. 位置の記憶（掃除の目印・id 写像）がブロック書き替えを生き延びられない
4. 後始末アーキテクチャ — ゴミを合法的に書けて、掃除係が後から難問を背負う

## 2. 役割の線引き

> **ts はテキストを 1 バイトも書かない。mbt は 1 ピクセルも読まない。**

- mbt = 意味の層。モデル・parse・print・履歴。ヘッドレスで網羅検証できる
- ts = 見せ方と入力。layout・DOM・寸法実測（canvas）・ポインタの解釈。真実を持たない
- 境界を渡るのは値だけ: 命令（id と引数）/ 編集イベント / snapshot + editSets

## 3. 文書モデル（真実）

```
Doc     { trees: Root の列 }

Node    { id, label, hidden, contents: Content の列 }
Root    { node: Node, branches: (side, Branch) の列 }
Branch  { node: Node, children: Branch の列 }

Content = Link{url} | Image{path} | Code{lang, body} | Svg{body}
          … 将来 Text 等を追加可能。型に合わないものはモデルに存在しない
```

不変条件は 2 つ:
1. **id は文書内で一意**（テキストには保存されない。セッション限り）
2. **hidden の入れ子は吸収**（HTML コメントは入れ子にできないため。
   hide 時に子孫のフラグを消す）

### 形の決定と理由

- **depth を持たない** — 深さは木の中の位置。挿し直せば全員の深さが自動で変わる
- **parent ポインタを持たない** — 所有は children の片方向のみ
- **共通部分は型の括り出し（Node を Root/Branch に埋め込む）** — id→表 の外部化は
  「宙ぶらりんの id」を表現できてしまうため却下。label の欠けたノードは構文的に書けない
- **side は Root の列のスロットに付く** — 場所の属性であって物の属性ではない。
  Branch は自分の側を知らず、深い階層に側が付く状態は書けない
- **Group という概念は無い** — 欲しかった機能は左右の任意分岐だけ。
  同じ側の節分け（×1 区切り・継ぎ目の線・束の壁）は機能ごと廃止
- **Content は型付き** — 「mmm が扱うものだけ登録する」以上、何が扱われるかは
  build が判定する。カードの語彙は見せ方ではなくモデルの語彙
- **hidden はフラグ、マーカーは綴り** — `<!--`/`-->` は印字機だけが書く。
  未閉じマーカーは構文的に書けない

## 4. 読み書きの法則

```
print : Doc → md     … 全域・決定的。正規形をちょうど 1 つ出す。これが書式の定義
parse : md → Doc     … 全域・選別的。扱える構造だけを拾い、残りは落とす

法則 1: parse(print(doc)) = doc    … mmm 産の文書は完全に往復する（ファズの本丸）
法則 2: print(parse(md))          … 外部 md の「mmm への射影」。インポートの定義
```

- **順序は意味**。印字機の権限は綴りだけで、並べ替えはしない
  （側の列 R,L,R は読み順の情報。R,R,L への並べ替えは別の文書）
- **エスケープは print の責務** — label に `#` があっても、Code の body に
  ``` があっても、印字が衝突しない綴り（より長いフェンス等）を選ぶ。
  これにより文字列を運ぶ操作から注入の概念が消える

### 変換の連鎖

```
原文 ─ scan → 行の列 ─ build → Doc ─ print → 正規md ─ diff → md ペイン
（字句: 行の形+span）  （選別+解釈）        └ layout/cards → map ペイン
```

| 工程 | 仕事 | 知っているもの |
|---|---|---|
| **scan** | 行の**形**（見出し形・リスト形・区切り形・マーカー形・フェンス開閉・空行・他） | 行単体 + フェンス内外。文脈なし。CommonMark 突き合わせの対象 |
| **build** | **選別と解釈** — 役割の確定（隙間か中身か）、Content の型判定と登録、木・side・hidden の組み立て、**扱えないものの破棄** | 文脈のすべて。曖昧さの裁定者 |
| **print** | 深さ→接頭辞（list_from 参照）/ side の変わり目→`---` 1 本 / hidden→マーカー対 / Content→各型の正規綴り / エスケープ | 正規形の規則のみ |
| **cards/layout** (ts) | 型付き Content の**描画**（サムネ・ハイライト・寸法） | 見せ方のみ。分類はもうしない |

### 方言表（scan/build が CommonMark と異なる点の公式定義）

| 項目 | 裁定 |
|---|---|
| setext 見出し（`===`/`---` 下線） | 読む（CommonMark 準拠）。印字は常に ATX |
| `#######`（7 個以上） | 見出しとして読む（意図した方言） |
| `<!---` / `--->` | 許容して読む。印字は `<!--`/`-->` |
| 区切り | 枝間の隙間に**有るか無いか**だけ。本数・空行・銘柄は無関係。×1/×2 の区別は廃止 |
| 綴りの文書単位ダイヤル | `list_from`（書き方モード）と EOL のみ |
| **扱えないもの** | 型に合わない中身・帰属しない切れ端・不対マーカー → **破棄**（インポートで消える） |

CommonMark 実物（`@lezer/markdown`）との行分類突き合わせテストで、この表を実行可能にする。

### 左右分岐の記法

- 読み: 枝間の隙間に区切りが有れば側をトグル。先頭は右、先頭の枝の前に区切りがあれば左
- 印字: 側の変わり目にちょうど 1 本。どんな側の列も 1:1 に書ける。堆積は表現不能

## 5. 命令のレーン

| レーン | 命令 | 性質 |
|---|---|---|
| **モデルの道** | move / interpose / indent / outdent / add / delete / flipSide / toggleHidden / **setLabel / setContent / addContent / moveContent** | モデルを直接操作。文字列フィールドへの代入は print のエスケープが守るので注入不能 |
| **読みの道** | **md ペインの打鍵だけ** | parse を通る。★id 照合（世界で唯一の推測地点）はここだけ |

B 転回により rename・カード編集は素直なモデル操作に戻った。
ルート直下へのドロップは **(挿入位置, 側)** の 1 規則。区切りの増減は印字の帰結。

## 6. 反映

```
開く:          parse（破壊的インポート）→ Doc
打鍵:          ペインのバッファ → parse → Doc 更新（★id 照合）
モデル命令:     Doc' → print 全文 → diff → ペインへ editSets
undo/redo:     モデル差分を戻す/進める → print → 同上
保存:          print(Doc) をファイルへ
```

- md ペインは **print(Doc) の鏡**。打鍵中はバッファを保ち（カーソル下で文字を動かさない）、
  モデル命令の反映時に正規形へ同期する
- diff は「間違えても壊れない」部品（正しさは print が保証。最悪カーソルが跳ぶだけ）
- スプライス・trivia・初回スナップの葛藤は、**問題ごと消滅**（保存すべき綴りが存在しない）

## 7. undo（モデル通貨）

真実がモデルなので、**履歴の通貨もモデル差分**（テキスト通貨から反転確定）。

- エントリ = モデルの可逆な変化（木の操作の逆 / フィールドの旧値）+ tag
- id は木が運ぶので、照合表が不要。undo/redo で id が自明に生存
- 打鍵は「parse 結果のモデル差分」として積む（tag で併合）
- no-op はモデル不変で検出（何も積まない）
- 検証: 「任意の列を全部 undo すると初期 Doc に一致」のファズ

## 8. map

- 毎回全量導出。DOM 差分は速度の都合であって意味論ではない
- 寸法実測（canvas）は ts のみ
- 側をまたぐ読み順は絵に出ない（md ペインが受け持つ）

## 9. 未決の旗

1. **frontmatter の運命** — `image-folder:` は扱う。他ツールの yaml キーは原則どおりなら消える。
   head だけ不透明な例外にするか、原則を貫くか
2. **インポートの礼儀** — 開いたとき「N 行が取り込まれず消えます」と告げるか
3. **md ペインの再同期タイミング** — 打鍵中はバッファ維持。snap はコマンド時か、フォーカス喪失時か
4. **id 照合の設計** — 打鍵の道の 1 点。旧 Doc との突き合わせ規則
5. **列内並べ替え → スロット順の割り付け** — map の列内で動かしたとき、
   反対側スロットとの相対位置の規則
6. **CommonMark 突き合わせテスト** — 方言表の実行可能化
7. **Content 型の初期セット確定** — Link/Image/Code/Svg（+Draw?）。Text は将来枠
