# 反映の粒度 — 変わった所しか触らない

## 問題

反映（`core/tree/reflect.mbt`）は「変わった所だけを md に映す」と言っているが、2 つの場面で約束より広く書く。

1. **中身だけ変わったノードのラベルの行を書き直す。** `walk` はノード自身が違えば「ラベルの行 + 中身」をまとめて断片で置き換える。`## a` の下のコードを 1 枚消すだけで `## a` の行も消して入れ直すので、その行に置いた目印（段 1 の `follow`）が死ぬ。中身を消したときの選択が core の focus に頼っているのはこの当て板。
2. **隙間（空行）に持ち主が無い。** 消えるノードの範囲は「行の頭から最後の中身の尻まで」で、その後ろの空行は残る（`# r\n\n\n## b`）。差すときは逆に、前の行が空行でなくても断片を置くので `hello\n### b` になり、断片の尻の空行と文書の空行が重なって尻に溜まる。

正しさは今までどおり「読み直して形が一致する」検証が持つ。ここで決めるのは**どこを触るか**と**隙間をどう写すか**で、どちらも見た目と目印の話。

## 決め

### 列の差分は 1 つ

子の列（`kids`）がやっている「id で突き合わせ、消えた物は範囲を消し、増えた物は隣に差し、残った物には降りる」を、**中身の列にも同じ関数でやる**。中身にも id と地番が付いた（#41）ので同じ形に乗る。

ノード 1 つの中は 3 つの列に分かれる:

```
行     ラベルの行（マーカー + ラベル。`## a\n` / `- a\n`）
中身   Block の列（地番 [from, to)。to は行末の改行込み）
子     ノードの列
```

- **行**が違えば（ラベル・種類・畳み）、行の範囲 `[from, 行末)` だけを書き直す。種類か畳みが違えば今までどおり部分木ごと
- **中身**は id で列の差分。`SetBlock` で内容だけ変わった中身はその範囲を置き換える。並びが変われば中身の列を丸ごと
- **子**は今までどおり列の差分。並びが変われば容器ごと

これで「ラベルも種類も同じノードの行は編集の範囲に入らない」が成り立つ。

### 隙間は文書の流儀を写す

隙間 = 前の物の尻から次の物の頭までの字（空行）。反映は流儀を決めず、**その容器が兄弟の間に使っている隙間**を写す。

- **区切り（sep）** — 容器に元から 2 つ以上の兄弟が居れば、その間の字に空行が有るかで決める（有れば `eol`、無ければ空）。居なければ既定: 見出しの下と文書の直下は空行 1 つ、項目の下は無し（詰まった列）
- **消える並び**（連続して消える兄弟は 1 つの並びとして扱う）は、次に残る兄弟が居ればその頭まで消す。居なければ前に残る兄弟の尻から消す。前も居なければ**容器の自分の尻**（行の尻、中身が有ればその尻）から消す
- **増える並び**は、次に残る兄弟の手前なら `断片 ⋯ 断片 + sep`、前に残る兄弟の後ろなら `sep + 断片 ⋯ 断片`、容器が空なら `sep + 断片 ⋯`（断片どうしの間も sep）

中身の列も同じ規則で、容器の自分の尻は行の尻、列の尻は最初の子の頭（子が無ければノードの尻）。

### 地番の尻は行末の改行込み

フェンスのコード・`$$`・`:::` の `to` は閉じの行の改行の手前で止まっていた（`closing()`）。他の中身（段落・定義行）は改行込みなので揃える。隙間の算術が「行」で数えられるようになる。

### 中身を消したときの focus はそのまま

core の `delete` が持ち主を返すのは残す（操作の結果として自然）。この枝で目印も生き残るようになるので、どちらでも同じ所を指す。

### 選択は 1 つの値

ts の `selection`（ノード）と `picked`（カード）は排他だと約束して 2 つの欄で持っていた。1 つの値にする:

```ts
type Choice = { kind: "nodes"; sel: Selection } | { kind: "card"; id: number };
```

`host.selection()` / `host.picked()` はこの値の見方（カードのときは `NONE` / ノードのときは null）で、書くのは `choose(c)` 1 本。

## 法則

`core/tree/reflect_law_wbtest.mbt` に足す（見本 × 全 id × 変え方）:

- **行の不可侵** — ラベルも種類も畳みも同じノードの行 `[from, 行末)` は、どの編集の範囲とも交わらない。変え方に「中身を足す / 消す / 置き換える」を足して回す
- **隙間の保存** — 編集を当てた md に、元に無かった連続空行（`\n\n\n`）は無い。消した後・足した後の両方

`core/edit/law_wbtest.mbt` に段をまたぐ法則:

- **目印の生存** — 中身だけを変える操作（AddBlock / SetBlock / MoveBlock / Delete(中身)）の後、持ち主のラベルの目印は `follow` で同じノードに着く

固定の試験（`reflect_wbtest.mbt`）: 中身を 1 枚消す・足す・置き換える、子を消す・足す・動かす、それぞれの md を字で。

## 構成

```
core/tree/reflect.mbt     列の差分 diff（子と中身で共用）、隙間 sep、行の範囲 line_end
core/tree/content.mbt     closing() の尻を改行込みに
core/tree/spans_wbtest.mbt  尻の更新
core/tree/reflect_wbtest.mbt / reflect_law_wbtest.mbt / core/edit/law_wbtest.mbt  法則
src/main.ts               Choice、choose()
src/mindmap.ts            host の見方はそのまま
docs/core.md              反映の節を書き直す（列の差分・隙間）
docs/design.md            設計の型 — 部品ごとの型と段の間の法則（監督のための 1 ページ）
```

## やらないこと

- 反映が全文へ落ちる条件（frontmatter・改行の流儀・根の並べ替え）は変えない
- 畳まれたノードの中の差分（`<details>` が部分木を包むので今までどおり丸ごと）
- カードの番号の追跡（中身に目印を置く）。持ち主の行が生き残れば、カードは持ち主 + 何枚目で引ける — 別の段
