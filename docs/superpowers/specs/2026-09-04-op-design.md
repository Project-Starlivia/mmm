# op — 木への操作（設計）

feat/tree で作り直した core に、**Doc を Doc にする操作**の段を足す。
md も CodeMirror も知らない純粋な関数で、反映（feat/reflect）とも描画
（feat/render）とも独立に積める。md との境界（md + Op → 編集列）は反映が
feat/tree に入ってからの別 PR。

## 位置づけ — core の全体

```
読み   md ──read──> mdAst ──build──> Doc（+ 地番）──project──> View ──JSON──> ts
操作   Doc ──apply(op)──> Doc                                   ← この設計
反映   md + 前の Doc + 地番 + 後の Doc ──reflect──> 編集列 ──> CodeMirror
書き   Doc ──unbuild──> mdAst ──write──> 正規形の md
```

サイクルは 1 本。**書くのは操作だけ、読みのサイクルは決して書かない。**
id は読みが文書順に振る通し番号で、サイクルを越えて持たない。

### core の表に出る関数

揺れを止めるために、いま在るもの・隣の枝で作っている途中のもの・この段で
足すものを 1 か所に並べる。

**`core/tree`（feat/tree に在る）**

| 関数 | 何か |
|---|---|
| `read(md) -> mdAst` | ライブラリの読み |
| `parse(md) -> Doc` | `build(md, read(md))` |
| `build(md, mdAst) -> Doc` | mdAst → Doc。id を文書順に振る |
| `unbuild(doc) -> mdAst` | Doc → mdAst。骨格だけ我々が書く |
| `serialize(doc) -> md` | `write(unbuild(doc))`。正規形 |
| `check(doc) -> [Flaw]` | 型で言えない不変条件。parse の出力は必ず空 |
| `md_ast_sig` / `ast_sig` | 指紋。lab と wbtest が段を切り分けるのに使う |

**`core/tree`（feat/reflect で作っている途中。#29 の id は未取り込み）**

| 関数 | 何か |
|---|---|
| `survey(md) -> (Doc, spans)` | Doc と地番（id → 原文の範囲）を並べて返す |
| `fragment(node, depth, sides, eol) -> md` | 部分木 1 つの正規形 |
| `prose(body, eol) -> md` | 散文の正規形 |
| `reflect(md, before, spans, after) -> [Edit]` | 前後の木を id で比べ、dirty の地番を断片で置き換える |

| `shape(doc) -> Doc` | id を消した形。検証の比較に使う |

**`core/view`（feat/tree に在る。feat/render が `View { frontmatter, trees }` に広げる）**

| 関数 | 何か |
|---|---|
| `project(doc) -> [Tree]` | Doc から削るだけで map の木を作る |

**`core/op`（この設計で足す）**

| 関数 | 何か |
|---|---|
| `apply(doc, op) -> Done?` | 操作を木に当てる。`None` は「できない操作」 |
| `locate(doc, id) -> Place?` | いまどこに居るか |
| `order(doc) -> [Int]` | id を文書順に並べる |

**`core/tree/js`（browser への薄い層。中身は持たない）**

いまは lab のための読みだけ（`mmmTreeJson` / `mmmViewJson` / `mmmCheck` /
`mmmSerialize` と指紋）。反映が入った後に `edit(md, op) -> { edits, focus }` を
1 つ足す（下記「境界」）。

## 型

```
Place = Roots(i)                        // 木の間
      | Under(parent, i, side: Side?)   // 見出しの子 / 項目の子。side は parent が根のときだけ意味を持つ
      | Body(id, i)                     // 中身

Op = Add(at: Place, labels: [String])   | AddBlock(at: Place, content: Content)
   | Rename(id, label)                  | SetBlock(id, content)
   | Delete(ids)                        | Move(ids, at: Place)
   | Wrap(id, label)                    | FlipSide(id)
   | Fold(id, open: Bool)               | Unfold(id)
   | Graft(at: Place, md: String)

Done = { doc: Doc, focus: Int? }        // 操作後の木と、そこで選ぶべき id
```

- **`Place` は「居る場所」と「行く場所」の両方。** `locate` が返すのも、`Move` に
  渡すのも同じ型。行き先は core.md の言う 4 つ（roots / 見出しの子 / 項目の子 /
  中身）で、見出しの子と項目の子は `Under` 1 つ — どちらになるかは親が決める
- **ノードも中身も同じ動詞。** `Delete` / `Move` は id が指すものがノードでも
  中身でも効く。#29 で id を 1 つの列にしたのはこのため
- **添字は操作前の並びで数える。** ts が見ている View の並びそのもの。`Move` で
  同じ親の中を動かすときは、動かすものを抜いてから添字を詰める
- 型の上では「ノードを `Body` へ落とす」が書けるが、apply が `None` で断る。
  型で殺すより充足を実装に任せる方針（core.md）のとおり

## 決め

core.md「操作の決め」を引き継ぎ、この段で決まったものを足す。

- **側は根のもの。** 枝を動かしても側は運ばれず、行き先が決め直す。根の子への
  `Under` の side は、`Some` ならそれ、`None` なら隣の子（添字の位置に居る子、
  末尾なら前の子）の側、隣が無ければ Right
- **綴りは隣に従う。** 新しいノードの sign は、兄弟がいればその sign、いなければ
  親が項目なら項目、それ以外は見出し。モード（`list_from`）は Reform と一緒に来る
- **sign は行き先に従う。** 項目の下へ落ちた見出しは部分木ごと項目になる（情報が
  落ちるのは「記法は行き先に従う」の帰結）。見出しの下へ落ちた項目は、隣の規則で
  見出しか項目になる
- **flipSide は 3 段。** 根は `sides` を一括反転、根の子はその 1 つを反転、深い
  ノードは反対側の末尾へ引き出す（深さは保つので、間を Implicit が埋める）
- **選んだ祖先の中の子孫は無視する。** `Delete` / `Move` の ids に親と子が両方
  あれば、子は親と一緒に動く
- **Implicit は子が尽きたら消える。** `Delete` / `Move` で抜いた後、子の無い
  Implicit は祖先へ向かって消す（check の `BarrenImplicit`）
- **Implicit に名を付ければ見出しになる。** `Rename` は Implicit を
  `HeadingNode { label, children }` にする
- **畳みの名前はラベル。** `Fold` の summary は core が label から埋める。
  Implicit は畳めない（型に fold が無い）
- **比例性。** 操作の影響は、選んだ部分木とその親の中に収まる
- **文字列は常に md として解釈される。** ラベル専用のエスケープや拒否は作らない
- **apply の結果は check を通る。** 通らなければ操作のバグ

### id

- 新しいノード・中身の id は**文書に無い番号**（`order` の最大 + 1 から）。既存の
  id は振り直さない — 反映が前後を id の等しさで突き合わせるため
- `focus` は後の Doc の id 空間で言う（新しいノードなら鋳た番号）。読み直し後の
  番号への読み替えは境界の仕事（下記）

## Op ごとの意味

| Op | 入口 | `None` になるとき | 結果 / focus |
|---|---|---|---|
| `Add(at, labels)` | Enter / Shift+Enter / Tab / + / 新しい根 / 貼り付け（行ごと） | `at` が `Body`、labels が空 | labels の数だけ連続して差す。sign は隣に従う / 最初の新しいノード |
| `AddBlock(at, content)` | Shift+L / Shift+C / 画像 / 貼り付け（URL） | `at` が `Body` でない、id が Implicit | 新しい id で差す / その中身 |
| `Rename(id, label)` | 編集確定 | id が中身 | ラベルを替える。Implicit は見出しになる / id |
| `SetBlock(id, content)` | カードのその場編集 | id がノード | content を替える。id は保つ / id |
| `Delete(ids)` | Delete / × | ids が空、知らない id | 部分木ごと消す。根なら Root ごと、根の子なら side も。Implicit の掃除 / None |
| `Move(ids, at)` | D&D / Alt+↑↓ / Tab / Shift+Tab / 根の脇 / カードの移動 | ids が空、ノードと中身が混ざる、`at` が種類と合わない、`at` が動かすものの中 | 文書順を保って抜き、`at` に差す。side と sign は行き先が決める / 最初の id |
| `Wrap(id, label)` | Shift+Tab | id が中身 | 新しいノードが id の席に座り、id はその唯一の子になる。根なら新しい Root（sides は `[Right]`）/ 新しいノード |
| `FlipSide(id)` | 右クリック Flip side | id が中身 | 3 段の規則 / id |
| `Fold(id, open)` | Shift+H | id が中身か Implicit | `fold = Some { open, summary: Some(label) }`。畳み済みなら open だけ替わる / id |
| `Unfold(id)` | Shift+H | 畳まれていない | `fold = None` / id |
| `Graft(at, md)` | Mod+V（見出しつき md） | `at` が `Body`、md に根も散文も無い | parse した根たちを `at` に差す（側は捨てる）。先頭の散文は行き先の親の body 末尾（`Roots` なら Doc の body）へ / 最初の根 |

ts 側の振り分け（貼り付けが md か行か URL か、Shift+H が Fold か Unfold か）は
読むだけの判断なので ts に残る。**途中の id が要る合成は core、要らない判断は
ts。** これが層の線引き。

## 道具 — 型の異種性を幽閉する場所

`core/op/tool.mbt`（`fresh` だけは `place.mbt`）。Op から呼ぶだけで、外へは出さない。

| 道具 | 何か |
|---|---|
| `pluck(doc, id) -> (Doc, Node)?` | ノードを部分木ごと抜く。側は捨て、Implicit を掃除する |
| `pluck_block(doc, id) -> (Doc, Block)?` | 中身 1 枚を抜く |
| `graft(doc, node, at) -> Doc?` | `Roots` / `Under` に差す。side と sign をここで決める（**唯一の場所**） |
| `graft_block(doc, block, at) -> Doc?` | `Body` に差す |
| `wrap(doc, id, node) -> Doc?` | node が id の席に座り、id を子にする。`Wrap` と、後の `Interpose` が使う |
| `heading(node) -> HeadingNode` | 見出しに。Implicit はラベル `""` |
| `item(node) -> ListNode` | 項目に。部分木ごと畳む |
| `fresh(doc) -> Int` | 文書に無い id |

行き先は 4 つ（`Place` の 3 変種と、`Under` の親の種類）。**これより増え始めたら
設計を疑う**（core.md）。

## 境界（別 PR）

反映が feat/tree に入ってから、`core/tree/js` に 1 つ足す。

```
edit(md, op) -> { edits: [Edit], focus: Int? }

  (before, spans) = survey(md)
  done            = apply(before, op)          // None なら edits は空
  edits           = reflect(md, before, spans, done.doc)
  focus           = number(done.doc) で done.focus を読み替えた番号
```

`number(doc) -> Doc` は文書順に id を振り直す関数で、`order` から出る。反映の
検証（形の一致）が通る限り、これが読み直しの id と一致する。全文正規形へ落ちた
場合も、往復の法則が成り立つ範囲で一致する。

`Op` と `Content` を JSON から受ける（FromJson）のもここ。core は状態を持たず、
操作 1 回ごとに md を読み直す。

## テスト

- **木は手で組む。`parse` で作らない**（unbuild と同じ理由。読みに依存させない）
- 道具 1 つ・Op 1 つずつ wbtest。期待値は木
- 法則: 任意の木と Op で、`apply` が `Some` を返せば `check` が空。
  総当たりは Op ごとの単体が揃ってから
- 反映との結合（`parse(apply(md, reflect(…)))` の形が操作後と一致）は境界の PR

## 段

`feat/op`（`.worktrees/feat/op`、feat/tree から）に 1 段 1 コミット。最後に 1 PR
で feat/tree に squash。

1. `place.mbt` — `Place` / `locate` / `order` / `fresh`
2. `tool.mbt` — pluck / graft / wrap と変換。ここが山
3. `op.mbt` — `Op` / `Done` / `apply`。Op 1 つずつ。最後に check の法則
4. `docs/core.md` — 「操作」の節にこの型と決めを書く。「undo はスナップショット」
   の行を消す（反映が純粋関数になった今、undo は CodeMirror のもの）。
   spec.md「構成」に `op/` を足す

## 後回し・決めていないこと

- `Reform(list_from)` とモード。開いたときの自動判定（リスト項目の最も浅い深さ）
  も、意味の裁定なので core の読み関数として一緒に足す
- `Comment(ids)`。断片に依存する。入口も未決
- `Interpose(id, target)`（Shift+ドラッグ）。道具 `wrap` は用意する
- fold の `open` を Mindmap でどう見せるか、`Shift+H` が 2 状態を巡回するか
  3 状態か。型には載せてあるので、決めても Op は変わらない
- `Graft` の先頭の散文の置き場は「行き先の親の body 末尾」と決めたが、
  `Roots(i)` で `i > 0` のときは貼った場所より前に出る。ts は `Roots(0)` 以外で
  散文つきの md を渡さない前提
