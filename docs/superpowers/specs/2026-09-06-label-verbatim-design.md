# label-verbatim — 名前は md の 1 行（設計）

issue #92（`_` `*` を打つと `\` が出る）から。**名前は md の 1 行の原文で、mmm は
その字を変えない。** 逃がし（`\`）は人が打つもので、mmm は足しも引きもしない。
書かれた md が何を意味するかは文法が決め、地図はその意味を描く。

## いま何が苦しいか

「名前」の定義が読む側と書く側で違う。

| 側 | 名前とは | 例 |
|---|---|---|
| 読む（`build.mbt` の `head_label` / `item_label`） | マーカーの後ろから行末までの**原文** | `## foo\_bar` → `foo\_bar` |
| 書く（`unbuild.mbt` の `inlines`） | `parse_inlines` で読み直した **mdAst** | `foo_bar` → Text → ライブラリが `foo\_bar` と書く |

ライブラリ（mizchi/markdown）は正しい。Text の `_` を `\_` と書くのは「AST が往復で
変わらない」約束どおりで、remark も同じ。食い違いは mmm の中の 2 つの定義にある。

症状は 2 つ出る。

- 打った `foo_bar` が md では `foo\_bar` になり、読む側が原文を返すので地図に `\` が出る。
  `__init__` は Strong に読まれて `**init**` に化ける
- 一方で、リストアイテムの中身は文書と同じ規則で読まれるので、名前の先頭が `#` `>`
  `1.` なら別のブロックになる。ここは逃がされず、`- # foo` は「空の項目の中の見出し」
  になって名前が消える。今の読みは項目の中の見出しを Opaque にするので地図にも出ない

逃がしの方針が無いことが本当の問題で、`\` はその症状の 1 つ。

## 決め

- **名前は md の 1 行の原文。** 読む側は今のまま。書く側は名前を `parse_inlines` に
  通さず、そのまま行に置く（ライブラリには「中身を逃がさずに書く」`HtmlInline` で
  素通しさせる。mmm 側では `verbatim` と呼ぶ）。対象は見出しの名前と項目の名前
- **mmm は名前の字を足しも引きもしない。** `\` が md に現れるのは人が打ったときだけ。
  読む側の `\` は原文のまま名前に入る。表示で落とすかは見せ方の決めで、この設計の外
- **項目の中身は文書と同じ規則で読む。** 項目の中の見出しは、その項目の子ノード
  （型は `ListNode` のまま。「項目の子孫は項目」は変えない）。見出しの後ろの段落・
  コード・入れ子のリストは、文書と同じくその見出しの中身と子。`#` の数は入れ子の
  相対だけを決め、飛びは埋めない（項目は相対記法なので Implicit は無い）。
  見出し以外（引用・HTML）は今までどおり Opaque
- **綴りは席が決める。** 読んだ形を書き戻すとき、項目の子は入れ子の項目で綴る
  （#117 の規則）。`- # node` を触れば `- - node` になり、読み直すと同じ木
- **名前に例外は無い。** `check` の `UnwritableName`（畳みの名前に `</summary>` や
  空行）は落とし、`writable` も消す。名前の字で操作を断らない。残る破れは全部「木の
  形が md に書けない」もの（`Swallowed` / `GappedItem` / `TooDeep` など）
- **木に無い focus は選択を解く。** 操作の後の木と、書いた md を読み直した木の形が
  一致しないとき（`- ---` で項目が水平線になった等。合流の安全網が開く場面と同じ）、
  core の `edit` は focus を None で返し、TS は選択を解く。focus は文書順の番号なので、
  形がずれたまま返すと別のノードを指す。今は `isNode` が偽だとカードとして選ぶ道に
  落ち、無いカードを選んだ状態になる（#91 で見えていた穴）

## 帰結（受け入れる）

| 打った名前 | md | 読み |
|---|---|---|
| 見出し `foo_bar` | `## foo_bar` | `foo_bar` |
| 見出し `__init__` | `## __init__` | `__init__` |
| 見出し `# node` | `## # node` | `# node` |
| 見出し `foo ##` | `## foo ##` | `foo`（閉じの `#` は飾り） |
| 項目 `# node` | `- # node` | 空の項目 → 子 `node`。触れば `- - node` |
| 項目 `1. node` | `- 1. node` | 空の項目 → 子 `node`（今もこう読める） |
| 項目 `> q` | `- > q` | 空の項目 + Opaque（今と同じ） |
| 項目 `---` | `- ---` | 水平線。項目は無くなり側が変わる。Undo で戻る |
| 畳みの名前 `a</summary>b` | そのまま | md が言うとおりに読む |

これらは全部「md が言うとおり」で、字は 1 つも失われない。`# node` を字にしたい
人は md ペインと同じく `\# node` と打つ。

`- x` の後ろに `# n` の行がある手書きの md も、この読みで `x` の子 `n` になる
（今は `x` の Opaque）。

## 法則

守る法則は今のまま。

- 往復: `read(serialize(read(md)))` の形が `read(md)` と一致する
- 意味の保全: 書いた後に字が減っていない。名前を素通しにするので今より通りやすい

足す見本:

- 名前の字: `foo_bar` / `__init__` / `a\_b` / `# node` / `foo ##` / `a</summary>b`
  を見出しと項目それぞれで往復（`edit` の Rename / AddNode / Wrap）
- 項目の中の見出し: `- # n` / `- x` + `# n` / `- # n` + `## s` + `text` + `- k` /
  `- ### a`（飛び）/ `- ## a` + `# b`（浅く戻る）
- `- ---`: 木から消えて側が変わる。focus は None

## Link の題は別

`[題](url)` の題は名前ではなく inline の構造で、`]` は逃がさないとリンクが閉じる。
ライブラリは `[` を逃がして `]` を逃がさない（#93）。この設計の対象外で、#93 で決める。

## 改行を含む名前は別

見出しの名前に改行が在るとき setext で書く決め（#85）はそのまま。書く側は `spell`
が担い、深さ 3 以上へ改行入りの名前が来る操作は断る。

## 文書

- `docs/core.md`「型」— 「項目の領土に書かれた見出しは骨格にならず、原文のまま中身に
  なる」を「項目の中身は文書と同じ規則で読む。見出しは項目の子」に。md に書けない
  並びの一覧から `UnwritableName` を落とす
- `docs/core.md`「決まっていないこと」— 「ライブラリの正規化をどこまで受けるか」を
  この決めで閉じる（名前は素通し。#85 の setext は `spell`）
- `docs/spec.md` — 「名前は md の 1 行。mmm は字を変えない。`\` は人が打つ」を 1 段落

## 却下した案（再提案しない）

- **逃がす** — 名前を行に置くとき、構造を壊す先頭（`#` `>` `-` `1.` `---` ...）を
  mmm が `\` で守る。列挙か読み直しが要り、mmm が置いた `\` が名前に見える。
  拡張（`$$` `:::`）で漏れる
- **名前は AST の字**（世間の WYSIWYG の流儀） — 読む側を Text から取る。地図に
  太字・斜体を描く仕組みが要り、`\_foo\_` と `_foo_` の区別が失われて触ると意味が変わる
- **断る** — 構造を壊す名前で操作を None に。名前に例外を 1 つでも残すと「名前は
  md の 1 行」が嘘になる
- **md ペインで `\` を隠し、カーソル行だけ見せる** — ソースを見せる場所で字が
  出たり消えたりする。mmm が `\` を書かないので不要
