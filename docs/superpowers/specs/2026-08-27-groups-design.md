# `---` の分割 — グループと左右

## なぜ

ルート直下の枝が増えると、片側 1 列のマップは縦に間延びする。`---` で枝の
並びを**グループ**に区切り、グループ単位で**左右**に振り分けられるようにして、
地図として読める形にする。

`---` に意味を持たせるのは 3 度目になる。過去 2 回の教訓が出発点
（記録は `docs/audit/FIXES-2026-08-13.md`）:

- **v1（束）**: `---` ごとに右・左・右…と交互配置。「操作しても側が変わらない」
  を保とうとした瞬間、並べ替え・最下段の譲り・偶奇の帳尻が芋づるで必要になり、
  md も見た目も嘘をつき始めた
- **v2（トグル）**: どの `---` も「そこから下の左右が入れ替わる」。機構は
  痩せたが、**側の自由・順序の安定・導出レイアウトは同時に成立しない**という
  結論が残った — 記号が 1 種類しか無いので、隣り合うグループの「側が同じか
  違うか」を局所に表現できず、掃除は偶数本規則の帳尻になった
- Web 化で全廃。いまの `---` はただの本文の行

今回の記法は**太さ 2 種**でこのトリレンマを解く。隣接グループの側の差は
1 ビットで、それを**その境界の太さがそのまま持てる**:

- どんな側の並びも表現できる（1 つの隙間に 1 つの境界で必ず足りる）
- 操作は常に局所編集（下のグループが巻き添えで反転しない）
- 導出は非可侵のまま。導出元は「連続する thematic break の本数」= 順序・位置の
  情報で、md エコシステムが意味として保存するもの。綴り（`---` / `***` / `___`）
  は区別しない — CommonMark ではどれも同じ thematic break

## 記法

```
# root

## a          … 右（グループ 1）
## b          … 右（グループ 1）

---              ── 分割

## c          … 右（グループ 2。同じ側の次のグループ）

---              ┐
---              ┘ 分割 + 切り替え

## d          … 左（グループ 3。ここから反対側）
## e          … 左（グループ 3）
```

マップではルートを挟んで、右に [a b] と [c] が間隔を空けて縦に積まれ、
左に [d e] が伸びる。

- `---` **1 本** = **分割**。次のグループを同じ側に始める
- `---` **2 本連続** = **分割 + 切り替え**。次のグループを反対側に始める

## 読む規則 — 寛容に

連続する区切り行のかたまりを **1 つの境界**と読む。「連続」は間の空行と
hide マーカー行を透過して数える（畳んだだけで境界が死ぬ・分裂する、を防ぐ
— v1 の実バグ）。**1 本の境界は分割だけ、2 本以上の境界は分割 + 切り替え**。
3 本以上も「切り替え 1 回」— 本数の偶奇に意味を持たせると、1 本の増減が
遠くの表示を変える v2 の再演になる。

区切り行が**有効**なのは次の全部を満たすとき。満たさなければただの本文の行:

1. フェンスの外にある
2. 直前が本文の行でない（`本文\n---` は CommonMark の setext 見出し `##` と
   同じ形。空行・構造行・区切り行の直後だけを区切りと読む）
3. 境界の次の構造行（空行・hide マーカー透過）が、**その木のルート直下の深さ**
4. その木のルートより後にある

3 と 4 で front matter（ルートより前）・木をまたぐ `---`（次が深さ 1）・
深い階層の `---`（次が直下より深い）は自動的に無効になる。特別扱いは持たない。

- **側**はルートの側（右）から始まり、太い境界を通るたびに反転する。
  ルート見出し直後の境界も有効 — 2 本ならいきなり左始まり
- **空のグループは表現できない**。枝が無い区間は「区切り行の連続」なので
  1 つの境界に潰れて読まれる。空という状態が最初から存在しない
- **区切り行はどのノードの範囲にも属さない**（コピー・移動・削除に付いて
  こない）。範囲を縮めるのは「境界の直前で終わるノード」だけ — 一律に切ると
  ルートの範囲まで切れる（v1 の教訓）
- **深さの読み替えはしない**。`Node.depth` は今までどおり書かれた深さのまま。
  v1 の「束の中は相対の深さ」は raw_depth の分裂を生み、バグの震源だった
- 区切りの無い文書は 1 グループ・全部右 — **既存文書の表示は変わらない**

## 書く規則 — 保守的に

区切りを書くのは**操作（Mod+D&D / Flip side）と掃除だけ**。md を手打ちした
ときは読むだけで、勝手に書き直さない。

- 正規形は 1 つ: 分割 = `---` 1 行、切り替え = `---` の 2 行連続（間に空行
  なし）。直前が本文の行なら空行を 1 つ挟む（setext 化を防ぐ）
- **書く列はルートの形が決める**。見出しルートなら列 0。リスト項目ルート
  （L モード）なら**その項目の中身の列へ字下げする** — 列 0 に書くと外の
  CommonMark パーサがそこで外側のリストを閉じ、木そのものが割れる。
  `insertContent` / `fence_open` の `base` と同じ理屈で、検証も同じく
  `@lezer/markdown` に読ませて木が一致することを固定する

### 掃除 — 不変条件は 1 つ

**どの操作の前後でも、操作対象でないグループの側は変わらない。**

機構も 1 つ: グループ列から境界が消えるとき（グループが空になった・
親作成で枝が直下から消えた）、その境界の反転ぶんを**次（下）の境界へ xor で
畳む**。次が無ければそのまま捨てる。

| 消える並び | 残る境界 |
|---|---|
| 分割 + 分割 | 分割 |
| 分割 + 切り替え（順不同） | 切り替え |
| 切り替え + 切り替え | 分割（反転 2 回 = 無し） |

v2 の偶数本規則はこの 1 規則に吸収される。触ってよいのは**直前まで区切り
として効いていた行だけ** — 無効な `---`（ただの本文）には決して触らない。
掃除は構造コマンド共通の後処理として 1 箇所に置き、同じトランザクションに
積む（undo は常に 1 回）。

## レイアウト

- ルートを挟み、右のグループは右へ、左のグループは**ミラーで左へ**伸びる。
  ルートの箱・ラベルは反転しない — 反転するのは配置（x）と線の向きだけ
- 同じ側のグループは文書順に縦へ積む。グループ間は広い間隔（`GAP.group`）
- **区切り線は常に描く**。線を引くのは「同じ側の列の中の、グループの継ぎ目
  すべて」— 意味の境界と 1:1 ではない（右 A・左 B・右 C の並びでは、右列の
  A と C の継ぎ目に線が出るが、そこにあるのは太い境界 2 つ）。線は見せ方で
  あって意味ではないので、これでよい。文書から決まるものなので render が
  描き、書き出し（SVG/ラスタ）にも入る
- 2 つ目以降の木・`#` 前の木は従来どおり下部に積む。**各木が自分の区切りを
  読む** — 主ルートの特別扱いは無い
- エッジ・ドロップ判定・ホバー `+` は**枝ごとの向き 1 符号**で追従する。
  v1 の u/v フレーム機構（`Frame`/`projU`/`projV`）は戻さない

## 操作

キーは README の流儀どおり `Mod` = `Ctrl` / `Cmd`。

| 操作 | 動作 |
|---|---|
| **Mod+ドラッグ** | グループモード: グループの継ぎ目・上下端・反対側にスロットが出て、落とすとそこに**新グループ**（枝はルート直下へ読み替え。境界の太さは側の差から自動で決まる） |
| **右クリック → Flip side** | そのノードの属するグループを**丸ごと反対側へ**。実体は両脇の境界の太さを xor（両方反転）— そのグループだけが移り、他は 1 つも動かない |
| **Alt+↑↓** | 従来どおり並べ替え。ただし**グループの壁で止まる** |
| **Mod+Alt+↑↓** | 壁を越える並べ替え。端で押すと隣のグループの端に入る（太い境界を越えれば側も変わる）。壁の無い深さでは Alt+↑↓ と同じ |
| **←→** | 画面の向きに従う。左の枝では ← が子へ、→ が親へ |
| 普通のドラッグ | 従来どおり（子 / 兄弟 / 親割り込み）。別グループの枝の隣に落とせば普通にそこへ移る — **グループは場所であって所有ではない** |

- 「境界の反転」は **Flip side の 1 形だけ**にする。境界 1 本の生のトグルは
  そこから下が全反転する遠隔作用で、しかもグループ単位の反転を組み合わせれば
  どんな側の並びにも届く（表現力が等価）。届くのに危ない道は増やさない
- `Tab`（直前の兄弟の子へ）は壁で止まる（Alt+↑↓ と同じ扱い）。
  `Enter` の兄弟追加はグループの中に足す（区切り行は範囲の外なので自然にそうなる）
- 左に枝がまだ 1 つも無くても、Mod+ドラッグの反対側スロットは常に出る —
  最初の左グループはこれで作る

## 見送り（YAGNI）

- 深い階層のグルーピング（直下だけ。深さの読み替えを復活させない）
- グループの名前・見出し化
- 左側のホバー `+` ボタン（Mod+D&D で足りる。欲しくなったら足す）
- キーボードでの新グループ作成
- グループ単位のドラッグ（全選択 + Mod+D&D で代用）
- 境界 1 本の生のトグル（上記）

## 置き場所

- **core**: 区切りの走査（parser）、グループと側の導出（doc）、snapshot に
  ノードごとの `group`（木の中のグループ通し番号）と `left`（枝ごとに一定。
  ルート直下の値を子孫にもそのまま出し、UI は再導出しない）、
  コマンド `moveNewGroup(ids, スロット)` / `flipSide(id)`、構造コマンド共通の
  掃除。**どの行が区切りかの判定は core にしか無い**
- **map/**: layout（左右ミラー・`GAP.group`・区切り線の位置）、drop（スロット
  と向きの符号）、navigate（視覚方向）、edge（向きの符号）、render（線の描画）
- **mindmap.ts**: Mod+ドラッグのグループモードとスロット表示、
  Mod+Alt+↑↓、右クリックメニューの Flip side
- **README**: レイアウト規則（「`---` はただの本文の行」を差し替え）と操作表

## 段取り

1. **読む + 見せる** — parser・グループ/側の導出・snapshot・左右レイアウト・
   区切り線。読みは木を変えない（parent/depth は不変）ので、ここまでで
   既存操作は全部そのまま動く
2. **操作 + 掃除** — Mod+D&D・Flip side・Mod+Alt+↑↓・壁・共通の掃除。
   書く操作と掃除は 1 つの単位（書けるのに掃除が無いと、空グループの残骸が
   堆積する）

## テスト

- core: 有効条件（setext / フェンス / hide 透過 / front matter / 木またぎ /
  深い階層）、境界の本数と側、掃除の xor 3 通りと不変条件（操作対象でない
  グループの側が変わらない）、各構造コマンド経由の掃除、undo 1 回
- TS: layout のミラーと線、drop のスロット、navigate の視覚方向
- 外部パーサ整合: リスト形の文書に区切りを書いて `@lezer/markdown` と
  木が一致すること
- 既存の roundtrip / corpus は区切りの無い文書で不変
