# verbatim — 読んだ綴りは保ち、新しいものだけ綴る（設計）

issue #92（名前に `_` `*` を打つと `\` が出る）から始まり、#84 #87 #94 #85 #93 まで
同じ根に行き着いた。

> **md から読んだものは、そのまま持つ。mmm が綴りを決めるのは、新しく作るときと、
> 席が変わって保てなくなったときだけ。**

書かれた md が何を意味するかは文法が決め、地図はその意味を描く。mmm は字を足しも
引きもしない。逃がし（`\`）は人が打つもの。

## いま何が苦しいか

書く側が、読んだ原文を返していない。名前は `parse_inlines` で mdAst にしてから
ライブラリに書かせ、中身（Opaque・水平線・Details）は md として読み直してから
ライブラリに書かせる。ライブラリは AST を正規形で書くので、触ったノードの綴りが
まとめて変わる。

| 症状 | issue |
|---|---|
| 名前 `foo_bar` が `foo\_bar` になり、読む側は原文を返すので地図に `\` が出る。`__init__` は `**init**` に化ける | #92 |
| 触った所だけ `*`→`-`、`1.`→`-`、setext→ATX、`~~~`→```` ``` ````、定義行は末尾へ | #84 |
| 表が桁揃えされ、全角では揃わない | #87 |
| 表があると合流の安全網（読み直して一致しなければ全文正規形）が毎回開く | #94 |
| 水平線をライブラリが `***` と書くので `spell` が `---` に直す。段落直後は setext になるので直さない、という例外規則 | — |
| 改行を含む見出しの名前が ATX に落ち、2 行目が段落になる | #85 |

一方で、名前の先頭が `#` `>` `1.` のとき項目の中身は別のブロックに読まれるが、
今の読みは項目の中の見出しを Opaque にするので地図から消える。逃がされてもいない。

ライブラリ（mizchi/markdown）は正しい。Text の `_` を `\_` と書くのは「AST が往復で
変わらない」約束どおりで、remark も同じ。問題は mmm が読んだ綴りを捨てて
ライブラリに綴らせていること。

docs/core.md「操作」の決めに「文字列は常に md として解釈される。ラベル専用の
エスケープや拒否は作らない」は既に在る。この設計はそれを実装に通し、中身と骨格の
綴りにも同じ線を引く。

## 決め

### 綴りの表

読んだら保つ・新しく作るときの既定・席が変わって保てないときだけ綴り直す、の 3 列。
「席で保てないとき」の列が、mmm が綴りを変える場面の全部。載っていないものは変えない。

| 記法 | 読んだら | 新しく作るとき | 席で保てないとき |
|---|---|---|---|
| 見出しの深さ（`#` の本数） | 深さとして保つ（飛びは Implicit） | 親の深さ + 1 | 動かせば席の深さ。7 段目は項目（#108） |
| 見出しの書き方（ATX / setext） | 保つ | ATX | setext は深さ 3 から書けない → ATX。名前に改行が在れば ATX に落とせないので、その操作は断る（#85） |
| 見出しの閉じ `##` | 保つ | 付けない | — |
| 項目のマーカー（`-` `*` `+` / `1.` `1)`） | 保つ（列ごと） | 隣の列に従う（`sign_at`）、無ければ `-` | 別の列へ動けばその列のマーカー（混ぜると別の列に割れる） |
| 番号付きの数字 | 保つ | 隣に続く数字 | — |
| 入れ子の字下げ幅 | 保つ | 2 | — |
| 項目の詰め / 空行（tight / loose） | 保つ | 詰める | ラベル直後の空の項目は空行が要る（setext 化を避ける。今の `underlined`） |
| 側の境界 `---` `***` `___`・本数 | 保つ | `---` | — |
| 水平線のカード | 保つ | mmm は作らない | — |
| `<details>` の包み（属性・空行） | 保つ（既に `text`） | 今の形 | — |
| 名前の字（`\` 含む） | 保つ | 打った字そのまま | — |
| Opaque（段落・表・引用・HTML） | 保つ | mmm は作らない | — |
| コードのフェンス（```` ``` ```` / `~~~`・長さ・info） | 保つ | ```` ``` ```` | 中身に ```` ``` ```` が混ざれば長さを伸ばす |
| リンク / 画像の書き方（`[t](u)` / `<u>` / 素の URL / 参照） | 保つ | `[t](u)` / `![a](s)` | 題や URL を編集したら生成 |
| 定義行 `[r]: url` の位置 | 保つ（その場） | — | — |
| frontmatter | 保つ（既に raw） | — | — |
| 改行（LF / CRLF） | #95 で別に決める | | |

### 名前

- 名前は md の 1 行の原文。読む側は今のまま（マーカーの後ろから行末まで）。
  書く側は `parse_inlines` に通さず、そのまま行に置く。対象は見出しと項目の名前
- **名前に例外は無い。** `check` の `UnwritableName`（畳みの名前に `</summary>` や
  空行）と `writable` を消す。`Fold` の「書けなければ名無しで畳む」も消え、畳みの
  名前は常にラベルそのもの。名前の字で操作を断らず、字を落とさない。残る破れは
  全部「木の形が md に書けない」もの（`Swallowed` / `GappedItem` / `TooDeep` など）
- 読む側の `\` は原文のまま名前に入る。表示で落とすかは見せ方の決めで、この設計の外

### 項目の中身は文書と同じ規則で読む

- 項目の中の見出しは、その項目の子ノード（型は `ListNode` のまま。「項目の子孫は
  項目」は変えない）。見出しの後ろの段落・コード・入れ子のリストは、文書と同じく
  その見出しの中身と子。`#` の数は入れ子の相対だけを決め、飛びは埋めない（項目は
  相対記法なので Implicit は無い）。見出し以外（引用・HTML）は今までどおり Opaque
- 書き戻すときは席が綴る（#117）。`- # node` を触れば `- - node` になり、読み直すと同じ木

### 木に無い focus は選択を解く

操作の後の木と、書いた md を読み直した木の形が一致しないとき（`- ---` で項目が
水平線になった等。合流の安全網が開く場面と同じ）、core の `edit` は focus を None で
返し、TS は選択を解く。focus は文書順の番号なので、形がずれたまま返すと別のノードを
指す。今は `isNode` が偽だとカードとして選ぶ道に落ち、無いカードを選んだ状態になる。

### 書く側の形

書く側が生成するのは、新しく作ったものと、席で保てなくなったものだけ。それ以外は
読んだ原文を置く。`spell` の `***`→`---` と段落直後の例外は消える（水平線の綴りを
保てば、生成する水平線は境界の `---` だけで、骨格の間に空行付きで置くので setext には
ならない）。改行を含む見出しの名前は setext で書く（#85）— これは「読んだ setext を
保つ」の帰結で、`spell` の特別な規則ではない。

## 帰結（受け入れる）

| 打った名前 | md | 読み |
|---|---|---|
| 見出し `foo_bar` | `## foo_bar` | `foo_bar` |
| 見出し `__init__` | `## __init__` | `__init__` |
| 見出し `# node` | `## # node` | `# node` |
| 見出し `foo ##` | `## foo ##` | `foo`（閉じの `#` は飾り。書き戻しも `## foo ##`） |
| 項目 `# node` | `- # node` | 空の項目 → 子 `node`。触れば `- - node` |
| 項目 `1. node` | `- 1. node` | 空の項目 → 子 `node` |
| 項目 `> q` | `- > q` | 空の項目 + Opaque |
| 項目 `---` | `- ---` | 水平線。項目は無くなり側が変わる。focus は None。Undo で戻る |
| 畳みの名前 `a</summary>b` | そのまま | md が言うとおりに読む |

全部「md が言うとおり」で、字は 1 つも失われない。`# node` を字にしたい人は md
ペインと同じく `\# node` と打つ。

触ったノードでも、編集していない部分は字が 1 つも変わらない。名前だけ変えれば
名前の行だけ。

## 型に持つもの

原則の帰結として、読んだ綴りを持つ場所が要る。今無いのは: 境界の綴り、水平線の
綴り、コードのフェンス、リンク / 画像の原文、項目のマーカーと字下げと詰め、見出しの
書き方と閉じ。名前・Opaque・Details・frontmatter は既に原文を持つ。

持ち方（Block とノードに原文を 1 本持つか、種類ごとに欄を持つか）は実装計画で
決める。合流は id の等しさで前後を突き合わせるので、原文を持つこと自体は合流を変えない。

## 法則

守る法則は今のまま。

- 往復: `read(serialize(read(md)))` の形が `read(md)` と一致する
- 意味の保全: 書いた後に字が減っていない
- 足す法則: **触っていない字は変わらない** — 1 ノードを Rename したとき、そのノードの
  名前の行以外の字が原文と一致する

足す見本:

- 名前の字: `foo_bar` / `__init__` / `a\_b` / `# node` / `foo ##` / `a</summary>b`
  を見出しと項目それぞれで往復（Rename / AddNode / Wrap）
- 項目の中の見出し: `- # n` / `- x` + `# n` / `- # n` + `## s` + `text` + `- k` /
  `- ### a`（飛び）/ `- ## a` + `# b`（浅く戻る）
- `- ---`: 木から消えて側が変わる。focus は None
- 綴りを保つ: `*` の列、`1)` の列、setext、閉じ `##`、`***` の境界、`~~~` のフェンス、
  表、素の URL、定義行 — それぞれ隣を Rename して字が変わらない
- 席で綴り直す: setext を深さ 3 へ動かす、`*` の列の項目を `-` の列へ動かす

## 対象外

- **Link の題**: `[題](url)` の題は名前ではなく inline の構造で、`]` は逃がさないと
  リンクが閉じる。ライブラリは `[` を逃がして `]` を逃がさない（#93）。題を編集した
  ときの生成の話として #93 で決める
- **改行**: LF / CRLF は #95
- **表示で `\` を落とすか**: 落とさない。地図の名前に inline の記法（`**` `~~` `\`）を
  どう見せるかは 1 つの話なので、まとめて別に決める

## 文書

- `docs/core.md`「型」— 「項目の領土に書かれた見出しは骨格にならず、原文のまま中身に
  なる」を「項目の中身は文書と同じ規則で読む。見出しは項目の子」に。md に書けない
  並びの一覧から `UnwritableName` を落とす。原文を持つ欄を型に足す
- `docs/core.md`「パイプライン」— 書きの `spell` の説明を書き直す（`***` の規則が消える）
- `docs/core.md`「操作」— 「畳みの名前はラベル（`<summary>` に書けなければ名無しで畳む）」の括弧を落とす
- `docs/core.md`「決まっていないこと」— 「ライブラリの正規化をどこまで受けるか」を
  この決めで閉じる
- `docs/spec.md` — 「正規形」の節を、綴りの表の「新しく作るとき」の列に合わせる。
  「名前は md の 1 行。mmm は字を変えない。`\` は人が打つ」を 1 段落
- unbuild.mbt 冒頭の「その正規化は**この段では素直に受ける**」を書き直す

## 却下した案（再提案しない）

- **逃がす** — 名前を行に置くとき、構造を壊す先頭（`#` `>` `-` `1.` `---` ...）を
  mmm が `\` で守る。列挙か読み直しが要り、mmm が置いた `\` が名前に見える。
  拡張（`$$` `:::`）で漏れる
- **名前は AST の字**（世間の WYSIWYG の流儀） — 読む側を Text から取る。地図に
  太字・斜体を描く仕組みが要り、`\_foo\_` と `_foo_` の区別が失われて触ると意味が変わる
- **断る** — 構造を壊す名前で操作を None に。名前に例外を 1 つでも残すと「名前は
  md の 1 行」が嘘になる
- **md ペインで `\` を隠し、カーソル行だけ見せる** — ソースを見せる場所で字が
  出たり消えたりする。mmm が `\` を書かないので不要
- **生成物を規則で直す**（`spell` の `***`→`---` のような規則を増やす） — 元の入力を
  持てば要らない。規則は生成物ではなく入力を守る向きに置く
