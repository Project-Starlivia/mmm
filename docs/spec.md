# mmm — 仕様

概要・実行方法・ライセンスは [README_JA.md](../README_JA.md)（[English](../README.md)）。ここには UI の細部と挙動を置く。

## 構成

**コアが「その .md が何を意味するか」の唯一の判定者で、TS は「それをどう
見せるか」だけを持つ。** 見出し・フェンス・hide 領域の判定は core に 1 つしか
無い（同じ規則を UI 側で書き直すと、静かに食い違う）。

**型は名乗らせず確かめる。** `as T` も `!` も置かない — 外れていても誰も
気づけないため（実際 `<svg id="logo">` を `HTMLElement` と名乗り続けていた）。
`instanceof` / 型ガード / 既定値のどれかで確かめる。
守っているかは `test/assertions.test.ts` が見張る。

```

        文字オフセットの編集セットに変換されるため、未編集行のバイト列は
        決して再整形されない。

ブラウザで動く。ファイルは **File System Access API** で 1 つずつ開き、
開いたハンドルへ上書きする。**Chromium 系でしか動かない**と言い切っていて、
ダウンロードでの保存にフォールバックしない — 2 本目の道を作ると、そちらでは
画像が死に「実体はただの .md」が壊れるため。詳しくは `web.md`。

## 開発

必要: Node.js、pnpm、[MoonBit toolchain](https://www.moonbitlang.com/download)
(`moon` が PATH にあること)

```
pnpm install
pnpm run dev        # コアをビルドしてから vite（http://localhost:13131）
```

- 本番ビルド: `pnpm run build` → `pnpm run preview` で確認
- コア(`core/*.mbt`)を変更したら `pnpm run core` で JS を再生成
- コアのテスト: `pnpm run test:core` / UI 側のテスト: `pnpm test`
- 型チェックだけ: `pnpm run check`（src と test の両方）
- 性能の物差し: `pnpm run perf`（追加の依存なし。規模ごとに init / 1 打鍵 /
  カード抽出 / 全コピー / 全段下げを測る。`pnpm run perf -- fixtures` で
  `test/fixtures/*.md` も）。負荷サンプルの作り直しは `pnpm run fixtures`

### 配る

**Cloudflare Workers の静的アセット**に置く（`wrangler.jsonc`）。mmm は
ブラウザだけで動くので**サーバ側のコードは 1 行も持たない** — `main` の無い
配信だけの Worker で、ファイルは Cloudflare が直接返す。

入口は `/` の 1 つだけで、クライアント側のルーティングは持たない。だから
`not_found_handling` は `none` にしてある — 無い場所には素直に 404 を返す
（`single-page-application` にすると綴り違いにもアプリを返してしまい、
「見つからなかった」ことが伝わらない）。

配り先は **`mmm.<アカウント名>.workers.dev`**（`workers_dev: true`）。書かなく
ても既定でそうなるが、選んだ結果であって書き忘れではないことを残すために
明示してある。独自ドメインへ移すときは `routes` に差し替える。

```
pnpm run deploy       # ビルドしてから配る
pnpm run deploy:dry   # 配らずに設定と中身だけ確かめる
```

**`main` に入ったものは GitHub Actions が自動で配る**（`.github/workflows/ci.yml`）。
1 つのファイルに `check` と `deploy` の 2 つを置いてあり、`deploy` は
`needs: check` で待つ — ワークフローをまたぐと順番を約束できず、確かめ
終わる前に配り始めてしまう。**配るのは `check` が組んだ dist そのもの**
（artifact で渡す）で、組み直さない。確かめたものと配るものが別々になる
余地を残さないため。

MoonBit は公式の GitHub Action が無いので、配布スクリプトで入れて
`$HOME/.moon/bin` を PATH に通している。

要る Secrets は 2 つ:

| 名前 | 何か |
|---|---|
| `CLOUDFLARE_API_TOKEN` | **Edit Cloudflare Workers** 権限のトークン |
| `CLOUDFLARE_ACCOUNT_ID` | ダッシュボード右下の Account ID |

## 使い方

**画面に出る文字は英語**(ボタン・メニュー・通知)。docs とコード内のコメントは
日本語のまま — 読む相手が違う。以下では英語のラベルをそのまま引く。

### 帯と、ペインの隅

**帯は「文書に何かする」だけ。「いま何を見ているか」はペインの中に置く。**

```
mmm  empty.md              Files  [SVG ⤓ │ ▾]  ⋯
```

**帯は 1 本で、左は名乗り・右は道具**。ロゴとファイル名だけが左に残り、
`Files` / 書き出し / `⋯` は右へ寄せてひと塊にする — 何かしたいときに
探す場所が 1 つで済む。
**帯のボタンはみな枠を持たない字**。押すものではなく「開くところ」だと
佇まいで言う(ネイティブのメニューバーと同じ)。枠は透明のまま置いてあり、
場所だけ取らせて**継ぎ目の 1 本にだけ色を付ける**(下記)。

`Files` は**文書ぜんぶに効くもの**を集める — New / Open / Rename / Save /
Save as と、画像フォルダ。`⋯` は**低頻度だが消したくないもの** —
Undo / Redo / ブランドカラー / テーマ / Shortcuts / GitHub。
消さずに、優先度だけ下げる。3 つの塊(戻す / 見た目 / 外に開く)に分けてある。

**そのペインにだけ効くものは、帯に出さずペインの隅に浮かせる**(`.pane-tool`)。
md の右上に書き方(H / n+ / L)。普段は沈めておいて、触れたら起きる。
**押しても下へ抜けない** — 道具は乗っているだけで、下のキャンバスとは
別のもの(マップは背景を押されると矩形選択を始めてポインタを捕まえるので、
抜けるとボタンが効かなくなる)。md 側は**スクロールバーの内側**に置く。
あの帯はブラウザが押下を横取りし、`z-index` では前に出せない。

**ペインの開閉は、隅ではなく分割線にくっつける**(下記「ペインの表示/非表示」)。

メニューの中の**灰色の見出し**は、続く行たちが**何に効くか**を言う
(いまのファイル名の下に Rename と Save が並ぶ)。区切り線と違って名前を
持てるので、「どれに効くのか」が要る並びではこちらを置く。保存していなければ
`not saved yet` と言い、名前を変える相手が無いので Rename は無効になる。

書き出しだけは 2 つで**1 つの塊**に見せる — 1 つの操作の 2 面
(出し方 / 選び直し)だから。ほかの帯のボタンと同じ枠なしの字のまま、
**継ぎ目の 1 本だけ**が仕切りになる(`.group`)。継ぎ目はボタンの縁ではなく
浮かせた短い 1 本(上下に余白を持つ)なので、縁と見分けが付かない、と
いうことにならない。左が「いまの出し方」で押せばそれ、`⌄` で選び直す —
選ぶだけの矢印には**字の分の横幅はいらない**ので、絵 1 つぶんまで細くする
(`.icon-only`)。
**形式が文字、行き先が絵**(落とすのか、貼れるようにするのか)で、絵は
形式ではなく行き先に付く。

絵は `src/icons.ts` が唯一の源で、**字形ではなく線で引く** — ⤓ や ⧉ は
環境によって在ったり無かったり、太さも大きさも揃わない。色は `currentColor`
なので hover も disabled もテーマも CSS 側だけで面倒を見られる。

**Undo / Redo に帯のボタンは無い**。`Mod+Z` / `Mod+Shift+Z` が本道で、
`⋯` の中が押せる保険。

`⋯` の GitHub はリポジトリを、Shortcuts は [shortcuts.md](shortcuts.md)
を、それぞれ新しいタブで開く。**操作の早見は画面に持たない** — 覚え書きは
docs 側にあり、画面には出しっぱなしにしない。

`⋯` の **Copy link** は、いまの本文を丸ごと URL に載せてクリップボードへ置く
（`src/app/share.ts`）。クエリ(`?`)ではなく**フラグメント(`#md=...`)** —
フラグメントはブラウザから外へ一切出ないので、サーバのログにも、外部リンクを
踏んだ先の Referer にも本文が漏れない。中身は gzip 圧縮してから
base64url。保存の有無を問わない — まだ保存していない文書も、見出しから
導いた仮の名前のまま渡せる。

リンクを踏むと mmm 自身が開き、起動時にハッシュがあればそれを**未保存の
新規文書**として読み込む(このときだけ前回ファイルの復元をしない)。
読み込んだらその場でハッシュを消す(`history.replaceState`) — 文書の身元は
あくまでファイルハンドル 1 つで、リンクは入口でしかない。残すと URL 自身が
2 つ目の身元になり、打った瞬間から嘘になる。

画像は旅をしない — `![](...)` は相対パスなので相手の環境には無い。貼って
ある文書でリンクをコピーすると、そう伝える(`hasImages`)。長さも拒否は
しない。相手側の実際の上限は mmm には分からないので、8000 字を超えたときは
「切られるかもしれない」とだけ伝える。

ブランドカラーは、ヘッダーのロゴをクリック(またはフォーカスして
`Enter`/`Space`)しても選べる。`⋯` の行はそこへの近道 — ロゴが押せることは
佇まいからは読めないので、探す場所をもう 1 つ用意した。

### 狭いとき

`720px` を切ると**居場所が 2 つになる** — md だけか、マップだけか。「両方」は
消える(並べられない幅で残すと、状態が 2 つになって食い違う)。ファイル名も
隠す(タブが言っている)。

**分割線は線としての性質だけを落とす**(0 幅・背景無し・掴めない・ドラッグでの
幅変更も無い)。要素そのものは残るので、`‹ ›` はいつもと同じ 1 か所に居られる。
居場所が 2 つなら行き先も 1 つしかないので、「押せないなら出さない」により
**画面に出る矢印は常に 1 本**になる。切り替えは `Alt+1` / `Alt+2` / `Mod+/`
もそのまま担う。

- **New / Open / Save / Save as**: ヘッダーの **Files**、`Mod+Alt+N` / `Mod+O` / `Mod+S` / `Mod+Shift+S`
  (`Mod+N` はブラウザの「新規ウィンドウ」に吸われがちなので `Alt` を足してある)。
  `.md` のドラッグ&ドロップでも開ける。
  新規と開くは、未保存の変更があれば確認してから捨てる。
  **Rename** も同じ Files の中(キーは無い — 押す機会がそれだけ稀)
- 起動すると**前回のファイルを開き直す**(IndexedDB に覚えたハンドルから
  ディスクを読み直す)。許可の再確認が要るときは、ヘッダーのファイル名欄を
  クリックすると開く
- **外部変更は追わない。** 他所で書き換えたら開き直せば最新になる、それだけを
  約束する(ブラウザに `notify` 相当が無く、ポーリングは「見張っているようで
  見張れていない」ので持たない)
- `Mod` は `Ctrl` / `Cmd` どちらでも同じ
- 大文字のキー(`Shift+H`)は**実際に Shift を押している**ときだけ効く。
  CapsLock で `h` が `H` になっても折り畳みには化けない

#### 文書の名前

「無題」という状態は持たない。**名前は本文から導く**ので、`# 設計メモ` と
打った瞬間からその文書は `設計メモ.md` と呼ばれる。同じ名前が保存ダイアログの
初期値にもなる。上から順に、最初に成立したものを使う:

1. **保存したファイル名** — 開いた/保存した後は常にこれ。見出しを書き替えても追わない
   (ファイル名はディスク上の識別子、見出しは内容の名前。役割が違うので一致させない)
2. **いちばん大きい見出しのうち先頭** — 文書内で `#` がいちばん少ないもの。
   同じ大きさが並べば先に書いたほうが勝つ。`##` しか無ければそれがいちばん大きい
3. **(2 が整形で空になったら) 文書順で最初の見出し**
4. **`empty`**

ファイル名に使えない文字(`\ / : * ? " < > |` と制御文字)は落として `-` で繋ぐ
(`設計/検討` → `設計-検討`)。空白はそのまま残す。長さは UTF-8 250 バイトで
打ち切る — `.md` を足しても実際の上限 255 に収まるようにするためで、
見た目を整えるためではない(日本語 83 文字ぶんあり、普段は触れない)。
道具が出す名前は**常にファイル名として有効**であることを守る。

**リネームは Files の中にある。** 開いているファイル**そのもの**の名前を、
同じフォルダの中で変える(`FileSystemFileHandle.move()`)。`Mod+Shift+S` とは
別の操作 — あちらは**写しを作る**ので元のファイルがそのまま残る。
保存していなければ名前を変える相手がディスクに無いので、その行は無効になる。

`move()` は Chromium だけが持つ。mmm は元から Chromium 限定なので前提は
変わらないが、無い環境で黙って何も起きないのは通らないのでそう言う。

### 指で使う

**モードは無い。** 触れたものが答えを持っているので、指なら指の作法、
マウスならマウスの作法がその場で決まる(触れた瞬間の `pointerType`)。

| 指 | どこ | 何が起きる |
|---|---|---|
| 1 本 | 背景 | 動かす(パン) |
| 1 本 | ノード | 叩けば選ぶ / なぞれば動かす |
| 2 本 | どこでも | 拡大縮小(同時に動かす) |
| 長押し | ノード | 右クリックと同じメニュー |

**指では矩形選択が出ない** — 背景を 1 本指のパンに明け渡したため。
叩いて 1 つずつ選ぶ。

**ノードを足すボタン**は `⋯` の `Show add buttons` / `Hide add buttons` で
出し入れする(選び直した状態は保存される)。**主たるポインタが指で、かつ
ホバーできない機械では既定で出ている** — 物理キーボードの有無は Web から
分からないので、その代わりに使う近似(外れていれば `⋯` の 1 行で直せる)。

選んだノードの周りに `+` が出て、子はその枝が**育つ辺**に、親はその枝が
**入ってくる辺**に、上下が兄弟(`Tab` / `Shift+Tab` / `Enter` / `Shift+Enter`
と同じ)。左右どちらが子でどちらが親かは**その枝の向き**(`layout.ts` の
`dirOf`)で決まる — 左右の入れ替え(鏡映)を書いてよいのは `geometry.ts` の
`growthEdgeOf` / `entryEdgeOf` だけで、`addButtons.ts` は向きを渡して結果を
そのまま使うだけ。ルートは深さ 1 の見出しを親で包めないので、その口は
出ない。上下は左右と置き方が違う — 左右(子・親)は縁の外へ 26px 離すが、
上下(兄弟)は縁ちょうどに置く。兄弟どうしの縦の間隔は 10px しかなく、横と
同じだけ外へ出すと隣のノードに食い込むため。

**ファイルピッカーを持たないブラウザでは、開けない・保存できない。**
`docs/web.md` のとおり 2 本目の道は作らない。`Files` の該当行は理由とともに
無効になり、同じ機能をキーボードショートカットで呼んでも黙って何も起きず
**同じ理由が画面に一瞬出る**。書いて書き出すことはできる。

これは**指かどうかとは別の軸**。Android Chrome はピッカーを持つので電話でも
全部できるし、デスクトップの Firefox / Safari は指と無関係にファイルだけ落ちる。
どこまで届くか、届かない側で何をするかは `docs/browsers.md`。

### 木の書き方 — 見出しとリスト

同じ木を `#` でも `-` でも書ける。**マップはどちらでも同じに見える。**

```
# root                    - root

## branch A          ⇄      - branch A
[記事](https://…)             [記事](https://…)

### leaf                      - leaf
```

読みは**常に両方を構造として受ける**。見出し `#+`(本数無制限。7 本以上は
md の制約の外だが、mmm はそのまま積める)と、リスト項目 `-` `*` `+`。
リストの深さは「直近の見出しの深さ + 1 + 入れ子段数」で、**見出しは入れ子を
リセットする**。入れ子は字下げのスタックで数えるので、他所の 4 スペースも
タブも読める。「本文」という概念は無い — `- x` は必ずノード
(mmm は散文を編集する道具ではない)。

**書き方はモードが決める。** モードは「深さ b 以上をリストで書く」の
b ひとつで、md ペイン右上の 3 ボタンで替える:

| ボタン | b | 書かれ方 |
|---|---|---|
| **H** | ∞ | 全部 `#` |
| **n+** | 1〜6(押すたび巡回) | 深さ n 未満は `#`、n 以上は `-` |
| **L** | 1 | 全部 `-` |

押すと文書ぜんぶがその正規形に書き直される。1 回の undo で戻る。
**同じモードをもう一度押す = 整形**。

リストの形では、**外の Markdown パーサが同じ木に読めること**まで面倒を見る:
中身の行は項目の中身の列まで字下げし、ラベルと中身の間には空行を置き、
兄弟の間は詰める(CommonMark の tight list)。どれか 1 つでも崩れると、
外のパーサはそこでリストを閉じ、続く項目は別のリスト・深い字下げは
コードブロックに化ける。フェンスの中はコードなので、字下げは塊ごと動かし、
空行には触らない。
マップからの追加・編集(`Tab` / rename / D&D / 段の上下)が書く行も、
このモードに従う。

モードは**ファイルを開いたときだけ**自動で判定される(リスト項目が現れた
最も浅い深さ。無ければ H)。開いたあと md をどう手打ちしてもモードは
動かない — 混ざった文書も読みは正しく、揃えたくなったらボタンを押す。
モードはどこにも保存されない。テキストが真実で、次に開けば再検知される。

### 右クリックメニュー

**入れ子は「まとめた名前そのものが、いちばん普通の 1 つでもある」形**にする。
`Add ▸` は触れば開いて Child / Below / Above / Parent が選べ、**押せばその場で
子ノードが増える**(子の追加は他の 3 つより桁違いに多いので)。`Export ▸` は
どれか 1 つが普通ということが無いので、開くだけ。

**載せないもの**: 1 段下げ / 1 段上げは D&D で足りる(複数選択なら
`Tab` / `Shift+Tab`)。画像フォルダは文書ぜんぶの設定なのでヘッダーにある。

平らに並べると 24 行まで伸びるので畳んである。器はメニュー自身が持つ —
子メニューも同じ `ContextMenu` で、置く場所が親の行の隣になるだけ
(右に入らないときは親の左へ回る)。

### レイアウト規則

- `#` 見出しは**いくつあってもよい**。2 つ目以降はそれぞれが**独立した別ツリー**になり、
  マップ下部に順に積まれる(以前は構造から外していたが、テキストに在るのにマップから
  消えて選択も移動もできなかったため改めた)
- `#` より**前**に書かれたノード群も同じく**別ツリー**として下部に表示される
- ルート直下の枝は `---` で**グループ**に分かれる。**`---` 1 本 = 分割**(同じ側の
  次のグループ)、**2 本以上 = 分割 + 左右の切り替え**(そこから先はルートの反対側)。
  同じ側の列の中では、グループの継ぎ目に薄い線が 1 本出る
- 区切りとして効くのは「直前にノードがあり、直後の見出しがそのルートの直下」の
  ときだけ。文書の頭(frontmatter)・木をまたぐ `---`・深い階層の `---` は
  ただの本文の行
- 区切り行は**どのノードの範囲にも属さない**(コピーや移動に付いてこない)

### マインドマップ側

**同じことをする道は 1 本だけ**にしてある。vim キー(`hjkl` `dd` `yy` `gg` `u`…)は
持たない — 矢印 / `Enter` / `Tab` / `Mod+X C V Z` に一本化した。キーの一覧は
[shortcuts.md](shortcuts.md)、ここでは動作の細かい意味だけを言う。

**編集** — 編集開始(`Mod+Enter` / ラベルをダブルクリック)はカーソルが末尾に付く。
編集確定に**キャンセルは存在しない**(編集中の `Tab` は無効)。編集中ノードの
クリックはカーソル移動だけで、確定はしない。

**新規作成**(`Enter`/`Shift+Enter`/`Tab`/`Shift+Tab`、選択ノードの `+`)は作成後
そのまま編集開始する。**名前がまだ無いノードでは「足す」より「埋める」が
先に来る。** 空のノードを選んで `Enter` を押すと、兄弟を足さずにそのノード
の編集に入る(空のまま足しても名無しが 2 つ並ぶだけで、次に打つ場所が
決まらないため)。さらに**そのまま打ち始めれば、その文字から書ける** —
`Enter` を挟まなくてよい。名前のあるノードでは何も起きない(打鍵でラベルを
壊さない)。

**構造・選択** — `Mod+V` の中身は、見出しつき md なら**子ツリー**に、ただの
テキストなら**行ごとに子ノード**に、URL 単体なら**そのノードの内容**
(リンクカード)に、画像は保存して `![]()` を挿入する。`Shift+H` はサブツリー
の折り畳み/展開(コメントアウト、下記)、`Shift+D` はその場で描いて画像として
貼る(下記)、`Shift+L` はクリップボードの URL をリンクとして貼り**そのまま
題を打てる状態**にする(下記)。`Alt+←→` はブラウザの戻る/進むなので使わない
(並べ替えは `Alt+↑↓`)。`↑↓`/`←→` は**同じ深さの列**を上下移動(いとこも
含む・端でループ)/親・子へ移動。

| マウス操作 | 動作 |
|---|---|
| クリック / `Shift+クリック` / `Mod+クリック` | 選択 / 範囲選択(文書順) / 追加・解除 |
| 空白ドラッグ / `Space+ドラッグ` / 中クリック | 矩形選択 / パン / パン |
| ホイール / `Shift+ホイール` / `Mod+ホイール` | 縦スクロール / 横スクロール / ズーム(カーソル基点) |
| `Home` / マップ左上の的ボタン | 選択(無ければルート)を画面の中心へ寄せる(拡大率は変えない) |
| ノードをドラッグ | 上 = 子、間 = 兄弟挿入、**右(子の伸びる方向)= 子**(インジケータ表示) |
| `Shift+ドラッグ` | A→B の線に落として **A→C→B と割り込む**(親の挿入) |
| ルートの脇へドラッグ | その側の末尾へ(要るときだけ `---` が書かれる) |
| `Mod` を押したままドロップ | そこに**新しいグループ**(既存のグループの真ん中なら割って入る) |
| 右クリック → Flip side | そのグループを丸ごと反対側へ |

### コンテンツカード(リンク / コード / SVG / 画像)

ノードの**添付コンテンツ**(見出し直下の本文)は、内容に応じてノード下部に
カード行として縦に積まれる(**枚数の上限は無い**):

- `[タイトル](URL)` または素の URL の行 → リンクカード。`↗` クリックで新しい
  タブで開く(外部通信はしない)。ラベル自体が URL のノードはただのテキスト
- ` ``` ` フェンスのコードブロック → モノスペースのプレビュー(6 行まで、
  以降は `…`。言語はツールチップ)。**色付き** — CodeMirror の言語一覧
  (`@codemirror/language-data`、143 言語)をそのまま使う。**各言語は
  実際に文書へ出てきたときに読み込む**ので、最初のバンドルには入らない
  (読み終わってから色が載る)。知らない言語は色を付けない。その場編集でも
  **色が付いたまま**(裏に色付きの層、表に透明な textarea を重ねてある)
- `<svg>…</svg>` ブロック → そのまま描画(data URL 経由の静的表示)
- `![](相対パス)` → 画像サムネイル(下記)

リンクやコードを足したいときは **MD ペインに打つ**。同じことをする道を
2 本持たないため、専用のポップアップは持たない。

**選択・編集**(4 種のカードすべてで共通の道具立て。キーの一覧は
[shortcuts.md](shortcuts.md))

カードはノードとは別に、それ単体で選べる。ノードの選択とカードの選択は
**どちらか一方だけ**が常に成り立つ(片方を選ぶと、もう片方の選択は外れる —
2 種類同時に選ばれていると `Delete` や `Alt+↑↓` が何に効くのか決まらない
ため)。選んだカードは MD ペイン側でも元の行がハイライトされる。

| マウス操作 | 動作 |
|---|---|
| カードをクリック | 選ぶ / もう一度で外す |
| カードをダブルクリック | その場で編集 |
| 選んだカードをドラッグ | 別ノードへ移動 / ノード内で順番変更 |

選んでいるカードには枠が付き、枠の右上角に重ねて **×** が出る(押すと上の
`Delete` と同じくその行を消す。`Mod+Z` で戻る)。その場編集は、カードに
ぴったり重なる入力欄にそのカードの元テキストをそのまま載せる。`Enter` は
改行で、確定は `Esc` / `Mod+Enter` / 他所をクリック(キャンセルは持たない)。
入力欄を開いている間の `Mod+Z` は**その欄の中の取り消し**で、文書の undo は
動かない(開いたままの入力欄が指す範囲だけ古くなり、確定で別の場所を
上書きしてしまうため)。
コードカードだけは中身に ` ``` ` の**開きと閉じも含む**ので言語の指定も
その場で直せるが、**囲いそのもの（バッククォート）は打ち消せない** — 言語名
だけが開けてある(直せることがその場で編集する理由の半分で、囲いを壊す
必要はないため)。他の 3 種にはこの制限は無い(囲いを持たないので)。

ドラッグで掴めるのは**選んでいるカードだけ** — 選んでいないカードを掴むと、
これまで通りノードが動く(2 つの意味を 1 つの掴みに乗せない)。落とし先は
ドロップ位置に出る線で示す。動かした先でもそのカードは選ばれたままなので、
続けて `Alt+↓` を押せば同じカードが動き続ける。

### 画像(ローカルファースト)

画像は md の**相対パス**で書く(`![](./x.webp)`、`![](../pics/y.png)`)。
ただしブラウザはファイルのハンドルから親フォルダへ辿れないので、
**画像を置くフォルダを 1 度だけ選んでもらう**。

**フォルダを選ぶとき(初回だけ)**

1. フォルダを 1 つ選ぶ。**どこでもよい** — md を含むかどうかをアプリは調べない
2. **保存パス**を聞く(初期値 `./`)。これは「**md から見て、選んだフォルダが
   どこにあるか**」の宣言で、フォルダと一対のもの。だからフォルダを選び直す
   ときにしか聞かない

**画像を置くたび**

3. **名前**を書く(初期値は日時。`assets/shot` のように `/` を入れれば
   選んだフォルダの下にサブフォルダを作る)
4. WebP に変換して選んだフォルダへ書き、本文に
   `![](保存パス + 名前.webp)` を挿入する(1 回の Undo で戻せる)

md と同じフォルダを選んで `./` のままなら、何も考えなくて合う。`../pics/` に
貯めたいなら `pics` を選んで保存パスに `../pics/` と書く。

読むときも同じ宣言を使う。本文の `![](p)` が保存パスで始まれば、その残りを
選んだフォルダの中に探す。始まらなければ点線のプレースホルダにファイル名で
出す。フォルダを選ぶ / 選び直すのは**ヘッダーの Images** — どのフォルダに
画像が居るかは**文書ぜんぶの設定**なので、New / Open / Save と同じ **Files** に置く
(画像カードのクリックは選択に使うので、そちらには載せない)。

**宣言が実際の配置と食い違っていても、アプリは気づかない。** アプリの中では
辻褄が合って見え、ディスク上の md だけが嘘になる。これはユーザーの責任。

入り口は 3 つ。**ノードの上に画像ファイルをドロップする**、ノードを選んで
`Mod+V` で貼る、**その場で描く**(下記)。どれも 3 と 4 を通る — 置き場所も
名前の付け方も 1 か所が持つ。ノードの外に落としたものは受け取らない
— どこに付いたか分からない貼り方はしない。`.md` を落としたときはその md を開く。

現在ファイルを保存済みであることが要る(未保存だと相対パスの基準になる場所が
無い)。`https://` の画像は外部通信になるため表示しない。md 側の記述はただの
相対パス画像なので、他のエディタや GitHub でもそのまま表示できる。

#### 名前を付けてリンクを貼る

ノードを選んで `Shift+L`(または右クリックメニューの **Link**)で、クリップボードの
URL が `[](url)` の形で本文に入り、**カードの入力欄が題の上で開く**。そのまま
名前を打って `Mod+Enter`。クリップボードが既に `[題](url)` なら題を選んだ状態で
開くので、Enter で残すか、打ち直すかを選べる。リンクでなければ何も入れずに知らせる。

ポップアップは作らない。**既にあるカードの入力欄をそこで開くだけ**なので、
道は増えていない — `Mod+V` で貼ってから直すのと同じ場所へ、1 手で着く。

文書に書くのは `[](url)` で、**題は空のまま**。題が無いときにホスト名を出すのは
`parseLink` の**見せ方**の話で、文書に書く文字ではない(`linkLine` が
その線引きを持つ)。

#### その場で描く

ノードを選んで `Shift+D`(または右クリックメニューの **Draw**)で、描くための
窓が開く。描いたものは上と同じ道を通って WebP として保存され、そのノードの本文に
`![](保存パス + 名前.webp)` が入る。**mmm の中に描く道は他に無い**ので、これは
2 本目の道ではない。

道具は**塊が 3 つ**。左に「何で描くか」と「どのくらいで」、右へ離して
「やり直す」を置く — 描くために選ぶものと、描いたものを取り消すものは
種類が違う。

| 道具 | |
|---|---|
| インク | 色 5 つと消しゴムが**同じ並び**の丸。1 つだけが選ばれる |
| 太さ | 細・中・太の 3 段。ボタンには**その太さの点**が出る(字で「2px」と書かない) |
| 取り消し | `Mod+Z` またはボタン。**一筆ずつ**戻る(「クリア」も戻せる) |
| クリア | 全部消す |

**消しゴムは紙の色のインク**でしかない(実装も色と太さを差し替えるだけ)。
同じ並びに置いてあるので、色を選べばそれだけでペンに戻る —
「消しながら色を選ぶ」のような、意味の無い組み合わせが最初から作れない。
色を持てないので、丸の中身だけが絵になる(絵は Feather Icons の `eraser`
の座標を比率どおり縮小したもの)。

**色は決め打ちで、太さは 3 段しか無い。** OS のカラーピッカーと生のスライダーは
「何でも選べます」としか言っておらず、選ぶ手間だけを渡してくる。紙の上で
読める色だけを並べ、**選べるものを絞ることを道具の言い分にする**。

末尾の 1 本は**ブランドカラー**(ロゴと同じ `--accent`)。綴りは持たないので、
色を変えれば筆も変わる。既定にはしない — 淡い色を選ぶと紙の上で消えるため、
選べば使えるが黙って選ばれてはいない。

**太さの 3 段が何 px になるかは、インクが決める**(ペンは 2 / 4 / 8、消しゴムは
8 / 16 / 24)。消しゴムはペンと同じ太さでは細すぎて使えないが、掛け算を隠すと
「細を選んだのに太い」になる。だから**ボタンの点も一緒に太る** — 見えている
点が、出てくる太さ。

確定は `Mod+Enter` か確定ボタン、**破棄は `Esc` かキャンセルボタン**。

マップ側の入力欄は「確定のみでキャンセルは存在しない」が、ここだけは違う。
あちらは**すでに文書に在るもの**を直すので戻す先があるが、こちらは確定するまで
文書に何も無く、引き返せないと逃げ場が無いため。

### Hide/Show = 折り畳み(コメントアウトで無効化)

`Shift+H`(または右クリックメニュー)で選択ノードのサブツリー全体を
`<!--` / `-->` の行で包む。md としてはただの HTML コメントなので
**GitHub などの外部レンダラでは消える**。

マップ上では**折り畳みを兼ねる**:

- 対象ノードは小さく薄く表示され、`+3` のように**折り畳んだ子孫の数**が付く
- **子孫はマップから消える**(レイアウトからも外れるので場所を取らない)
- そのノードで `Shift+H` をもう一度押すか、右クリックメニューの
  「再表示」で戻る

マーカーの判定は**エディタや GitHub と同じ**にしてある: `<!--` は追加の
ハイフンが付いていてもよく(`<!---`)、閉じ側は 2 個以上のハイフン + `>`
なら閉じる(`-->` `--->` いずれも可)。ハイフン 1 個の差で「閉じたつもりが
閉じておらず以降が全部消える」のを避けるため。コードフェンス内は対象外。
入れ子の Hide は不可(既にマーカーを含むサブツリーの Hide は無視される)。

### ペインの表示/非表示

移動には**別々の 2 つの軸**がある。混ぜない: **見え方**(どのペインが
出ているか)は分割線の矢印か `Alt+数字`、**フォーカス**(どのペインに打鍵が
届くか。隠れていれば出してから移る)は `Mod+/`。キーは
[shortcuts.md](shortcuts.md)。

`Alt+数字` は各ペインの表示トグルで、番号は左からの並び順。MD を編集中でも
効く(最後の 1 枚を隠すと反対側が表示される)。

**見え方は「分割線の居場所」ひとつで言い切れる。** 「両方消えた」は作らない
ので、辿り着ける形は 3 つしかなく、左から順に並べればそのまま分割線を
左右に動かす話になる:

```
md 無し   ←   両方   →   マップ無し
（左端）      （中）      （右端）
```

だから**矢印は向きを変えない**。`‹` はいつでも「分割線を左へ 1 つ」、`›` は
いつでも「右へ 1 つ」。何が起きるかはツールチップが言う(`Hide the map` /
`Show the Markdown pane` など)。**端では、その先の矢印は消える** — 押して
何も起きない一手を、沈んだ姿で誘わない。

矢印は**分割線の下端**に横に 2 つ並ぶ。真ん中は本文と地図のいちばん見たい
ところなので、そこには浮かせない。**分割線そのものは隠さない** — 片方の
ペインを消しても、残りが flex で埋まるぶん分割線がそのまま境目まで押し出
されるので、矢印はいつも同じ 1 か所に居られる(角と角に分けると、片方だけ
スクロールバーを避けた分ずれて見える)。片方だけになると分割線は窓の縁に
来るので、矢印もその内側へ寄る。

スプリッタは両方表示のときドラッグで幅を変える。**片方だけのときは、
押せば分割へ戻る** — 動かす幅が無いので掴んでも何もできないが、縁に寄った
分割線はそこに見えているので、細い矢印 1 つを狙わせるより易しい取っ手に
なる(カーソルもそのとき押す形に変わる)。

矢印キーは割り当てない。`Ctrl+←→` はテキスト欄の単語移動で、書いている
最中に一番使うため。`Ctrl+数字`(タブ切替) / `Ctrl+J`(ダウンロード) /
`Ctrl+Shift+R`(再読込) はブラウザの予約で、`Ctrl+\` は JIS 配列で位置が
変わる — 消去法で残るのが `Alt+数字`(JetBrains と同じ体系)。
どちらを出しているかは覚えない — 起動は毎回、両方から。

### ペインをまたぐ印

**どちらのペインに居るかで、どちらが指すかが決まる。**

| フォーカス | 何が出る |
|---|---|
| マップ | 選んでいるノード(またはカード)の範囲が、md 側で薄く塗られる |
| md | カーソル(と選択)が掛かっているノードの**内側**に、もう 1 本の輪が出る |

**md 側の印はテキスト選択ではない**(CodeMirror の装飾)。実選択にすると
カーソルを奪うので、マップを触っただけで書いていた場所が飛ぶ。実選択は
フォーカスが外れると描かれもしないので、見せるには結局この装飾を作り直す
ことになる。

**マップ側の印は選択ではない。** 操作の対象(`Delete` / `Tab` / `Alt+↑↓` /
Export の範囲)は選択だけが決め、カーソルが動いても入れ替わらない。地図も
動かさない — 打鍵のたびに寄せると、書いている手元が揺れる。

**その輪が箱の内側に在ることが、選択との違いそのもの。** 外から掴むのが
選択で、中に居るのがカーソル。だから濃さで competing せずに済み(同じ軸に
乗せると「強い枠 / もっと強い枠」の勝負になる)、両方が成り立つときも
外が選択・内がカーソルでそのまま両方読める。塗りで差をつけると、選択の
塗りに上書きされてここが言えなくなる。

濃さは**この輪だけが持つ**。`--accent-soft` は面を塗るための薄さで
(md 側のハイライトも矩形選択も面)、2px の線に当てると消える。内側に居る
以上は選択と紛れようがないので、線として読める濃さでよい。
輪はノードの子ではなく、world に浮かぶ別の印
(`CardPick` と同じ) — 子にすると、カーソルが動くたびにそのノードの中身が
丸ごと作り直される。本数が変わったときだけ作り足して余りを捨てる
(グループの継ぎ目と同じ)。

どれに付くかは、**そのノード自身の文に掛かっているかどうか、それだけ**
(`src/caret.ts`)。自身の文とは見出しの行と、子に取られていない本文
(あいだの空行も含む — コアの `contentEnd` は次のノードの直前まで伸びる)。
これで文書は隙間なく分かれるので、点でも範囲でも複数カーソル
(`Alt+クリック`)でも同じ 1 つの規則で言える。文書の頭・最初の見出しより
前の散文・区切り行には何も出ない — そこはどのノードの文でもない。

**子孫まで含む `to` で見てはいけない。** ノードの区間は入れ子なので、
カーソル 1 つでもルートまでの祖先が全部光る。実際にそう作って試したが、
**マップの上では選ばれているのと見分けが付かなかった**(印の数も語彙も
選択と同じになる)。道筋を見せる価値より、選択と紛れない価値を採る。

**閉じ際もその中と見なす。** 区間そのものは半開だが、カーソルはその位置に
立てる(文字と文字の隙間に居る)。半開のまま読むと文書の末尾では文が閉じ
きっていて何にも掛からず、**追記しているあいだじゅう印が出ない**という、
いちばん困る形になる。裏返しとして、継ぎ目ちょうどでは両側が光る。

**畳んだ枝の中に居るときは、どこも光らない。** 掛かっているのは埋もれた
子孫のほうで、その箱はマップに無いため。光るのは**掛かっていて、かつ
描かれているもの**だけ、という一言で済む。

### エクスポート

**入口が範囲を決める。**

| どこから | 書き出す範囲 |
|---|---|
| ヘッダーの書き出しボタン(`SVG ⤓ ▾`) | 常にマップぜんぶ |
| 右クリックメニューの **Export ▸** | **選んでいる枝**(その子孫ごと)。何も選んでいなければ全体 |

新規 / 開く / 保存 が文書ぜんぶを相手にするのと同じ高さにヘッダーを置き、
「これ」を相手にする操作は右クリックへ寄せた。ボタンを見て範囲が分かる。

枝が「その子孫ごと」なのは、mmm では「選ぶ」がどこでも枝ごとを意味するから
(コピー・カット・削除・移動)。書き出しだけ別の意味にはしない。畳んだまま
書き出せば畳んだ姿が出る。どちらも一時的な UI 状態(選択・ドロップ印)は
含まれない。

**出し方はどちらも同じ 4 つ**で、並びの定義は `app/export.ts` の 1 か所。

| | |
|---|---|
| **Download SVG** / **Download WebP** | ファイルに落とす |
| **Copy PNG** / **Copy SVG** | クリップボードへ |

ヘッダーは**いまの出し方がボタンに出ていて**、押せばそれで出る。隣の `▾` で
選び直すとその場で出て、次からの既定になる — 押す前に何が起きるかが見える。

右クリック側は **Export ▸** の入れ子。平らに 4 行足すと右クリックが伸びるので
畳んである(入れ子の器はメニュー自身。子メニューも同じ `ContextMenu` で、
置く場所が親の行の隣になるだけ)。

**WebP はクリップボードに置けない**(ブラウザが受け取らない。`ClipboardItem`
が許すのは PNG と SVG だけ)ので、コピー側の絵は PNG になる。
SVG のコピーは `text/plain` にも同じものを載せる — Figma や Illustrator は
SVG のソースを貼られたほうが確実に開く。

SVG はスタイルとサムネイルを埋め込んだ自己完結ファイル。ラスタは **2 倍**で
描く(倍率は選ばせない — 書き出したものは画面で見えている通りであるべき)。

地は持たない(透明)。貼り先の色にそのまま乗る。右下の余白には
`made with mmm` の透かしを置く(SVG だけリンクが生きる — ラスタは絵として
焼かれるため)。

### 文字コードと改行

**UTF-8 / LF だけ**。読み込み時に CRLF も単独の CR も LF へ正規化し、
**保存も LF で書く**(元の改行へ戻さない)。クリップボードから来る文字列も
同じ規則で揃える。Shift-JIS の往復も CRLF の往復も、ネイティブだから
背負えた要求だった。

CodeMirror は読み込んだ文書の改行を内部で LF に正規化するのに対し、コアは
渡されたバイト列をそのまま保持する。両者に別々の改行を渡すと文字位置が
ずれて、打鍵が見当違いの場所に書き込まれる。これを避けるための統一。

コアが**書き足す**改行も常に LF。以前は「その文書の流儀」を毎回探していたが、
入口で LF に揃えている以上そこには辿り着けなかった(既にある行のバイト列は
従来どおり触らない)。

### その他

- `⋯` の中でライト/ダークテーマ切り替え(初期値は OS 設定、不明ならダーク)
- ヘッダーのロゴを押すとブランドカラーを変更できる(クリックでも、フォーカス
  して `Enter` / `Space` でも。favicon にも反映され、保存される)
- localStorage に残すのは**テーマとブランドカラーだけ**。本文の控えは持たない
  — 持てばディスクの .md と二重の真実になる
- IndexedDB に置くのは**ファイルとフォルダのハンドル**(ディスクへの指し示し)
  だけ。起動時にそこから**ディスクを読み直す**。許可が切れていれば
  まっさらから始まる。未保存のスクラッチは残らない
- 保存・読み込みの失敗はヘッダーのファイル名欄に表示される(キャンセルは無表示)
