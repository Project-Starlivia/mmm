# mmm — 仕様

概要・実行方法・ライセンスは [README_JA.md](../README_JA.md)（[English](../README.md)）。ここには UI の細部と挙動を置く。

## 構成

**コアが「その .md が何を意味するか」の唯一の判定者で、TS は「それをどう
見せるか」だけを持つ。** 見出し・フェンス・hide 領域の判定は core に 1 つしか
無い（同じ規則を UI 側で書き直すと、静かに食い違う）。

**型は名乗らせず確かめる。** `as T` も `!` も置かない — 外れていても誰も
気づけないため（実際 `<svg id="logo">` を `HTMLElement` と名乗り続けていた）。
`instanceof` / 型ガード / 既定値のどれかで確かめる。
（見張っていた `test/assertions.test.ts` は旧 core と一緒に消してある。
操作が戻るときに戻す）

ブラウザで動く。ファイルは **File System Access API** で 1 つずつ開き、
開いたハンドルへ上書きする。**Chromium 系でしか動かない**と言い切っていて、
ダウンロードでの保存にフォールバックしない — 2 本目の道を作ると、そちらでは
画像が死に「実体はただの .md」が壊れるため。**動く道が 1 本だけあるほうが良い。**
線が実際どこを走るか（正確には「ピッカーを持つブラウザか」で、デスクトップ /
モバイルの軸ではない）は `browsers.md`。

**フォルダを先に開かせて、その中から md を選ばせる形は採らない。** ハンドルから
親フォルダには辿れないので隣の画像にはフォルダの許可が要るが、それを求めるのは
**画像を初めて置くときだけ**。画像を使わない文書にフォルダの話をさせない。

## 開発

必要: Node.js、pnpm、[MoonBit toolchain](https://www.moonbitlang.com/download)
(`moon` が PATH にあること)

**MoonBit は最新を追う。** CI も手元も `latest` で、版はどこにも固定しない
(`moon.mod` に処理系の版を書く欄が無いので、固定するなら CI の 1 行になる —
そうすると「動いていた頃」を抱え、上げる引き金を人が覚えていなければならない)。
上流が動いて赤くなったら、手元を上げて同じ commit で直す。赤くなる形は
**整形の出す形が変わる**か**非推奨の印が増える**かのどちらか (#24)。

```
pnpm install
pnpm run dev        # コアをビルドしてから vite（http://localhost:13131）
```

- 本番ビルド: `pnpm run build` → `pnpm run preview` で確認
- コア(`core/*.mbt`)を変更したら `pnpm run core` で JS を再生成
- コアのテスト: `pnpm run test:core` / UI 側のテスト: `pnpm test`
- 型チェックだけ: `pnpm run check`（src・test・lab）
- 部品の見た目を並べて見る: `pnpm run lab` → http://localhost:13132/parts/
- 負荷サンプル（`test/fixtures/*.md`）の作り直し: `pnpm run fixtures`

### 配る

**Cloudflare Workers の静的アセット**に置く（`wrangler.jsonc`）。mmm は
ブラウザだけで動くので**サーバ側のコードは 1 行も持たない** — `main` の無い
配信だけの Worker で、ファイルは Cloudflare が直接返す。

入口は `/` の 1 つだけで、クライアント側のルーティングは持たない。だから
`not_found_handling` は `none` にしてある — 無い場所には素直に 404 を返す
（`single-page-application` にすると記法違いにもアプリを返してしまい、
「見つからなかった」ことが伝わらない）。

配り先は **`mmm.<アカウント名>.workers.dev`**（`workers_dev: true`）。書かなく
ても既定でそうなるが、選んだ結果であって書き忘れではないことを残すために
明示してある。独自ドメインへ移すときは `routes` に差し替える。

```
pnpm run deploy       # ビルドしてから配る
pnpm run deploy:dry   # ビルドしてから、配らずに設定と中身だけ確かめる
```

**`main` に入ったものは GitHub Actions が自動で配る**（`.github/workflows/ci.yml`）。
1 つのファイルに `check` と `deploy` の 2 つを置いてあり、`deploy` は
`needs: check` で待つ — ワークフローをまたぐと順番を約束できず、確かめ
終わる前に配り始めてしまう。**配るのは `check` が組んだ dist そのもの**
（artifact で渡す）で、組み直さない。確かめたものと配るものが別々になる
余地を残さないため。

MoonBit は公式の GitHub Action が無いので、配布スクリプトで入れて
`$HOME/.moon/bin` を PATH に通している。

要る Secrets は 2 つ:

| 名前 | 何か |
|---|---|
| `CLOUDFLARE_API_TOKEN` | **Edit Cloudflare Workers** 権限のトークン |
| `CLOUDFLARE_ACCOUNT_ID` | ダッシュボード右下の Account ID |

## 使い方

**画面に出る文字は英語**(ボタン・メニュー・通知)。docs とコード内のコメントは
日本語のまま — 読む相手が違う。以下では英語のラベルをそのまま引く。

### 帯と、隅に浮く道具

**帯は「文書に何かする」だけ。「いま何を見ているか」は Markdown と
Mindmap の中に置く。**

**画面に「ペイン」とは書かない。** 見えているものの名前は Markdown と
Mindmap の 2 つで、`pane` は器の呼び名(＝こちらの都合)でしかない。
コードの中(`#md-pane` / `.pane-tool` / `App::new`)だけがそう呼ぶ。

記法は **`Mindmap`** で 1 つ。英語としての正しい形は `mind map`(2 語)だが、
`mmm` = markdown / mindmap / mirror と名乗った時点でこの製品での記法は
1 語に決まっている。語の途中を大文字にする(`MindMap`)のはブランドの装置で、
そこまでは主張しない。**一般名詞としての「マインドマップ」とは別語**扱い
— [freedom.md](freedom.md) が論じているのはそちら(世に言う自由なそれ)で、
`Mindmap` は mmm の片側の名前。

```
mmm  empty.md              Files  [SVG ⤓ │ ▾]  ⋯
```

**帯は 1 本で、左は名乗り・右は道具**。ロゴとファイル名だけが左に残り、
`Files` / 書き出し / `⋯` は右へ寄せてひと塊にする — 何かしたいときに
探す場所が 1 つで済む。
**帯のボタンはみな枠を持たない字**。押すものではなく「開くところ」だと
佇まいで言う(ネイティブのメニューバーと同じ)。枠は透明のまま置いてあり、
場所だけ取らせて**水平線の 1 本にだけ色を付ける**(下記)。

`Files` は**文書ぜんぶに効くもの**を集める — New / Open / Rename / Save /
Save as と、画像フォルダ。`⋯` は**低頻度だが消したくないもの** —
Undo / Redo / アクセントカラー / テーマ / Easy grab(当たりを広げる。下記「Mindmap 側」)/
Shortcuts / GitHub。消さずに、優先度だけ下げる。3 つの塊(戻す / 見た目と手触り /
外に開く)に分けてある。

**片側にだけ効くものは、帯に出さずその隅に浮かせる**(`.pane-tool`)。
Markdown の右上には書き方(# / n+ / -)が来る(**まだ無い** — #250)。普段は沈めておいて、
触れたら起きる。
**押しても下へ抜けない** — 道具は乗っているだけで、下のキャンバスとは
別のもの(Mindmap は背景を押されると矩形選択を始めてポインタを捕まえるので、
抜けるとボタンが効かなくなる)。Markdown 側は**スクロールバーの内側**に置く。
あの帯はブラウザが押下を横取りし、`z-index` では前に出せない。

**出し分けは、隅ではなく分割線にくっつける**(下記「Markdown と Mindmap の
出し分け」)。

**ノードが 1 つも無いあいだは、両方の真ん中に始め方が出る**
(`app/parts/hint.mbt`。Markdown は `Write a # Title to start`、Mindmap は
`Press Enter to start`)。出る条件は**ノードの数ひとつ**で、
どちらも同じ — 片方だけ別の条件で消えると、同じ状態を見ているのに
食い違って見える。器も 1 つ(`.pane-hint`)。

メニューの中の**灰色の見出し**は、続く行たちが**何に効くか**を言う
(いまのファイル名の下に Rename と Save が並ぶ)。区切り線と違って名前を
持てるので、「どれに効くのか」が要る並びではこちらを置く。保存していなければ
`not saved yet` と言い、名前を変える相手が無いので Rename は無効になる。

**押す前に分かることは、押す前に言う。** 起きないと決まっている操作は、
押させて後から失敗を告げるのではなく、その入口を沈める — 沈んだ行は
**触れば理由が読める**(hover)。ただし**沈めるのは、通り道が本当に無い
ときだけ**。「保存すれば通れる」なら沈めずに、押した先で保存まで案内する
(画像の置き場所がこれ — 壁ではなく駅)。押せなさは JS が持ち、CSS は佇まいだけを
言う(`pointer-events` で止めると hover ごと死んで理由が読めない)。
同じ理由で、進めない値を打っているあいだは、たずね箱の進むボタンが沈み、
理由が入力欄のすぐ下に出る。ドラッグ中の絵は、落ちる行に線が出て、
ノードの外ではブラウザのカーソルが受けないと言う。

しらせ(`.notice`)に残るのは**やってみて初めて分かった失敗**だけになる。
出るのがそれだけになったので、「しくじりかどうか」の分岐も持たない —
役はいつも `alert`(読み上げにすぐ割り込む)で、頭にはいつも印が座る。

そのうえで、起きなかった理由には**向きが 2 つ**ある。**言うのは印の形で、
色は増やさない** — 危険色を 1 つ足せば「その色＝まずいこと」を覚えてもらう
話になるし、形なら、テーマにも色覚にも寄りかからない。縁も浮くもの共通の
`--line` のまま。読み上げにはどちらも `alert` で出す(頼んだことが起きな
かったのは同じで、待たせる理由が無い)。

| | 印 | 何を言っているか |
|---|---|---|
| `failed` | 丸(`circle-alert`) | **こちらが果たせなかった。** 鳴らすのではなく、認める — 気をつけるべきだったのは読む人ではないので、道路標識の三角は使わない。頭に **`Sorry...`** が付き、字は `Couldn't …`(`Could not` はログの口調) |
| `blocked` | 三角(`triangle-alert`) | **先へ進めない。次の一手はそちらにある。** 相手へ向けて言う三角がここでは正しい(動くのは相手) |

詫びは**文言ではなく `failed` の側が持つ**。言葉ごとに書くと足すたびに
付け忘れるし、詫びるかどうかは文言ではなく向きの話。末尾が `...` なのは、
言い切って区切るのではなくそのまま続けて言うため(文言のほうが `—` を
持っていることがあるので、`—` は使わない)。

**器の中は 3 つ**(`.icon` / `.lead` / `.msg`)。印と詫びが 1 つの塊で、文言は
そこから離れて立つ — あいだ(12px)は塊の中(4px)よりはっきり広い。近さは
「仲間である」と言ってしまうので、仲間でないものは近づけない。

**入れ物は、意味を持つか CSS で言えない境目があるときだけ置く。** 束ねる器は
持たない — 伸びるのは `.msg` だけなので、折り返しても印と詫びは離れない。
`.lead` / `.msg` が `div` ではなく `span` なのも同じ理由で、flex の中では
どちらも同じに敷かれるが、`div` は「段落だ」と嘘をつく。器そのものが
`div role="alert"` なのは、HTML に「しらせ」のタグが無く、`<output>` は
`role="status"` に落ちてしまうため(こちらはすぐ割り込む `alert` が要る)。

揃えるのは**まん中**。印と詫びが掛かっているのは文言の 1 行目ではなく
**言っていること全体**なので、行に付けにいかない — 折り返して 2 行になっても
器の高さのまん中に居る。

**ほとんどは `failed`。** 「保存が先」も「リンクとして読めない」もこちら —
置き場所を持たない文書に画像を収めると言ったのも、貼られた字をリンクとして
読むと言ったのもこちらで、相手の不注意ではない。`blocked` は**次の一手が
相手にあるときだけ** — 書き出すものが無い(ボタンは沈めてあるのでキー(`Mod+E`)から
来た人にしか出ない。触って読める言葉と同じものを出す)と、貼る先のノードを
選んでいない(`Select a node to paste … into`。選べば通る)。

書き出しだけは 2 つで**1 つの塊**に見せる — 1 つの操作の 2 面
(出し方 / 選び直し)だから。ほかの帯のボタンと同じ枠なしの字のまま、
**水平線の 1 本だけ**が仕切りになる(`.group`)。水平線はボタンの縁ではなく
浮かせた短い 1 本(上下に余白を持つ)なので、縁と見分けが付かない、と
いうことにならない。左が「いまの出し方」で押せばそれ、`⌄` で選び直す —
選ぶだけの矢印には**字の分の横幅はいらない**ので、絵 1 つぶんまで細くする
(`.icon-only`)。
**形式が文字、行き先が絵**(落とすのか、貼れるようにするのか)で、絵は
形式ではなく行き先に付く。

**字の隣に置く絵は、行箱ではなく字の見えている塊に合わせる**(2px 下げる)。
行箱は字の上にアクセントぶんの余りを抱えていて(Segoe UI は 12px の字に 13px
の ascent を取るのに、大文字の高さは 9px)、そのまま中央に置くと絵だけが
浮いて見える。当てないのは 2 つ — **絵だけのボタン**(隣に字が無く、器の中央が
正しい)と、**帯の書き出しボタン**(字が `SVG` `PNG` `WebP` と大文字だけで、
見えている塊が高い位置にあるぶん半分の 1px で合う)。数はどれも実測。

絵は `app/parts/icons.mbt` が唯一の源で、**字形ではなく線で引く** —
⤓ や ⧉ は環境によって在ったり無かったり、太さも大きさも揃わない。色は `currentColor`
なので hover も disabled もテーマも CSS 側だけで面倒を見られる。

**Undo / Redo に帯のボタンは無い**。`Mod+Z` / `Mod+Shift+Z` が本道で、
`⋯` の中が押せる保険。

`⋯` の GitHub はリポジトリを、Shortcuts は [shortcuts.md](shortcuts.md)
を、それぞれ新しいタブで開く。**操作の早見は画面に持たない** — 覚え書きは
docs 側にあり、画面には出しっぱなしにしない。

`⋯` の **Copy link** は、いまの本文を丸ごと URL に載せてクリップボードへ置く
（`app/link.mbt`）。クエリ(`?`)ではなく**フラグメント(`#md=...`)** —
フラグメントはブラウザから外へ一切出ないので、サーバのログにも、外部リンクを
踏んだ先の Referer にも本文が漏れない。中身は gzip 圧縮してから
base64url。保存の有無を問わない — まだ保存していない文書も、見出しから
導いた仮の名前のまま渡せる。

リンクを踏むと mmm 自身が開き、起動時にハッシュがあればそれを**未保存の
新規文書**として読み込む(このときだけ前回ファイルの復元をしない)。
読み込んだらその場でハッシュを消す(`history.replaceState`) — 文書の身元は
あくまでファイルハンドル 1 つで、リンクは入口でしかない。残すと URL 自身が
2 つ目の身元になり、打った瞬間から嘘になる。

但し書きは**押す前に、行の右端の印で**言う。**印は 1 つ**で、中身は触れば
吹き出しに並ぶ — 何本あっても「この一手には気に留めることがある」という
同じ 1 つの話なので、印を数だけ並べると別々の物に見える。
吹き出しが**すぐ**出るのは自前で持っているから(`title` はブラウザ任せで
一拍待たされ、その間 印は「何かある」としか言えていない)。

コピーは必ず成功するので、これはしくじりではなく「渡す前に知っておくこと」
— 押した後に言っても、そのときにはもう貼れる状態になっている。

**写せたことは、しらせではなく押した行が言う。** メニューは閉じず、その行の
頭の絵がチェックへ変わる（右端の但し書きの印はそのまま残る）。手元には何も
現れない一手なので、別の場所にしらせを出して閉じるより、押した場所で
うなずくほうが近い。解除は無い — 行はメニューが開いているあいだしか無く、
閉じて開き直せば建て直される。

**閉じないものはもう 1 つある — 切り替え。** テーマ(`Dark theme` / `Light theme`)と
Easy grab は押しても閉じず、**並びがその場で引き直される**。押した行が次の状態を
名乗るので(`Dark theme` を押すと、その行が `Light theme` になる)、変わったことは
押した場所で読めるし、続けてもう 1 つ切り替えられる。変わったのは画面の見え方
そのものなので、閉じて確かめに行く理由が無い。

**綴り直すのは並び全部**で、行が自分だけを書き換えることはしない — 書き換える形に
すると、同じ状態を「並びを組む表」と「行」の 2 か所が持つことになる。並びは開く
たびに組むものなので、切り替えのたびにもう一度組めばよい。焦点は同じ位置の行へ
戻す(行そのものは作り直される)。

チェックは**その場で引かれながら**出る(`parts/icons.mbt` の `motion`)。絵は
もともと線で引くものなので、線が引かれ切ったことがそのまま「済んだ」になる — 黙って
差し替えると、いつからそこに在ったのかが読めず、押した手応えにならない。
引く向きは**人が書く順**(短い腕の先 → 谷 → 長い腕)。

**時間のかかる一手では、引かれる前に輪が回る**(大きな Mindmap の PNG など)。
出すのは押してすぐではなく、**待たされていると分かってから**(0.2 秒) —
大半の一手はその前に終わるので普段は出ず、出してすぐ消せば点滅にしかならない。
チェックも輪も同じ場所に出て、出し入れは `parts/icons.mbt` の `nod` が 1 か所で持つ。

動きで伝えるのをやめている人には、チェックは引き終えた姿でそのまま出す。
**輪だけは止めない** — 止めた輪は「終わった」と嘘をつくので、目に障らない
速さまで落として、回っていることだけを残す。

字のまま並べないのは、**行の幅が但し書きの長さに引きずられる**から。
印なら幅は一定で、メニューの並びも頭出しも揃ったまま。

- 画像は旅をしない — `![](...)` は相対パスなので相手の環境には無い
  (木に聞く — `core/read` の `has_images`。フェンスの中の綴りは数えない)
- 長さも拒否はしない。相手側の実際の上限は mmm には分からないので、
  8000 字を超えたときに「切られるかもしれない」とだけ言う

長さは**gzip してからでないと分からない**ので、`⋯` を開くたびに本当に測る
(1ms 弱)。生の字数では代用できない — 同じ 8000 字の URL になる本文が、
中身次第で 9 千字から 10 万字まで開く。**メニューは待たずに開き**、
測り終えた時点でその行だけが埋まる。

アクセントカラーは、ヘッダーのロゴをクリック(またはフォーカスして
`Enter`/`Space`)しても選べる。`⋯` の行はそこへの近道 — ロゴが押せることは
佇まいからは読めないので、探す場所をもう 1 つ用意した。

### 狭いとき

`720px` を切ると**居場所が 2 つになる** — Markdown だけか、Mindmap だけか。
「両方」は消える(並べられない幅で残すと、状態が 2 つになって食い違う)。
ファイル名も隠す(タブが言っている)。

**分割線は線としての性質だけを落とす**(0 幅・背景無し・掴めない・ドラッグでの
幅変更も無い)。要素そのものは残るので、`‹ ›` はいつもと同じ 1 か所に居られる。
居場所が 2 つなら行き先も 1 つしかないので、「押せないなら出さない」により
**画面に出る矢印は常に 1 本**になる。切り替えは `Alt+1` / `Alt+2` / `Mod+/`
もそのまま担う。

- **New / Open / Save / Save as**: ヘッダーの **Files**、`Mod+Alt+N` / `Mod+O` / `Mod+S` / `Mod+Shift+S`
  (`Mod+N` はブラウザの「新規ウィンドウ」に吸われがちなので `Alt` を足してある)。
  `.md` のドラッグ&ドロップでも開ける。
  新規と開くは、未保存の変更があれば確認してから捨てる。
  **Rename** も同じ Files の中(キーは無い — 押す機会がそれだけ稀)。
  **ヘッダーのファイル名をクリックしても改名**できる — 名前を押したら
  名前が変わる、が読める形。保存していない / 改名を持たない環境では
  押せる顔をしない(理由は hover で出る)
- **起動時に勝手に開き直さない。** 立ち上げたら常に空から始まり、前のものを
  出すかどうかは人が決める。開く道は Files の **Recent ▸** — 知っている文書が
  最後に触れた順に並び、選べばその場で許可を取り直して開く(押されたことが
  その資格。ブラウザは押された直後にしか許可を聞けない)。
  いま開いているものは並びから外れる(開き直しても同じものが出るだけ)
- **外部変更は追わない。** 他所で書き換えたら開き直せば最新になる、それだけを
  約束する(ブラウザに `notify` 相当が無く、ポーリングは「見張っているようで
  見張れていない」ので持たない)
- `Mod` は `Ctrl` / `Cmd` どちらでも同じ
- 大文字のキー(`Shift+F`)は**実際に Shift を押している**ときだけ効く。
  CapsLock で `f` が `F` になっても折り畳みには化けない

#### 文書の名前

「無題」という状態は持たない。**名前は本文から導く**ので、`# 設計メモ` と
打った瞬間からその文書は `設計メモ.md` と呼ばれる。同じ名前が保存ダイアログの
初期値にもなる。上から順に、最初に成立したものを使う:

1. **保存したファイル名** — 開いた/保存した後は常にこれ。見出しを書き替えても追わない
   (ファイル名はディスク上の識別子、見出しは内容の名前。役割が違うので一致させない)
2. **いちばん大きい見出しのうち先頭** — 文書内で `#` がいちばん少ないもの。
   同じ大きさが並べば先に書いたほうが勝つ。`##` しか無ければそれがいちばん大きい
3. **(2 が整形で空になったら) 文書順で最初の見出し**
4. **`empty`**

ファイル名に使えない文字(`\ / : * ? " < > |` と制御文字)は落として `-` で繋ぐ
(`設計/検討` → `設計-検討`)。空白はそのまま残す。長さは UTF-8 250 バイトで
打ち切る — `.md` を足しても実際の上限 255 に収まるようにするためで、
見た目を整えるためではない(日本語 83 文字ぶんあり、普段は触れない)。
道具が出す名前は**常にファイル名として有効**であることを守る。

**リネームは Files の中にある。** 開いているファイル**そのもの**の名前を、
同じフォルダの中で変える(`FileSystemFileHandle.move()`)。`Mod+Shift+S` とは
別の操作 — あちらは**写しを作る**ので元のファイルがそのまま残る。
保存していなければ名前を変える相手がディスクに無いので、その行は無効になる。

`move()` は Chromium だけが持つ。mmm は元から Chromium 限定なので前提は
変わらないが、無い環境で黙って何も起きないのは通らないのでそう言う。

### 指で使う

**モードは無い。** 触れたものが答えを持っているので、指なら指の作法、
マウスならマウスの作法がその場で決まる(触れた瞬間の `pointerType`)。

| 指 | どこ | 何が起きる |
|---|---|---|
| 1 本 | 背景 | 動かす(パン) |
| 1 本 | ノード | 叩けば選ぶ / なぞれば動かす |
| 2 本 | どこでも | 拡大縮小(同時に動かす) |
| 長押し | ノード | 右クリックと同じメニュー |

**指では矩形選択が出ない** — 背景を 1 本指のパンに明け渡したため。
叩いて 1 つずつ選ぶ。

**ノードを足すボタン**(**まだ無い** — #48。以下は決め)は `⋯` の `Show add buttons` / `Hide add buttons` で
出し入れする(選び直した状態は保存される)。**主たるポインタが指で、かつ
ホバーできない機械では既定で出ている** — 物理キーボードの有無は Web から
分からないので、その代わりに使う近似(外れていれば `⋯` の 1 行で直せる)。

選んだノードの周りに `+` が出て、子はその枝が**育つ辺**に、親はその枝が
**入ってくる辺**に、上下が兄弟(`Tab` / `Shift+Tab` / `Enter` / `Shift+Enter`
と同じ)。左右どちらが子でどちらが親かは**その枝の向き**(core/map の
`dir`)で決まる — 左右の入れ替え(鏡映)を書いてよいのは core/map/geometry.mbt の
`growth_edge` / `entry_edge` だけで、`+` を描く側は向きを渡して結果を
そのまま使うだけ。ルートは深さ 1 の見出しを親で
包めないので、その口は出ない。上下は左右と置き方が違う — 左右(子・親)は縁の外へ 26px 離すが、
上下(兄弟)は縁ちょうどに置く。兄弟どうしの縦の間隔は 10px しかなく、横と
同じだけ外へ出すと隣のノードに食い込むため。

**ファイルピッカーを持たないブラウザでは、開けない・保存できない。**
上の「ブラウザで動く」のとおり 2 本目の道は作らない。`Files` の該当行は理由とともに
無効になり、同じ機能をキーボードショートカットで呼んでも黙って何も起きず
**同じ理由が画面に一瞬出る**。書いて書き出すことはできる。

これは**指かどうかとは別の軸**。Android Chrome はピッカーを持つので電話でも
全部できるし、デスクトップの Firefox / Safari は指と無関係にファイルだけ落ちる。
どこまで届くか、届かない側で何をするかは `docs/browsers.md`。

### 木の書き方 — 見出しとリスト

同じ木を `#` でも `-` でも書ける。**Mindmap はどちらでも同じに見える。**

```
# root                    - root

## branch A          ⇄      - branch A
[記事](https://…)             [記事](https://…)

### leaf                      - leaf
```

読みは**常に両方を構造として受ける**。見出し `#+`(6 本まで。7 本以上は
CommonMark どおり段落で、見出しにはならない)と、リスト項目 `-` `*` `+`。
**見出しは 6 段まで、階層そのものは無限** — 7 段目に着地する操作(足す・貼る・
落とす・包む)は、その部分木を項目で書く。手で `######` の下に続きを書くときと
同じ答えになる。
リストの深さは「直近の見出しの深さ + 1 + 入れ子段数」で、**見出しは入れ子を
リセットする**。入れ子は字下げのスタックで数えるので、他所の 4 スペースも
タブも読める。「本文」という概念は無い — `- x` は必ずノード
(mmm は散文を編集する道具ではない)。

**書き方はモードが決める**(**まだ無い** — #250。以下は決めで、core.md「決まっていないこと」の
Reform がこれ)。モードは「深さ b 以上をリストで書く」の
b ひとつで、Markdown の右上の 3 ボタンで替える:

| ボタン | b | 書かれ方 |
|---|---|---|
| **H** | ∞ | 全部 `#` |
| **n+** | 1〜6(押すたび巡回) | 深さ n 未満は `#`、n 以上は `-` |
| **L** | 1 | 全部 `-` |

押すと文書ぜんぶがその正規形に書き直される。1 回の undo で戻る。
**同じモードをもう一度押す = 整形**。

**項目のラベルはその項目の 1 行目。** 1 行目が段落でなければラベルは無い(空)。
途中の段落を引き上げてラベルにすると、その文字がラベルと中身の両方に出る。

**ノードの名前は md の 1 行の原文。** 地図で打った字はそのまま md に置かれ、md の字は
そのまま名前になる。`_` `*` `#` を字として使いたいときは、md ペインと同じく自分で
`\` を置く。項目の名前の先頭が `#` `>` `1.` なら、md の文法どおり別の構造(項目の中の
見出し = 子、引用、入れ子)として読まれる。

**GFM のタスクリスト(`- [ ] a`)は解釈しない。** チェックは綴りなので、`[ ] a` が
そのまま名前になる — 地図にもその字が出て、書き戻せば `- [ ] a` に戻る。CommonMark に
無い拡張を意味として持つと、読める機械と読めない機械で同じ md が別の木になる。
表と同じ線(原文のまま持つ)。

リストの形では、**外の Markdown パーサが同じ木に読めること**まで面倒を見る:
中身の行は項目の中身の列まで字下げし、ラベルと中身の間には空行を置き、
兄弟の間は詰める(CommonMark の tight list)。ラベルの直後に空の項目が続く
ときだけ、その列は詰めない — 詰めると `-` 1 本が段落の setext の下線に読まれ、
ラベルが消える。正規形は並びで変わる。どれか 1 つでも崩れると、
外のパーサはそこでリストを閉じ、続く項目は別のリスト・深い字下げは
コードブロックに化ける。フェンスの中はコードなので、字下げは塊ごと動かし、
空行には触らない。
Mindmap からの追加・編集(`Tab` / rename / D&D / 段の上下)が書く行も、
このモードに従う。

モードは**ファイルを開いたときだけ**自動で判定される(リスト項目が現れた
最も浅い深さ。無ければ H)。開いたあと md をどう手打ちしてもモードは
動かない — 混ざった文書も読みは正しく、揃えたくなったらボタンを押す。
モードはどこにも保存されない。テキストが真実で、次に開けば再検知される。

### 右クリックメニュー

**入れ子は「まとめた名前そのものが、いちばん普通の 1 つでもある」形**にする。
`Add ▸` は触れば開いて Child / Below / Above / Parent が選べ、**押せばその場で
子ノードが増える**(子の追加は他の 3 つより桁違いに多いので)。`Export ▸` は
どれか 1 つが普通ということが無いので、開くだけ。

**載せないもの**: 1 段下げ / 1 段上げは D&D で足りる(複数選択なら
`Tab` / `Shift+Tab`)。画像フォルダは文書ぜんぶの設定なのでヘッダーにある。

平らに並べると 24 行まで伸びるので畳んである。器はメニュー自身が持つ —
子メニューも同じ `ContextMenu` で、置く場所が親の行の隣になるだけ
(右に入らないときは親の左へ回る)。

### レイアウト規則

- `#` 見出しは**いくつあってもよい**。2 つ目以降はそれぞれが**独立した別ツリー**になり、
  Mindmap の下部に順に積まれる(以前は構造から外していたが、テキストに在るのに Mindmap から
  消えて選択も移動もできなかったため改めた)
- `#` より**前**に書かれたノード群も同じく**別ツリー**として下部に表示される
- ルート直下の枝の**左右は水平線が決める**。右から始まり、水平線 1 本で反対側へ
  裏返る。本数にも記法(`---` `***` `___`)にも差はない — 詳しくは「md の裁定」
- **グループという概念は無い。** 左右の切り替えだけがある
- 境界にならなかった水平線は、書かれた場所にそのまま線として残る

### Mindmap 側

**同じことをする道は 1 本だけ**にしてある。vim キー(`hjkl` `dd` `yy` `gg` `u`…)は
持たない — 矢印 / `Enter` / `Tab` / `Mod+X C V Z` に一本化した。キーの一覧は
[shortcuts.md](shortcuts.md)、ここでは動作の細かい意味だけを言う。

**編集** — 編集開始(`Mod+Enter` / ラベルをダブルクリック)はカーソルが末尾に付く。
編集確定に**キャンセルは存在しない**(編集中の `Tab` は無効)。編集中ノードの
クリックはカーソル移動だけで、確定はしない。

**新規作成**(`Enter`/`Shift+Enter`/`Tab`/`Shift+Tab`、選択ノードの `+`)は作成後
そのまま編集開始する。**名前がまだ無いノードでは「足す」より「埋める」が
先に来る。** 空のノードを選んで `Enter` を押すと、兄弟を足さずにそのノード
の編集に入る(空のまま足しても名無しが 2 つ並ぶだけで、次に打つ場所が
決まらないため)。さらに**そのまま打ち始めれば、その文字から書ける** —
`Enter` を挟まなくてよい。名前のあるノードでは何も起きない(打鍵でラベルを
壊さない)。

**構造・選択** — `Mod+C` は選んだノードの**部分木を原文のまま**(子・孫の行と
中身ごと)クリップボードへ写す。複数なら文書順に空行で継ぎ、選んだ祖先の中の
子孫は数えない。深さは付け直さない — 貼る側が断片を木として読み直すので、
どこへ貼っても相対の形で入る。`Mod+X` は写せてから `Delete` と同じ消し方をする
(クリップボードが断れば何も消えない)。`Mod+V` は字を raw のまま core に読ませる。
見出し・項目は**形だけ**運び、綴りは貼り先に従う(子が見出しなら見出し、項目なら
項目。深い所は天井で項目)。ただのテキストは**行ごとに子ノード**、画像・リンク・
コードなどの中身は**そのノードの内容**(カード。URL 1 行もリンクカード)、画像の
データは保存して `![]()` を挿入する。`Shift+F` はサブツリー
の畳み/展開(`<details>`、下記)、`Shift+D` はその場で描いて画像として
貼る(下記)、`Shift+L` はクリップボードの URL をリンクとして貼り**そのまま
題を打てる状態**にする(下記)。`Alt+←→` はブラウザの戻る/進むなので使わない
(並べ替えは `Alt+↑↓`)。`↑↓`/`←→` は**同じ深さの列**を上下移動(いとこも
含む・端でループ)/親・子へ移動。

| マウス操作 | 動作 |
|---|---|
| クリック / `Shift+クリック` / `Mod+クリック` | 選択 / 範囲選択(文書順) / 追加・解除 |
| 空白ドラッグ / `Space+ドラッグ` / 中クリック | 矩形選択 / パン / パン |
| ホイール / `Shift+ホイール` / `Mod+ホイール` | 縦スクロール / 横スクロール / ズーム(カーソル基点) |
| `Home` / Mindmap 右下の的ボタン | 選択(無ければルート)を画面の中心へ寄せる(拡大率は変えない) |
| ノードをドラッグ | 上 = 子、間 = 兄弟挿入、**右(子の伸びる方向)= 子**(インジケータ表示) |
| `Shift+ドラッグ` | A→B の線に落として **A→C→B と割り込む**(親の挿入) |
| ルートの脇へドラッグ | その側の末尾へ(要るときだけ `---` が書かれる) |
| 右クリック → Flip side | その枝を反対側へ(水平線が書かれる) |

**箱の当たりは既定で見た目どおり**(Figma 等の図形ツールと同じ)。`⋯` の **Easy grab**
を入れると、見た目は変えずに**当たりだけ箱の外へ広がる** — 四方に 41、子の見えない
端のノードは枝の伸びる向きにさらに 63(world px。ズームと一緒に伸び縮みする。数字は
`core/map/select.mbt` の `grab`)。縁を狙って外れて選択が解ける、を無くすための好みで、localStorage に持つ。
帯が被れば見た目の箱に直線距離で近い方。ただし端の伸びだけで届く箱が居るときは行で
読む — y の近さ、同じなら x の近さ(端の伸びは横に長く、直線距離では隣の行の箱に
負けてしまうため)。同じ近さなら文書順の後ろ。選んでいる数では変えない。

**落とし先は 6 つの数字で決まる**(world px。数字は `core/map/drop.mbt`)。箱の内は
横へ `slop` だけはみ出しても内(縁を狙って外れる、を無くす)。上下の帯 `band` は
直前 / 直後の挿入を狙う幅で、隣の兄弟と重なるので近い方が取る(横のはみ出し +
縦のはみ出し × 2。兄弟軸を重く見る)。枝の伸びる向きへ `reach` まで出た通路は
「子にする」外側ゾーンで、兄弟軸には `slack` だけ箱からはみ出してよい。帯と通路が
被れば近い方、ただし通路の手前 `near`(親子の隙間 = 次の列の手前まで)は帯より強い
— 右に置いたのに兄弟になる、を防ぐ。その先は次の列の住人(前後への挿入)のもので、
列 N のノードが列 N+1 の兄弟挿入を横取りしない。誰も取らない列の上端の上 /
下端の下は、帯を `open_band` まで広げて端のノードの直前 / 直後が受ける(競う相手が
そもそも居ない場所なので、広げても何も奪わない)。無制限にしないのは、列の x に
居たまま上下に離すキャンセルの手を残すため。横は帯と同じ幅。値の出どころは記録に無い(Easy grab は実機で当てた)。ここで決めるのは規則の形だけ。

### コンテンツカード(リンク / コード / SVG / 画像)

ノードの**添付コンテンツ**(見出し直下の本文)は、内容に応じてノード下部に
カード行として縦に積まれる(**枚数の上限は無い**)。何がカードになるかの線は
「グラフィカルに扱う意思があるもの」で、散文はカードにも印にもならない —
理由は [pictures.md](pictures.md):

- `[タイトル](URL)` / `<URL>` / 素の URL だけの行 → リンクカード。`↗` クリックで
  新しいタブで開く(外部通信はしない)。**開ける先(`http(s)`)だけ**で、題を書かない
  形では URL そのものが題になる。字が混ざった行はただの本文。ラベル自体が URL の
  ノードはただのテキスト
- ` ``` ` フェンスのコードブロック → モノスペースのプレビュー(6 行まで、
  以降は `…`。言語はツールチップ)。**色付き** — CodeMirror の言語一覧
  (`@codemirror/language-data`、143 言語)をそのまま使う。**各言語は
  実際に文書へ出てきたときに読み込む**ので、最初のバンドルには入らない
  (読み終わってから色が載る)。知らない言語は色を付けない。その場編集でも
  **色が付いたまま**(裏に色付きの層、表に透明な textarea を重ねてある)
- `<svg>…</svg>` ブロック → そのまま描画(data URL 経由の静的表示)
- `![](相対パス)` → 画像サムネイル(下記)
- 境界にならなかった水平線 → 書かれた場所に細い線が 1 本
- 畳みにならなかった `<details>` → GitHub と同じ見え方。`<summary>` の字(無ければ
  `Details`)と、`<details open>` なら中身の字(6 行まで)。開閉は md の `open` が決める —
  Mindmap だけの状態は持たない

リンク(`Shift+L`)とコード(`Shift+C`)は、**Mindmap 側からも足せる**。どちらも
専用のポップアップは持たず、その場のカード入力欄が開くだけ — 器を増やさずに、
足した直後から打てる状態にする。リンクはクリップボードの URL を、コードは
空のフェンスを入れて本文行にカーソルを置く。

**字下げはコアが持つ**(`AddBlock` → `unbuild.mbt` の `list_item`)。リストの
形で書かれた文書では、フェンスの開き・本文・閉じの**全部の行**が項目の
中身の列へ入る。1 行目だけ
字下げすると 2 行目から列 0 に落ち、外のパーサはそこで項目を閉じる
(中身が空の本文行も、打ち始める場所なので同じ列に置く)。

**カードは 4 種のまま残す。** プレビュー 1 種に畳まない — 画像・リンク・コード・SVG は
出し方も触り方も違うので、1 つの「中身の絵」にすると全部が最小公倍数まで落ちる。

**選択・編集**(4 種のカードすべてで共通の道具立て。キーの一覧は
[shortcuts.md](shortcuts.md))

カードはノードとは別に、それ単体で選べる。ノードの選択とカードの選択は
**どちらか一方だけ**が常に成り立つ(片方を選ぶと、もう片方の選択は外れる —
2 種類同時に選ばれていると `Delete` や `Alt+↑↓` が何に効くのか決まらない
ため)。選んだカードは Markdown 側でも元の行がハイライトされる。

| マウス操作 | 動作 |
|---|---|
| カードをクリック | 選ぶ / もう一度で外す |
| カードをダブルクリック | その場で編集 |
| 選んだカードをドラッグ | 別ノードへ移動 / ノード内で順番変更 |

選んでいるカードには枠が付き、枠の右上角に重ねて **×** が出る(押すと上の
`Delete` と同じくその行を消す。`Mod+Z` で戻る)。`Mod+C` / `Mod+X` はノードと
同じ形で、写すのは**そのカードの原文**(地番で md から切り出した行そのもの)。
その場編集は、カードに
ぴったり重なる入力欄にそのカードの元テキストをそのまま載せる。`Enter` は
改行で、確定は `Esc` / `Mod+Enter` / 他所をクリック(キャンセルは持たない)。
入力欄を開いている間の `Mod+Z` は**その欄の中の取り消し**で、文書の undo は
動かない(開いたままの入力欄が指す範囲だけ古くなり、確定で別の場所を
上書きしてしまうため)。
コードカードだけは中身に ` ``` ` の**開きと閉じも含む**ので言語の指定も
その場で直せる。囲いを崩しても文書は壊れない — core が毎打鍵で読み直し、
囲いでなくなった字は散文として読まれるだけ(だから囲いを守る柵は置かない)。

ドラッグで掴めるのは**選んでいるカードだけ** — 選んでいないカードを掴むと、
これまで通りノードが動く(2 つの意味を 1 つの掴みに乗せない)。落とし先は
ドロップ位置に出る線で示す。動かした先でもそのカードは選ばれたままなので、
続けて `Alt+↓` を押せば同じカードが動き続ける。

### 画像(ローカルファースト)

画像は md の**相対パス**で書く(`![](./x.webp)`、`![](../pics/y.png)`)。
ブラウザはファイルのハンドルから親フォルダへ辿れないので、置き場所は
**指してもらう**しかない。

**実体は 2 つある。混ぜない。**

| | 何 | どこに在る | 役 |
|---|---|---|---|
| **宣言** | `image-folder: ./pics/`(md から見てどこか) | .md の頭 | **記録**。外(GitHub など)へ持っていく記法で、アプリを縛らない |
| **握り** | フォルダハンドル + 許可 | メモリ(IndexedDB は写し) | **動作の真実**。これが無いと読み書きできない |

パス文字列からハンドルは作れないので、**宣言があっても握りは別に要る**。

#### 画像が手に入ったとき(落とす / 貼る / 描き終える)

状態を上から見て、**足りないところだけが駅になる**。

| いまの状態 | 通る駅 |
|---|---|
| 保存済み・握りあり | フォーム |
| 保存済み・握りなし | フォルダ選択 → フォーム |
| **未保存** | **行程の箱** → 保存 → フォルダ選択 → フォーム |

**行程の箱**は「Images need a place on disk. Save the .md, then pick a folder.」
の 1 枚([Save the .md…] / Cancel)。**箱を挟むのは、保存が画像の外の操作**
だから — フォルダ選択は画像を置く一手の内側なので、前置き無しで開く。
ピッカーが 2 枚続くので、行程を先に言っておく(読まれなくても、ボタンの字が
次に起きることを言っている)。

**フォームは常に 1 枚**で、**分かっているところは字、分からないところだけ欄**:

```
  🖼 その画像
  ![](  ./pics/  [ 2026-08-30-1712 ]  .webp)
```

- 絵を出すのは、**何枚も続けて落としたときにどれの名前か**が字では読めないから
- `./pics/` が**欄になるのは初回かつ位置を計算できなかったときだけ**(下記)
- 名前の検証は打鍵ごと。使えない字・`.`/`..`・空、そして**もう在る名前**
  (`That name is taken`)。衝突は黙って上書きになるので、押す前に止める
- 進めない間は Enter ごと閉じる。既定値(日時)のまま Enter 1 発で通る

**複数枚**は 1 枚ずつ絵つきで聞く。取りやめはその 1 枚だけ落ちて、残りは続く。

**Draw だけ順序が逆。** 窓は無条件に開き、**確定した瞬間に**上の表へ合流する
— 落とす・貼るは絵が先に在って置き場所の駅を後から通るのだから、描くときだけ
先に事務を挟むのは形が逆。途中でやめても絵は窓に残る。

#### 宣言を決める / 直す

**道具は宣言を黙って書き換えない。** 触る口は 2 つだけで、どちらも計算済みか、
人が確定したもの。

1. **計算できたとき** — 選んだフォルダが md を含んでいれば、`resolve` が
   「フォルダから見た md までの道のり」を返すので、そこから正確に逆算できる。
   推量ではないので黙って書く
2. **計算できないとき**(md の外のフォルダ = `../pics/` など)— 手がかりは
   フォルダ名だけ。**当て推量では書かず、聞く**。画像の流れならフォームの
   欄として、`Files ▸ Choose folder` からなら 1 枚の箱として

   検証は打鍵ごと。絶対パスと URL は弾き、**末尾が選んだフォルダの実名と
   一致するか**を照合する(`pics` を選んで `../images/` と打てば止まる)。
   深さ(`../` が何段か)だけは確かめようが無い — ハンドルから親は辿れない。
   **確かめられる嘘は全部止めて、確かめられないところだけ人を信じる**

**記録と違うフォルダを指されたら、直すか聞く**(`The folder changed — update
the declaration?` / [Update] [Keep as is])。Update なら頭を書き換え、古い宣言の
下にあった本文の画像パスも一緒に動かす(1 回の Undo)。Keep as is も正当な選択 —
握りは移り、記録だけ古いまま。**宣言は記録で、握りが真実**だから成立する。

#### 読むとき

本文の `![](p)` が宣言で始まれば、その残りをフォルダの中に探す。始まらなければ
場所取り(点線)にファイル名で出す。

**握っていないときは、場所取りが自分で言う。** ファイル名の下に
`click to connect` が出て、押せば繋ぎ直しへ入る(押せるのは**その字だけ**。
場所取り自体はカードの選択のまま — 2 つの意味を 1 つの当たり判定に乗せない)。

**開いた瞬間にも誘う。** 保存済みの文書に画像が居て、握っていなければ
`Connect the image folder?` の箱([Connect…] / Not now)。出るのは画像が
居るときだけで、断っても場所取りの入口は残る。**握りを持っているなら
許可を聞くだけ**で済ませ、指し直しのピッカーは出さない — 場所はもう
分かっているのに選ばせるのは、分かっていることを聞くのと同じ。

握りが無い状態は**日常**になる。別の .md を開いた・Save as した・立ち上げ
直した、のどれでもそうなる(握りは「**この md** から見た**あのフォルダ**」と
いう対で、md の場所が変われば対ごと無効)。宣言は md に残っているので、
**どこかはもう分かっていて、指してもらうだけ**。

#### 握りを捨てるとき

**触って失敗したら捨てる。** 抜かれた USB・消されたフォルダを掴んだまま
持っていると、次も同じところで転ぶ。捨てれば場所取りと Connect の入口に
落ちるので、指し直せば戻る。宣言を手で打ち替えても**捨てない** — 宣言は
記録であって、動作を縛るものではない。

#### 入り口と、その他

入り口は 3 つ。**ノードの上に画像ファイルをドロップする**、ノードを選んで
`Mod+V` で貼る、**その場で描く**(下記)。どれも上の同じ流れを通る。
ノードの外に落としたものは受け取らない — どこに付いたか分からない貼り方は
しない。`.md` を落としたときはその md を開く。

ドラッグしているあいだ、**落ちる行に線が出る**(カードのドラッグと同じ
`.drop-line`)。予告するのは「どこに入るか」だけで、入った後の姿ではない。
絵かどうかは種類(MIME)で分かるので、`.md` が混ざっていればどこでも受ける。

`https://` の画像は外部通信になるため表示しない。md 側の記述はただの相対パス
画像なので、他のエディタや GitHub でもそのまま表示できる。

**まだ持っていないもの**: 消した画像の後始末(道具は書くだけで、孤児の webp は
残る)、`![]` の題(alt は常に空で書き、読むときも捨てている)。

#### 名前を付けてリンクを貼る

ノードを選んで `Shift+L`(または右クリックメニューの **Link**)で、クリップボードの
URL が `[](url)` の形で本文に入り、**カードの入力欄が題の上で開く**。そのまま
名前を打って `Mod+Enter`。クリップボードが既に `[題](url)` なら題を選んだ状態で
開くので、Enter で残すか、打ち直すかを選べる。リンクでなければ何も入れずに知らせる。

ポップアップは作らない。**既にあるカードの入力欄をそこで開くだけ**なので、
道は増えていない — `Mod+V` で貼ってから直すのと同じ場所へ、1 手で着く。

文書に書くのは `[](url)` で、**題は空のまま**。題が無いときにホスト名を出すのは
`core/map/card.mbt` の `link_card` の**見せ方**の話で、文書に書く文字ではない
(`host_of` がその線引きを持つ)。

#### その場で描く

ノードを選んで `Shift+D`(または右クリックメニューの **Draw**)で、描くための
窓が開く。描いたものは上と同じ道を通って WebP として保存され、そのノードの本文に
`![](保存パス + 名前.webp)` が入る。**mmm の中に描く道は他に無い**ので、これは
2 本目の道ではない。

道具は**塊が 3 つ**。左に「何で描くか」と「どのくらいで」、右へ離して
「やり直す」を置く — 描くために選ぶものと、描いたものを取り消すものは
種類が違う。

| 道具 | |
|---|---|
| インク | 色 5 つと消しゴムが**同じ並び**の丸。1 つだけが選ばれる |
| 太さ | 細・中・太の 3 段。ボタンには**その太さの点**が出る(字で「2px」と書かない) |
| 取り消し | `Mod+Z` またはボタン。**一筆ずつ**戻る(「クリア」も戻せる) |
| クリア | 全部消す |

**消しゴムは紙の色のインク**でしかない(実装も色と太さを差し替えるだけ)。
同じ並びに置いてあるので、色を選べばそれだけでペンに戻る —
「消しながら色を選ぶ」のような、意味の無い組み合わせが最初から作れない。
色を持てないので、丸の中身だけが絵になる(帯・メニューの絵と同じく
Lucide の `eraser`)。

**色は決め打ちで、太さは 3 段しか無い。** OS のカラーピッカーと生のスライダーは
「何でも選べます」としか言っておらず、選ぶ手間だけを渡してくる。紙の上で
読める色だけを並べ、**選べるものを絞ることを道具の言い分にする**。

末尾の 1 本は**アクセントカラー**(ロゴと同じ `--accent`)。記法は持たないので、
色を変えれば筆も変わる。既定にはしない — 淡い色を選ぶと紙の上で消えるため、
選べば使えるが黙って選ばれてはいない。

**太さの 3 段が何 px になるかは、インクが決める**(ペンは 2 / 4 / 8、消しゴムは
8 / 16 / 24)。消しゴムはペンと同じ太さでは細すぎて使えないが、掛け算を隠すと
「細を選んだのに太い」になる。だから**ボタンの点も一緒に太る** — 見えている
点が、出てくる太さ。

確定は `Mod+Enter` か確定ボタン、**破棄は `Esc` かキャンセルボタン**。

Mindmap 側の入力欄は「確定のみでキャンセルは存在しない」が、ここだけは違う。
あちらは**すでに文書に在るもの**を直すので戻す先があるが、こちらは確定するまで
文書に何も無く、引き返せないと逃げ場が無いため。

### 畳む / 消す

**md に書ける形しか作らない。** どちらも記法をそのまま書く操作で、Mindmap
だけの状態は持たない — 別のマシンで開いても同じ姿になる。意味の裁定は
「md の裁定」、ここでは操作としての見え方だけ。

**畳む**（`<details>`）— 選んだノードの定義ごと `<details>` で包み、
`<summary>` にラベルを書く。`Shift+F` は **畳む（閉）→ 開く → 外す** を 1 歩ずつ巡る。

- **閉じた畳み** — `▷ 名前` と小さく薄く表示され、`+3` のように**畳んだ子孫の数**が
  付く。**子孫は Mindmap から消える**(レイアウトからも外れるので場所を取らない)
- **開いた畳み**（`<details open>`）— `▽ 名前` と普通の大きさで表示され、子は普通に
  展開する。畳みであることは破線の枠だけが言う
- 畳まれたノードの名前は、開いていても閉じていても **`<summary>` の字**。名前を
  付け直せばラベルと `<summary>` の両方が同じ字になる
- 外部レンダラでは**畳まれた塊として見え、クリックで開ける** — 消えはしない
- 外すとタグが外れ、中身はその場で普通の md として読み直される。
  構造は歪みうるが、md をそのまま読んだ結果なのでそれが正しい

**畳みは mmm の独自要素で、`<details>` の見た目には引っ張られない。** `<details>` を
使うのは、一般的な HTML として外のレンダラでも畳みとして見えるから。折り畳み判定を
受けたノードは、Mindmap の上では「folded」として扱われる — GitHub が summary の行の
下に中身を並べるとしても、mmm はそれを写さない。`<folded>` や `<!-- -->` を綴りに
する道もあったが、コメントは入れ子にできず（最初の `-->` で閉じる）、独自タグは
外で畳みとして見えない。

**閉じ（`</details>`）は境界と同じ。** 領域は部分木を**過不足なく**覆うと決めて
あるので、閉じの後ろに書かれたものはその部分木の外。続く骨格は畳んだノードの
兄弟から測る。**側は裏返らない** — 裏返すのは `---` だけ。

```
- head / <details>## head</details> / - y     head, 畳み head, y の 3 つが兄弟
- head / <details>## head</details> / ### z   z は深さ 3 なので、間を Implicit が埋める
- head / <details>## head</details> / text    中身は畳むノードの body なので、
                                              領域が狭い ＝ 畳みは立たない（カード）
```

`</details>` の後ろに項目を書いても、その項目は畳んだ見出しの子にならない
（見出しの直後の項目が子になる規則の、唯一の逃げ道が `---` の境界とこれ）。
GitHub でも畳みの塊が閉じてから次のリストが始まるので、見え方は一致する。
**外の素朴なアウトライナは `- y` を `## head` の下に置く** — `---` の境界で
既に受け入れている食い違いと同じ種類。

**消す**（`<!-- -->`）— 選んだサブツリーを HTML コメントで包む
（呼び出す手はまだ決めていない。`Shift+H` は空いた）。

- **Mindmap から完全に消える。** ノードにも、畳みにも、薄い表示にもならない
- 外部レンダラでも消える
- 復活は md 側でマーカーを消すだけ。Mindmap からは戻せない(見えないので)

使い分けは **畳む = まだ要る**(畳んで取っておく)、**消す = もう要らないが
消したくはない**(md にだけ残る)。

コメントのマーカー判定は**エディタや GitHub と同じ**にしてある: `<!--` は追加の
ハイフンが付いていてもよく(`<!---`)、閉じ側は 2 個以上のハイフン + `>`
なら閉じる(`-->` `--->` いずれも可)。ハイフン 1 個の差で「閉じたつもりが
閉じておらず以降が全部消える」のを避けるため。コードフェンス内は対象外。

### Markdown と Mindmap の出し分け

移動には**別々の 2 つの軸**がある。混ぜない: **見え方**(どちらが出ているか)
は分割線の矢印か `Alt+数字`、**フォーカス**(どちらに打鍵が届くか。隠れて
いれば出してから移る)は `Mod+/`。キーは [shortcuts.md](shortcuts.md)。

`Alt+数字` はそれぞれの表示トグルで、番号は左からの並び順。Markdown を
編集中でも効く(最後の 1 枚を隠すと反対側が表示される)。

**見え方は「分割線の居場所」ひとつで言い切れる。** 「両方消えた」は作らない
ので、辿り着ける形は 3 つしかなく、左から順に並べればそのまま分割線を
左右に動かす話になる:

```
Markdown 無し   ←   両方   →   Mindmap 無し
（左端）          （中）        （右端）
```

だから**矢印は向きを変えない**。`‹` はいつでも「分割線を左へ 1 つ」、`›` は
いつでも「右へ 1 つ」。**着く先の姿**をツールチップが言う — `Markdown only` /
`Markdown + Mindmap` / `Mindmap only` の 3 つで、居場所の定義と同じ行に
住む(`app/panes.mbt` の `spots_for`)。出す/隠すの動詞で言うと、同じ 3 か所を
行き来する話が 4 通りに散る。**端では、その先の矢印は消える** — 押して何も起きない一手を、沈んだ
姿で誘わない。

矢印は**分割線の下端**に横に 2 つ並ぶ。真ん中は本文と地図のいちばん見たい
ところなので、そこには浮かせない。**分割線そのものは隠さない** — 片方を
消しても、残りが flex で埋まるぶん分割線がそのまま境目まで押し出
されるので、矢印はいつも同じ 1 か所に居られる(角と角に分けると、片方だけ
スクロールバーを避けた分ずれて見える)。片方だけになると分割線は窓の縁に
来るので、矢印もその内側へ寄る。

スプリッタは両方表示のときドラッグで幅を変える。**片方だけのときは、
押せば分割へ戻る** — 動かす幅が無いので掴んでも何もできないが、縁に寄った
分割線はそこに見えているので、細い矢印 1 つを狙わせるより易しい取っ手に
なる(カーソルもそのとき押す形に変わる)。

矢印キーは割り当てない。`Ctrl+←→` はテキスト欄の単語移動で、書いている
最中に一番使うため。`Ctrl+数字`(タブ切替) / `Ctrl+J`(ダウンロード) /
`Ctrl+Shift+R`(再読込) はブラウザの予約で、`Ctrl+\` は JIS 配列で位置が
変わる — 消去法で残るのが `Alt+数字`(JetBrains と同じ体系)。
**どちらを出しているかは覚える**（`mmm.panes`。"both" / "md" / "map" の 3 つで、
CSS へ降ろす `data-show` と同じ綴り）。書くのは人が動かしたときだけで、幅が
境目をまたいだときの射影は覚えた姿を上書きしない — あれは環境の都合であって、
選んだ結果ではない。覚えが無ければ両方から始まる。

### 選択の持ち主

**選択は 1 つで、持っている側（フォーカスのあるペイン）が決める。**

| 持ち主 | 選択 | 見え方 |
|---|---|---|
| md | カーソル（点でも範囲でも）が掛かっているノード | 地図: 箱の**内側**の輪。md: 何も塗らない |
| Mindmap | 地図で選んだもの（ノードの並びかカード 1 枚） | 地図: `selected` の枠。md: その範囲の薄塗り |

持ち主はフォーカスが最後に入ったペインで、窓・メニュー・帯へ抜けても変わらない。**帯へ
抜ける道は `Escape`** — 2 つのペインはどちらも `Tab` を飲む（地図は子を足すのに、md は
字下げに使う）ので、`Tab` では戻れない。地図の `Escape` は 1 段ずつ外へ（カードを外す →
選択を解く → 帯へ）。md から
地図へ移れば、その瞬間のカーソルのノードを引き継ぐ。地図から md へ戻れば地図の選択は捨て、
**md のカーソルは動かさない**（書いていた場所が飛ばない）。

**輪と枠は「誰が持っているか」の印。** 外から掴む枠が地図の選択、中に居る輪が md の
カーソル。同じ 1 つの選択の 2 つの顔なので、濃さで competing しない。輪はノードの子では
なく world に浮かぶ別の印（`CardPick` と同じ — 子にすると動くたびに中身が作り直される）。
濃さは輪だけが持つ（`--accent-soft` は面を塗るための薄さで、2px の線に当てると消える）。

**md 側の薄塗りはテキスト選択ではない**（CodeMirror の装飾）。実選択にするとカーソルを
奪う。地図が持つ間だけ出る。

**どれに掛かるかは、そのノード自身の文に掛かっているかどうか、それだけ**（`core/read/caret.mbt`）。
自身の文とは骨格の行と、子に取られていない中身（あいだの空行も含む）。文書は隙間なく
分かれるので、点でも範囲でも同じ 1 つの規則。文書の頭・最初の見出しより
前の散文・区切り行には何も出ない。**子孫まで含む `to` で見てはいけない** — カーソル 1 つで
ルートまでの祖先が全部光り、選択と見分けが付かなかった。

**閉じ際は中と見なす。** 区間は半開だが、カーソルはその位置に立てる。半開のまま読むと文書の
末尾では何にも掛からず、追記しているあいだ印が出ない。**点が継ぎ目ちょうどなら始まる側 1 つ**
— 両側を返すと、地図へ移った直後の Delete が 2 つ消す。範囲なら掛かる全部。

**選択に居るのは箱のあるものだけ。** 畳んだ枝の中に居るときは、どこも光らない。

**地図が持つ間の選択は位置で持つ。** ノードはラベルの頭、カードは中身の頭を CodeMirror に
預け（`src/state.ts`）、打鍵・undo・操作で CodeMirror が位置を写す。undo で戻しても同じノードが
選ばれている。位置が消えた点に潰れれば、そこに掛かるノード（隣）。**操作の後は core の
focus** — ノードを消せば次の兄弟 → 前の兄弟 → 親（core.md「操作」）。

**選択を書くのは持ち主の操作だけ。** ファイルの投下・宣言の書き換え・画像の保存は md を
書くだけで、選択に触らない（App の `write`）。

複数選択は任意の集合。md 側は範囲が掛かる全部、地図側は `Mod+クリック` /
矩形 / `Shift+矢印`。

**md のカーソルは 1 本にしてある。** CodeMirror は複数カーソルを持てる（切っているのは
`allowMultipleSelections` の facet 1 つ）が、入れていない — 地図の側で選べることの写しに
しかならないので、コアの外で要件を増やさない（#66）。読み（`core/read/caret.mbt` の
`caret_ids`）は範囲の列を受けるので、要るようになってもそこは直さなくてよい。

### エクスポート

**入口が範囲を決める。**

| どこから | 書き出す範囲 |
|---|---|
| ヘッダーの書き出しボタン(`SVG ⤓ ▾`) | 常に Mindmap ぜんぶ |
| 右クリックメニューの **Export ▸** | **選んでいる枝**(その子孫ごと)。何も選んでいなければ全体 |

新規 / 開く / 保存 が文書ぜんぶを相手にするのと同じ高さにヘッダーを置き、
「これ」を相手にする操作は右クリックへ寄せた。ボタンを見て範囲が分かる。

枝が「その子孫ごと」なのは、mmm では「選ぶ」がどこでも枝ごとを意味するから
(コピー・カット・削除・移動)。書き出しだけ別の意味にはしない。畳んだまま
書き出せば畳んだ姿が出る。どちらも一時的な UI 状態(選択・ドロップ印)は
含まれない。

**出し方はどちらも同じ 4 つ**で、並びの定義は `app/bar/export.mbt` の 1 か所。

| | |
|---|---|
| **Download SVG** / **Download WebP** | ファイルに落とす |
| **Copy PNG** / **Copy SVG** | クリップボードへ |

ヘッダーは**いまの出し方がボタンに出ていて**、押せばそれで出る。隣の `▾` で
選び直すとその場で出て、次からの既定になる — 押す前に何が起きるかが見える。

**出せたことは、そのボタンの絵がチェックに変わって言う**（Copy link と同じ
引かれ方。並びのほうは
押せば閉じる。Copy link と違い、答える場所はいつでも 1 つ — ボタン）。
手元には何も現れない（クリップボードも、ブラウザ任せのダウンロードも）ので、
押した場所が一度うなずくだけでいい。**戻すきっかけは 2 つ。ボタンから離れた
ときと、離れないまま少し経ったとき（1.5 秒）** — 離れたときだけにすると、
`▾` の並びから選んだときやキーで出したときはポインタがボタンに乗っておらず、
離れる瞬間が来ない。時間だけにすると、次に押したいときまで「いまの出し方」が
読めないままになる。早く来たほうを採る。しくじったときはうなずかない
（しらせのほうが出る）。

右クリック側は **Export ▸** の入れ子。平らに 4 行足すと右クリックが伸びるので
畳んである(入れ子の器はメニュー自身。子メニューも同じ `ContextMenu` で、
置く場所が親の行の隣になるだけ)。

**WebP はクリップボードに置けない**(ブラウザが受け取らない。`ClipboardItem`
が許すのは PNG と SVG だけ)ので、コピー側の絵は PNG になる。
SVG のコピーは `text/plain` にも同じものを載せる — Figma や Illustrator は
SVG のソースを貼られたほうが確実に開く。

SVG はスタイルとサムネイルを埋め込んだ自己完結ファイル。ラスタは **2 倍**で
描く(倍率は選ばせない — 書き出したものは画面で見えている通りであるべき)。

**ただしブラウザの上限には収める。** canvas は 1 辺 65,535 px・面積
268,435,456 px までで、WebP はさらに 1 辺 16,383 px までしか持てない。超えた
まま渡すと、PNG は絵にならず、**WebP は超えた分を黙って切り落とす**（どちらも
何も言わない）。だから大きな地図では倍率を落として全体を収める — **欠けた絵や
「出せない」より、粗くても全体が写るほうが良い**。上限に当たらない大きさでは
2 倍のまま。上限を持たない SVG は、どれだけ大きくてもそのまま出る。

地は持たない(透明)。貼り先の色にそのまま乗る。右下の余白には
`made with mmm` の透かしを置く(SVG だけリンクが生きる — ラスタは絵として
焼かれるため)。

### 文字コードと改行

**UTF-8 / LF だけ**。読み込み時に CRLF も単独の CR も LF へ正規化し、
**保存も LF で書く**(元の改行へ戻さない)。クリップボードから来る文字列も
同じ規則で揃える。Shift-JIS の往復も CRLF の往復も、ネイティブだから
背負えた要求だった。

CodeMirror は読み込んだ文書の改行を内部で LF に正規化する。コアは LF しか
読み書きしない。両者に別々の改行を渡すと文字位置がずれて、打鍵が見当違いの
場所に書き込まれる。これを避けるための統一。

コアが**書き足す**改行も常に LF。以前は「その文書の流儀」を毎回探していたが、
入口で LF に揃えている以上そこには辿り着けなかった(既にある行のバイト列は
従来どおり触らない)。

**コアの中では、揃えるのは木が抱える字。** 原文の文字列そのものは 1 バイトも触らない —
地番は原文の位置を指し、記法構造の書き戻しは原文を切って返すので、CRLF の md を
そのまま渡せばそのまま返る。CR を剥がすのは木へ渡す所(`carve` / `strip` と、
ライブラリから来る中身・frontmatter)だけで、そのおかげで書き戻した md の改行が
1 通りになる(#207)。読んだ字をそのまま持つ原則の、唯一の例外。

## 文書モデル

md をどう読むかの裁定。「使い方」も同じ裁定で書いてあるので、読みは 1 本に揃っている。

> **mmm は意味を 1 ビットも失わない。記法は mmm が所有する。**

構造・順序・中身は消えないし並べ替えられない。触った所でも、読んだ綴り
(マーカー・setext・閉じの `#`・境界の線・表・フェンス・定義行の位置)は
そのまま。mmm が綴るのは新しく作ったものだけで、見出しは `#`、項目は隣の
マーカー(無ければ `-`)、境界は `---`、画像は `![alt](src)`、リンクは
`[題](url)`。

**ただしラベルに改行が在る見出しは setext で書く。** ATX(`# a`)は 1 行しか
持てないので、`a` 改行 `b` を ATX で書くと 2 行目が中身に化ける。**読んだ
setext は保つ**の帰結として、ここだけは setext で書ける。木は ATX か setext かを
持たない — **ラベルに改行が在るかで決まる**ので、覚えておくものは無い。

setext は深さ 1〜2 しか綴れないので、それより深い見出しのラベルに改行を
入れる操作は断る(`DeepSetext`)。項目のラベルは `- a` 改行 `  b` で書けるので、
この制限は見出しだけ。

### md の裁定

md が既に意味を持つものだけを使い、意味を発明しない。位置や記法で同じ記号に
別の意味を振り分けない。**裏切らない読みは長持ちする。**

#### 項目の中

**`<li>` の中は、その項目の深さを 0 とした文書。** CommonMark は項目の中身を文書と
同じ塊の列として読む。mmm もそのまま鏡に映す — 骨格（見出し・項目）は `<li>` の中でも
箱で、中身は中身。項目の中だけの規則は作らない。

- **ラベルは顔（最初の塊）が段落のときだけ。** 段落でなければラベルは空で、その塊は
  md の解釈どおりに読む（見出しなら子、水平線・引用・コードなら中身）。mmm が判断して
  いるのは「段落かどうか」の 1 点だけで、塊の種類はライブラリが決める
- **`#` の本数は項目からの深さ。** 文書と同じ絶対座標で、飛びは Implicit が埋める。
  天井の 6 段も項目から数える
- **順序法則も同じ。** 見出しの後ろの項目はその見出しの子、項目の後ろの見出しは兄弟
- **側は無い。** 側は根の子だけの性質なので、項目の中の `---` は常に飾り（直前の
  ノードの body の尻）。項目の中に境界は立たない

```
- # head                  項目 "" → head
- ## head                 項目 "" → Implicit → head
- a / # x                 a → x（顔か 2 塊目かは関係ない）
- # x / --- / # y         項目 "" → [x（body: 線）, y]。側は無い
- - x / --- / - y         項目 "" → [x（body: 線）, y]。md ではリストが 2 つだが、mmm は 1 列
- ***                     項目 ""、body = [線]
- > q                     項目 ""、body = [引用]
- a / ---                 項目 "" → Implicit → 見出し "a"（setext の `---` は 2 段）
- ---   /   - - -         項目ではなく文書の水平線（CommonMark は水平線を優先する）
- - - head                項目 "" → 項目 "" → 項目 "head"（字が混ざれば水平線にならない）
```

**書く側も同じ規則を知る。** 名前の無い項目が 3 段続くとマーカーだけが 1 行に並ぶので、
書くときは子を次の行へ落とし、桁で入れ子を言う（`-` / `  - -`）。名前が在る行は直さない —
`- ---` が水平線に読まれるのは md の文法どおりで、その字は利用者のもの。

md の AST にあって mmm の木に無いものは、綴りとして扱う（loose / tight、`---` で
割れたリストが 2 つであること）。触らない限り原文の字は動かない。

mmm が新しく書くものは席が決めるので、見出しの無い項目に見出しを持ち込むことは
無い（[core.md](core.md)「操作」）。`- # head` は手で書かれたときにだけ現れる形。

#### 水平線(thematic break)

HTML5 の定義どおり「節の中での話題の転換」。**水平線で区切られた範囲を、
まとまりとして扱うことはしない** — 装飾の線は書かれた場所に居て、そのまま書き戻る。

**全部の記法(`---` `***` `___`)・全部の本数が同じ 1 つの意味。** 差別しない。
意味は常に「**隣を区切る**」で、見るのは**直後のブロックが何か**だけ。深さも
本数も記法も判定に使わない。

```
水平線の直後が見出しか項目の行か？

  はい  →  引き出す先(深さ 2 の口)はあるか？
             ある  →  境界
             ない  →  装飾
  いいえ →  装飾
```

**境界** — 「直前のものの一部ではない」という宣言なので、**そのノードを深さ 2 まで
引き出す**。足りない深さは Implicit が埋める。側が持てるのは深さ 2 だけなので、
境界もそこが持ち、1 つにつき側が 1 回裏返る。

```
# r / ## a / --- / ## b            r → [a, (境界)b]                b は左
# r / --- / ## a                   r → [(境界)a]                   a は左
# r / ## a / --- / ### x           r → [a, (境界)Implicit → x]     x は左
# r / ## a / ### x / --- / ### y   r → [a → x, (境界)Implicit → y] y は左
# r / ## a / --- / - b / - c       r → [a, (境界)b, c]             項目も同じ
# r / ## a / --- / --- / ## b      r → [a(中身 ---), (境界)b]      続けば手前は装飾
```

水平線が続いたときも規則は同じ。手前の 1 本は直後が水平線なので装飾に落ち、
書かれた場所（直前のノードの中身）に残る。**境界を取るのは最後の 1 本だけ**で、
本数がいくつでも側は 1 回しか裏返らない。

引き出したあと、**次の兄弟も引き出された先に並ぶ**。項目は相対記法なので深さは
導出値で、`#` の数ではなく座る枠から数える(数え直すと元の位置から数えてしまい、
`- b` の子に `- c` が潜る)。見出し(`## b` `## c`)と同じ形になる。

**装飾** — 直前のノードの body 末尾に線として置く。無ければ文書の body。
書かれた位置がそのまま保たれる。

```
# a / --- / body / ## b     a.body = [線, body]、b は右
# a / body / --- （文末）   a.body = [body, 線]
# r / --- / --- / ## b      ①は直後が水平線なので装飾、②が境界
                            a.body = [線]、b は左
```

**境界になれない場所**は規則の裏返しとして出る。根は文書に直接生えていて
深さ 2 の口を持たないので、引き出す先が無い。

```
# r / --- / # s      r.body = [線]、s は普通の根
body / --- / # a     doc.body = [body, 線]
```

mmm が側を書くときは見出し・項目の行の直前に `---`(触った所だけ正規形)。中身の編集で
線は境界に昇格/降格しうる(直前の散文を消す等)。**md 自身の性質**なので
操作は文字通りに行い、結果は見た目で示して undo に任せる。

#### 畳み(`<details>`)

**水平線と同じ形の裁定** — その記号が構造の位置にちょうど置かれたときだけ
構造として読み、それ以外は中身。畳みが立つのは**限られた形のときだけ**。

```
原文のその範囲が、mmm がそのノードを畳んだときに書く文字と一致するか？

  ① 領域がそのノードの body・children とその body を覆い、関係ない要素が入っていない
  ② 開き・閉じの塊が綴りだけで出来ている。タグ 1 つ 1 つが mmm の書く形そのもの
     (`<details>` / `<details open>` / `<summary>名</summary>` / `</details>`)で、
     開きの塊は「開き」か「開き + 名前」、閉じの塊は閉じだけ

  揃う      →  そのノードの畳み(`fold` が在る)。中身は普通に読む
  欠ける    →  中身。原文のままの Details が body に 1 個入る
```

②は独立した規則ではなく①と同じ問いの別の面 — **書き戻せない綴りは畳みにできない**
（畳みが立つと綴りは木から消えるので、書き戻せなければその文字が失われる）。名前が
2 枚あれば片方は木に置き場が無いので、開きの塊は「開き」か「開き + 名前」だけ。

**タグの間の空白は綴りではない。** 1 行に並べても行で分けても言っていることは同じ
なので、`<details><summary>h</summary>` も畳みになり、書き戻すときは mmm の並べ方に
なる（`*` の項目が `-` になるのと同じ、記法の正規化）。数えるのは**タグ 1 つ 1 つの
字並び**で、`<DETAILS>` や `<details >` は畳みにならず原文のまま残る。

**持ち主を決めるのは範囲であって、名前ではない。** `<summary>` が在るかも、ラベルと
一致するかも問わない。書かれていた名前はノードが持ち、書き戻すときそのまま出す。
だから**ラベルだけ手で書き換えても畳みは降格しない**(名前が古いまま残るだけで、
mmm 経由で触れば揃う)。

```moonbit
/// 畳み。在ること自体が「畳まれている」で、中身は書き戻すのに要る綴り
Fold { open : Bool, summary : String? }
```

`summary` が `None` と `Some("")` で違うのは往復のため — 書かれていない `<summary>` に
空の行を生やすと、触っていない場所が動く。

**タグの対はタグの並びで数える。** md のブロック境界とタグの入れ子は元々そろって
いないので、そろっている前提を持たない(`</details>` が空行なしで重なって 1 つの塊に
なっていても、閉じは 2 つと数える)。

**タグの読み方は HTML に従う。** 名前の大小は区別せず(`<DETAILS>` もタグ)、属性の中の
`>` は引用符の中なら数えず、名前の直後が空白・`>`・`/` でなければタグではない
(`<details-x>` はカスタム要素であって畳みの開きではない)。ただし**綴りとして認めるのは
mmm の書く形だけ**なので、`<DETAILS>` は対にはなっても畳みにはならず原文のまま残る。

**中にタグが無い範囲は跨ぐ。** md が「ここは生の HTML」と言った範囲で HTML の
字句規則に従うだけなので、md の読み解き直しではない。

- コメント(`<!--…-->`。`<!-->` と `<!--->` はそこで閉じた空のコメント)
- 擬似コメント — `<!` に `--` が続かない形と `<?` は最初の `>` まで
- 生テキストの `<script>` `<style>`、RCDATA の `<textarea>` `<title>`
  (`<pre>` は生テキストではないので含まない)
- `<svg>` — foreign content なので、中の `details` は SVG の要素であって畳みではない

`<script>var x = "</details>";</script>` は閉じにならない。閉じの名前も大小を
区別しないので `</SCRIPT>` で終わる。

**綴りを拾うのは生の HTML の塊だけ。** 段落の中に書いたタグは md が中身と言って
いるので綴りにしない。CommonMark のタグ表に無い名前(`<presentation>` など)で始まる
行は段落になるため、そこに書いた `</details>` はブラウザでは畳みを閉じても
mmm は閉じない。**md の切り方に従った結果**で、文字は残る。

**複数のノードを跨ぐ領域は畳みにならない。** 畳みはノード 1 つの状態なので、
mmm の木で言えるのは「この部分木がまるごと畳まれている」だけ。跨いだ領域は
言える形になっていないので原文のまま持つ。

```
# r / <details><summary>h</summary> ## h  body </details>    h の畳み。h.fold、h.body = [body]
# r / <details> ## h </details>                              h の畳み。名前は None
# r / ## h / <details> body </details>                       中身。行が領域の外
# r / <details><summary>h</summary> ## h </details> / ### x  中身。h の子 x が領域の外
```

**Implicit は行を省いた空の見出し。** マップには空の見出し（`## `）と同じ空の箱で
出て、同じに触れる。違いは md にその行が書いてあるかどうかだけ。省いたままでは
読めない席へ動かせば行が綴られる（label `""` の見出しになる）。畳むときも中身を持つ
ときも綴ってからなので、Implicit が畳みや中身を持つことは無い。

**`open` は畳みの綴りの一部**(`fold.open`)。外部レンダラで開いた姿になるかどうかが
変わるので、落とすと見え方が変わってしまう。マップでどう出すか・UI から立てられるかは
後で決める。**それ以外の属性は畳みの綴りではない** — 畳みにすると開きの塊ごと落ちて
消えるので、領域まるごと原文のまま持つ。

- **入れ子も同じ規則。** 外を解いたあと、中をまた同じ目で見る
- **中身を読まないのは Details のときだけ。** 畳みなら中は普通の md として
  読む(h はノードになる)。Details は原文のままなので、触っていない限り 1 バイトも
  変わらない(「読んだ綴りはそのまま」の帰結)
- **対の揃わないタグはただの文字。** 閉じだけでなく、閉じの無い開きも —
  タイプ中に文書の残りが吸い込まれないように
- **①の深さは `#` の数ではなく、積まれた深さ。** 境界の水平線は部分木を深さ 2 へ
  引き出し、飛びは Implicit で埋まるので、`#` の数で測ると「領域の外へ出た子」を
  覆っているつもりになる。水平線は単体では中身ではないので跨ぎ、**その先が骨格か
  どうか**でその水平線が境界だったか飾りだったかが決まる
- **領域の中の水平線は、領域の中にしか効かない。** 行き先が領域の外の骨格なら
  その水平線は部分木のものではないので①が欠ける(畳みが立つと綴りは木から消えるので、
  書き戻すと水平線が領域の外へ出る)。行き先が中なら、引き出された骨格が深さで
  弾かれるか、飾りとして中身に残るかのどちらか
- **リンクの定義行も中身。** mdAst はこれをブロックとして返さない(`Document.definitions`
  に分けて持つ)が、原文には在る。開きとノードの間に書いてあれば、そのノードのもの
  ではない要素なので①が欠ける
- **空行が要る。** 空行を挟まないと md は次の行まで 1 つの塊に飲み込む。mmm は常に
  空行を挟んで書く。飲み込まれた行があると②が落ちて原文のまま残る(重なった `</details>`
  だけは、何段ぶんか数えれば分かるので畳みのままでよい)
- **容器の字下げは剥がす。** 項目や引用の中では行頭の空白はその容器の記法であって
  中身ではないので、切り出しは列 0 に揃える(剥がさないと深い入れ子で字下げコードに化ける)。
  一方、列 0 の行に付いた 1〜3 個の空白は**見出しの `   # a` と同じ飾り**で、
  その行を書き直したときに落ちる
- 畳んだノードの表示名は覗いて導出: `<summary>` > 一番強い見出し（そのノードのラベル）> 最初の行
- **ラベルを書き換えても畳みは降格しない。** 名前は持ち主を決めていないので、
  `fold.summary` が古いまま残るだけ(mmm 経由で触れば揃う)

操作は**この記法を書く/外す UI** にすぎない:

- **畳む** = そのノードの定義ごと巻き、`<summary>` にラベルを書く
- **広げる** = タグを外す。中身はその場で普通の md として読み直される
- マップでは GitHub と同じく `<summary>` と、`open` なら中身の字を出す(「コンテンツ
  カード」)。中身を md として描くのは後の拡張

#### コメントアウト(`<!-- -->`)

**完全無効化。** 中身はマップの意味論に一切参加しない — ノードにも、畳みにも、
薄い表示にもならない。コードのコメントアウトと同じ。

- 原文はそのノードの中身としてそのまま運ばれ、往復で保存される
- 復活は md 側でマーカーを消すだけ。マップからは戻せない(見えないので)
- 薄表示 + 件数の見せ方は畳みが引き継ぐ(「畳む / 消す」)

使い分け: **畳む = まだ要る**(畳んで取っておく。マップから出し入れできる)、
**消す = もう要らないが消したくはない**(md にだけ残る)。

内部の持ち方(型・パイプライン・道具の決め)は [core.md](core.md)。
