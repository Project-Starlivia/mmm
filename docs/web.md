# Web へ戻す

## なぜ

**ブラウザのタブで開くほうが気楽だから。** それだけ。

Tauri が与えてくれたもの（パスの所有・外部監視・文字コードの往復）は、
気楽さと引き換えに手放す。手放せないもの（隣の画像を相対パスで読み書きする）
だけを、ブラウザの手段で作り直す。

## 何になるか

**`.md` を実体とするマインドマップエディタ。**

いまの mmm は「Markdown ⇄ マインドマップの双方向エディタ」で、2 枚の
ペインが互いを映していた。これからは**マップ 1 枚**になる。md はディスク上の
実体であり続けるが、テキストとして読み書きする窓は持たない — テキストを
直接いじりたければ、他のエディタで開けばいい。それは mmm の仕事ではない。

削る基準は変わらない。**「.md の見出し構造を空間で編集する」から説明できない
機能は持たない。** ただし**操作の快適さはコアバリューに含む** — 画像が
ドロップですぐ出ること、リンクやコードがカードとして見えることは、
「あれば良い」ではなく、この道具が道具である理由そのもの。

## 決めたこと

### 1. ファイルは 1 つずつ開く。フォルダは画像を初めて置くときだけ選ぶ

File System Access API を使う。**Chromium 系でしか動かない**と言い切る。
フォールバック（ダウンロードでの保存）は持たない — 2 本目の道を作れば
そちらでは画像が死に、「実体はただの .md」も壊れる。動く道が 1 本だけ
あるほうが良い。

- **開く** = `showOpenFilePicker()`、または `.md` のドロップ
- **保存** = 開いたハンドルへ上書き。まだディスクに無ければ、本文から導いた
  名前を初期値にして保存先を聞く
- **別名で保存** = 保存先を聞く。元のファイルはそのまま
- **新規** = 空の文書。保存するまでディスクには無い

ファイルのハンドルからは親フォルダに辿れないので、**隣の画像を読み書きする
にはフォルダの許可が要る**。それを求めるのは**画像を初めて置くとき**だけ。
フォルダを開かせてから md を選ばせる形は採らない — 画像を使わない文書に
フォルダの話をさせない。

### 2. 画像は「フォルダを 1 つ選ぶ → 置き場所と名前を決める」— アプリは確かめない

初めて画像を貼る／落とすとき:

1. `showDirectoryPicker({ startIn: fileHandle })` でフォルダを 1 つ選ぶ。
   **どこでもよい。** md を含むかどうかをアプリは調べない（`resolve()` で
   調べられるが、調べない — 探査も関与もしないほうが単純）
2. アプリ内のフォームで**保存パス**（初期値 `./`）と**ファイル名**
   （初期値 `yyyy-mm-dd-HHmmss`、拡張子 `.webp` は固定表示）を聞く
3. WebP に変換して**選んだフォルダの中に `ファイル名.webp` を書き**、本文に
   **`![](保存パス + ファイル名.webp)` を挿入する**

つまり保存パスとは「**md から見て、選んだフォルダがどこにあるか**」の宣言で、
その整合は**ユーザーが取る**。md と同じフォルダを選んで `./` のままなら、
何も考えなくて合う（ダイアログは md のあるフォルダで開くので、そのまま
「選択」を押すだけ）。`../pics/` に貯めたいなら `pics` を選んで保存パスに
`../pics/` と書く。ファイル名に `/` を入れれば（`assets/shot`）フォルダの
下にサブフォルダを作る。

読むときも同じ宣言を使う: 本文の `![](p)` が保存パスで始まれば、その残りを
選んだフォルダの中に探す。始まらなければ点線のプレースホルダにファイル名で
出す。**プレースホルダをクリックするとフォルダを選ぶ**（まだ選んでいない
ときの入り口がこれ）。

2 回目からはフォームだけ（保存パスは前回の値）。フォルダのハンドルと
保存パスは IndexedDB に残すので、次に来たときも選び直さない（Chromium は
許可を覚えるので、再確認のダイアログも普段は出ない）。

宣言が実際の配置と食い違っていても、アプリは気づかない — アプリの中では
辻褄が合って見え、ディスク上の md だけが嘘になる。**これはユーザーの責任。**

画像ファイルのドロップは、どこから来たものでも 2 と 3 で選んだフォルダへ
複製する。`.md` のドロップはその md を開く。

### 3. MD ペインを持たない — ノードは「見出し + その下の本文」を編集する

いまノードの編集はラベル 1 行だけで、本文（添付コンテンツ）は MD ペインか
専用ポップアップ（リンク / コード / お絵描き）からしか書けなかった。
ペインを外すなら、この 3 つの入り口も一緒に畳む。

**ノードを開くと、見出し行と直下の本文がひとつのテキストとして編集できる。**

- 1 行目 = ラベル（`#` は見せない）
- 2 行目以降 = 添付コンテンツ。打った内容がそのままカードになる
- `Enter` = 改行、`Mod+Enter` / `Esc` = 確定、`Tab` は無効

リンクを足す = 2 行目に `[title](url)` と打つ（URL をペーストすれば
いままで通り自動でリンク行になる）。コードを足す = ` ``` ` と打つ。
**入り口が 1 つになり、書けるものに制限が無くなる。**

これで CodeMirror 6（依存 6 つ）とポップアップ 3 種が消える。
残るポップアップは画像の置き場所を聞くフォーム 1 つ。

### 4. カードは 4 種のまま残す

リンク / 画像 / SVG / コード。「見て分かる」ことがマップの価値なので、
プレビュー 1 種に畳まない。ここは削らない。

### 5. 文字コードと改行は UTF-8 / LF だけ

Shift-JIS の往復も CRLF の往復も、ネイティブだから背負えた要求。
ブラウザでは UTF-8 で読み、UTF-8 で書く。読み込み時に CRLF は LF へ
正規化し、**保存も LF で書く**（元の改行へ戻さない）。

### 6. 外部変更は追わない

`notify` に相当するものがブラウザに無い。ポーリングは持たない
（「見張っているようで見張れていない」のが一番悪い）。他所で書き換えたら、
**開き直せば最新になる**。それだけを約束する。

### 7. 覚えるのはハンドルだけ

IndexedDB にファイルとフォルダのハンドルと保存パス。起動時は前回のファイルを
開き直す（許可の再確認が要るときは、ファイル名欄のクリックで開く）。
localStorage は空にする（ブランドカラーとテーマを削るため）。
テーマは OS 設定に従うだけ。

保存は明示（`Mod+S`）のまま。未保存でタブを閉じようとしたら
`beforeunload` で止める。

## 段取り

各フェーズの終わりに `pnpm test` / `pnpm run test:core` / `pnpm run check`
を通し、コミットする。

git は 2026-08-22 に入れた（それまでは未管理）。最初のコミットが Tauri 版の
現状。作業は `refactor/web` ブランチを `.worktrees/refactor/web` で進め、
終わったら main へ squash merge してブランチと worktree を捨てる。
**main は merge の瞬間まで Tauri 版のまま動く。**

### Phase 1 — Tauri を外す（Web で今の機能が動く）

いまの見た目・操作をそのままに、足回りだけ差し替える。**このフェーズが
終われば mmm はブラウザで動く。**

| 消す | 置き換える |
|---|---|
| `src-tauri/`（770 行 + Cargo）| — |
| `@tauri-apps/api` `plugin-dialog` `plugin-opener` `@tauri-apps/cli` | — |
| `scripts/icon.ts` | — |
| `src/app/externalChange.ts` | — |
| `test/eol.test.ts` | — |

- `src/app/io.ts` を FSA 版に書き直す（`open` / `save` / `saveAs` / `close`）
- ハンドルを IndexedDB に持つ層を足す（`src/app/handles.ts`）
- `src/app/assets.ts` の解決・保存をフォルダのハンドル経由にする
  （決めたこと 2）。画像名のフォームを保存パス + ファイル名の 2 欄にする
- D&D は `DataTransferItem.getAsFileSystemHandle()` で受ける
- 確認ダイアログはブラウザの `confirm()` に戻す。`beforeunload` を入れる
- `pnpm run dev` / `pnpm run build` が本流になる

### Phase 2 — ペインを外す（画面が 1 枚になる）

| 消す | 行数 |
|---|---|
| `src/editor.ts` + CodeMirror 依存 6 つ | 188 |
| `src/app/panes.ts` | 92 |
| `src/popup.ts` の link / code / draw | 約 240 |
| `index.html` の `#md-pane` `#splitter` `#btn-view-*` | — |
| `src/style.css` のペイン関連 | — |

- `src/mindmap.ts` のインライン編集を複数行に（決めたこと 3）
- `src/main.ts` から `applySets` / `highlight` / `reveal` の同期が消える
  （`Origin` が `"cm"` を失い、`applySnap` が縮む）
- `Mod+/`（ペイン切り替え）が消える
- `src/relevel.ts` は残す（貼り付けた md の深さ読み替えはマップ側でも要る）

### Phase 3 — 道を 1 本にする

同じことをする道が 2 本ある箇所を畳む。

- **vim キー**を全部削る（`hjkl` `gg` `G` `zz` `dd` `yy` `p` `u` `s` `cc`
  `i` `a` `A` `I` `o` `O`）。矢印 / `Enter` / `Tab` / `Mod+X/C/V/Z` に一本化
- **パン**: 空白ドラッグ = 矩形選択、`Space+ドラッグ` = パン。中クリックを削る
- **書き出し**: SVG のダウンロードだけにする。WebP とクリップボードコピー
  2 種を削る（4 ボタン → 1 ボタン）
- **ブランドカラー変更**と favicon の動的生成を削る。色は固定
- **テーマ切替ボタン**を削る。OS 設定に従うだけ
- ツールバーは **11 ボタン → 5 ボタン**（新規 / 開く / 保存 / SVG / ↩ ↪）

## 消えないもの

`core/`（MoonBit）は**一行も変わらない**。テキストが唯一の真実で、構造操作が
文字オフセットの編集セットに落ちるという設計は、ネイティブでもブラウザでも
同じように正しい。`src/map/` の純粋層（geometry / edge / cards / metrics /
layout / export）も、`src/app/name.ts` も `paste.ts` も `relevel.ts` も残る。

`src-tauri/` が消えて `src/app/io.ts` が入れ替わり、`src/editor.ts` と
`src/app/panes.ts` が消える。**変わるのは足回りと窓の枚数だけ。**

## いったん外すが、戻れる継ぎ目を残すもの

- **お絵描き**（canvas に描いて WebP で保存）。リンクやコードは md を打てば
  済むが、絵は打てない。`Blob` を渡せば置き場所を聞いて `![]()` を挿入する
  入り口（`assets.saveToDisk`）はそのまま残るので、戻すときはそこへ繋ぐだけ
- **MD ペイン**。コアの編集セット（`editSets`）はテキストビューのために
  今も出し続ける。戻すなら `applySnap` にその消費者を足す

## 未決

### 名前

mmm = **m**arkdown / **m**indmap / **m**irror。ペインを外すと mirror が
文字通りには成り立たなくなる。「md とマップが互いを映す」という意味では
生きているとも言えるが、2 枚のペインを指していたのは確か。

名前を変えるかは、Phase 2 が終わって手触りを見てから決める。
