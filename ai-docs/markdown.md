# mizchi/markdown の癖

読み書きの実装は `mizchi/markdown` が持ち、その癖を mmm の決めに揃えるのが方言
（`core/tree/md.mbt`）。**このファイルはその癖の実測の控え**で、直したもの・直していないもの・
直さないと決めたものを 1 か所に並べる。

**上流へ出すときは人の手で。** ここに在るのは再現に足りる材料であって、報告文ではない。
出すかどうか、何をどう書くかは人が確かめて決める。

環境: `mizchi/markdown@0.8.3`、`moonc v0.10.11+6ff76a5f9`、2026-09-10 実測。
指紋は `md_ast_sig`（方言）と `ast_sig(@markdown.parse(md).document)`（生）で、
形は `種類[from,to]`。span が無ければ範囲も出ない。

**走っている網は `core/tree/md_wbtest.mbt`。** 癖ごとに「生の指紋 → 方言の指紋」を並べて
あるので、ライブラリの版が上がって生の指紋が変わればそこで鳴る。この控えは読むためのもので、
真実は試験のほう。

## 方言が直しているもの

### フェンス付きの塊の尻が、閉じの行の手前で止まる

```
md   "# a\n\n```\nx\n```\n"   len 15
raw  H1Atx[0,4] Blank1[4,5] Fence()[5,11]
dia  H1Atx[0,4] Blank1[4,5] Fence()[5,15]
```

コード・`$$`・`:::` が同じ。方言（`stretched`）が閉じの行の改行まで伸ばす。
mmm は**塊の尻を行末の改行込み**と決めているので、他の塊（段落・見出し）に揃える形。
`md_wbtest.mbt` 「方言 — フェンス付きの塊の尻は閉じの行の改行まで」。

### 字下げコードの span が、剥いだ位置から始まる

```
md   "# a\n\n    code\n"   len 14
raw  H1Atx[0,4] Blank1[4,5] Indent[9,14]
dia  H1Atx[0,4] Blank1[4,5] Indent[5,14]
```

生では `[5,9)` の 4 桁が誰のものでもない。その 4 桁は容器の字下げではなく**その塊の記法**
なので、切り出しが剥がすと書き戻したとき段落に化ける（#206）。方言（`undent`）が戻す。

### 入れ子の `:::` の閉じが、段落として二重に出る

```
md   ":::a\n:::b\nx\n:::\n:::\n"   len 20
raw  Directive(a)[0,10] P[16,20]
dia  Directive(a)[0,20]
```

外の `:::` を閉じまで伸ばすと、生が段落と読んだ `[16,20)` が丸ごとその中に入る。
そのままだと同じ字が 2 度書かれるので、方言（`unswallowed`）が飲まれた塊を落とす。

### 閉じたフェンスを含む引用の span が空になる（#46 の直った分）

```
md   "> ```\n> x\n> ```\n"   len 16
raw  Quote                     ← 範囲が無い
dia  Quote[0,16]
```

生はこの引用の span を `from == to` で返し、その字を次の `BlankLines` に付ける。
直す前は木に引用が残らず、**書き戻すと文書ごと消えていた**。方言（`measured`）が
「空の span は中身を読めなかった印」として尻を次の塊の頭まで測り直す。

### 定義行の span が、改行の手前で止まる

後ろに何が続くかで生の span が変わる（定義行が続けば改行込み、でなければ手前で止まる）。
方言が改行込みに揃える。`md_wbtest.mbt` 「方言 — 定義行の尻は改行込み」と
「方言 — 定義行が続くと、生の span は改行込みになる。飲み込まない」。

### `Blank` の範囲が、入れ子の項目の周りで壊れる

方言は直さない。**`Blank` を使わないことで避けている** — 隙間は原文の字から測る（合流）。

## 直していないもの

### 項目の中にフェンス付きの塊があると、列の span が途中で止まる（#46 の残り）

```
md   "- ```\n  x\n  ```\n"        len 16  raw = dia = ListDashtrue[0,6](1)
md   "- $$\n  x\n$$\n"            len 12  raw = dia = ListDashtrue[0,5](1) Math[9,12]
md   "- > ```\n  > x\n  > ```\n"  len 22  raw = dia = ListDashtrue[0,8](1)
```

生と方言が一致するので、作っているのは上流。空の span ではなく**短い** span なので、
`measured` の規則は届かない。

被害は一様ではない。1 つ目は span が短くても往復する（切り出しが他の道で中身を拾う）。
**3 つ目は字が消える** — `serialize` が `"- \n"` を返し、マーカーより後ろが丸ごと落ちる。

```
"- ```\n  x\n  ```\n"        → そのまま
"- $$\n  x\n$$\n"            → "- $$\n  x\n\n  $$\n"   $$ が増え、桁がずれる
"- > ```\n  > x\n  > ```\n"  → "- \n"                  字が消える
```

issue #46 は「閉じないフェンス」と書いているが、**閉じたフェンスでも列の span は短くなる**。
引き金は「項目の中のフェンス付きの塊」で、被害が出るのはそのうち閉じの行が項目を
終わらせる桁に来る場合。

対照。フェンスが無ければ正しい。

```
md   "- > a\n  > b\n"   len 12  raw = dia = ListDashtrue[0,12](1)
```

### 列 0 の段落が、項目の桁へ字下げされる

```
md   "- ```\n  x\n``\n"   len 13
raw  ListDashtrue[0,10](1) P[10,13]
ser  "- ```\n  x\n  ``\n\n  ``\n"
```

こちらは span の話ではない。生の span は原文を隙間なく敷き詰めているのに、書きの側で
列 0 の段落が項目の中へ落ちる。#46 に同種として並んでいるが、原因は別。

### `tight` が、項目の**中**の空行でも偽になる

mmm の詰め（`loose`）は「項目と項目の間の空行」だが、ライブラリの `tight` は列のどこかに
空行があれば偽。そのまま書き戻すと空行が項目の間へ移り、触っていない字が変わる（#84）。
方言では直さず、**書く側**が項目の列を自分で組むことで避けている（`unbuild.mbt` の
`bullets`）。`md_wbtest.mbt` 「綴り — 項目の中の空行は項目の間に移らない。冪等」。

### GFM のタスクリストの `[ ]` を食べる

```
md   "- [ ] a\n"   raw = dia = ListDashtrue[0,8](1)
```

生は `[ ]` を食べて段落をその後ろから始める。mmm は**チェックを綴りとして扱う**ので
（#180）、ラベルはマーカーの後ろから測り直し、`[ ] a` がそのまま名前の字になる。
往復では 4 文字とも落ちない。

## 直さないと決めたもの

### 書きは LF だけ

`write` は改行を LF に潰す。読んだ原文をそのまま返す塊（`Block.source`）の中だけは
CRLF が残るので、CRLF の文書を書き戻すと**混ざる**（#207）。これはライブラリの癖ではなく
mmm の決め（読んだ綴りは保つ）が出た形で、`md_wbtest.mbt`「綴り — 書き戻しの改行は LF だけ」と
`content_wbtest.mbt`「CRLF は切り出しの中でも保たれる」が両側を留めている。

## 値段

ライブラリを抱える代償は**配布物で gzip +31KB**（591KB → 622KB。vite の dist で実測）。
上流に parser だけを取る道は無く、MoonBit にパッケージ単位の DCE も無い。

自前で書かないのは、ブロック規則を手で写すと間違いを照合する相手が居なくなるから。
旧 core はそれで往復を壊していた（字下げ行を段落と読み、書き戻すと見出しが生える）。
