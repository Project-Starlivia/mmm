# mmm

**markdown / mindmap / mirror** — 双方向に編集できる Markdown ⇄ マインドマップエディタ。

実体はただの `.md` ファイル。マインドマップは「その md を空間的に見るためのもう一つの窓」でしかない。

## 構成

```
core/   MoonBit — ドキュメントモデル。テキストが唯一の真実。構造操作はすべて
        文字オフセットの編集セットに変換されるため、未編集行のバイト列は
        決して再整形されない。
  parser.mbt   行スキャン(見出し / 区切り / フェンス / hide 領域)
  doc.mbt      状態と木の再構築
  edit.mbt     Edit 型と純関数(適用 / 逆転 / オフセット追跡)
  history.mbt  単一 Undo スタックとトランザクション
  heading.mbt  見出し行を書く・整える・探す道具
  add.mbt      作るコマンド(子 / 兄弟 / 親 / ルート)
  move.mbt     動かすコマンド(D&D / 並べ替え / インデント)
  cmds.mbt     その場のコマンド(rename / delete / hide / コピー用テキスト)
  seps.mbt     区切り(`---`)の掃除 — 下の左右を変えない偶数本規則
  api.mbt      スナップショット契約 / js/ エクスポート層(#export_name)
src/    TypeScript — UI
  coreApi.ts   MoonBit core への型付きラッパー
  editor.ts    Markdown ペイン(CodeMirror 6、履歴はコアに委譲)
  mindmap.ts   マインドマップペイン(DOM 差分更新と入力処理)
  popup.ts     リンク / コード / お絵描きの入力ポップアップ
  relevel.ts   貼り付けた見出しの深さを読み替える
  style.css    全体のスタイル
  map/         その純粋層 — geometry(座標系) / edge(線の形) / cards(添付→カード行)
               / metrics(寸法) / layout(木→箱の配置) / export(SVG 書き出し)
  main.ts      オーケストレータ(選択・同期・ファイル I/O・ショートカット)
  app/         その子系統 — name(文書の名前) / persist(色とテーマだけ) /
               theme(色) / panes(ペイン) / assets(画像) / export(書き出し) /
               io(ネイティブ本体との窓口 — invoke/listen) / logo(ロゴの唯一の源) /
               externalChange(外部変更時の追従/警告の判定) / paste(貼り付けの振り分け)
src-tauri/  Rust — ネイティブ本体。パスを所有し、ファイル I/O・アトミック保存・
        外部変更の監視・画像の解決/複製を担う(lib.rs)。UI にはテキストと名前だけ渡す
test/   検証 — *.test.ts(往復 / コマンド / 左右 / 改行の性質テスト)、
        tools/(負荷サンプル生成・性能計測)、fixtures/(生成された計測入力)
docs/   記録 — audit/ は過去の監査とリファクタの記録（当時のまま）
```

## 構成

UI は [Tauri](https://tauri.app/) のネイティブアプリ（WebView + Rust）。ファイル
I/O・監視・画像の実体は Rust 本体（`src-tauri/`）が持ち、**パスは Rust だけが
知る**。Webview 側（MoonBit core + TS UI）は「開いているテキスト」と表示名しか
持たない。ブラウザのサンドボックスが拒んでいた「隣の画像を相対パスで読む」
「外部変更を見張る」がネイティブでは素直にできる。

## 開発

必要: Node.js、pnpm、[MoonBit toolchain](https://www.moonbitlang.com/download)
(`moon` が PATH にあること)、[Rust](https://rustup.rs/)(`cargo`)

```
pnpm install
pnpm run app        # コアをビルドしてから Tauri アプリを起動（vite + Rust）
```

- 配布ビルド: `pnpm run app:build`（`src-tauri/target/release` に実行ファイル）
- UI だけ vite で見たいとき: `pnpm run dev:full`（ただしファイル I/O は Tauri 前提）
- コア(`core/*.mbt`)を変更したら `pnpm run core` で JS を再生成
- コアのテスト: `pnpm run test:core` / UI 側の往復・左右テスト: `pnpm test` / Rust 側(保存・文字コード等)のテスト: `pnpm run test:rust`
- 型チェックだけ: `pnpm run check`（src と test の両方）

## 使い方

- **新規 / 開く / 保存 / 別名で保存**: ツールバー、`Mod+Alt+N` / `Mod+O` / `Mod+S` / `Mod+Shift+S`
  (`Mod+N` はブラウザ/OS の「新規ウィンドウ」に吸われがちなので `Alt` を足してある)。
  `.md` のドラッグ&ドロップでも開ける。保存は temp→rename のアトミック書き込み。
  新規と開くは、未保存の変更があれば確認してから捨てる
- 起動すると**前回のファイルを開き直す**（Rust が app-config にパスを覚えている）。
  外部（別のエディタ・git など）でファイルが変わると、未編集なら黙って追従し、
  編集中なら知らせる
- `Mod` は `Ctrl` / `Cmd` どちらでも同じ
- 大文字のキー(`Shift+H` など)は**実際に Shift を押している**ときだけ効く。
  CapsLock で `h` が `H` になっても移動キーのまま扱われる

#### 文書の名前

「無題」という状態は持たない。**名前は本文から導く**ので、`# 設計メモ` と
打った瞬間からその文書は `設計メモ.md` と呼ばれる。同じ名前が保存ダイアログの
初期値にもなる。上から順に、最初に成立したものを使う:

1. **保存したファイル名** — 開いた/保存した後は常にこれ。見出しを書き替えても追わない
   (ファイル名はディスク上の識別子、見出しは内容の名前。役割が違うので一致させない)
2. **いちばん大きい見出しのうち先頭** — 文書内で `#` がいちばん少ないもの。
   同じ大きさが並べば先に書いたほうが勝つ。`##` しか無ければそれがいちばん大きい
3. **(2 が整形で空になったら) 文書順で最初の見出し**
4. **`empty`**

ファイル名に使えない文字(`\ / : * ? " < > |` と制御文字)は落として `-` で繋ぐ
(`設計/検討` → `設計-検討`)。空白はそのまま残す。長さは UTF-8 250 バイトで
打ち切る — `.md` を足しても実際の上限 255 に収まるようにするためで、
見た目を整えるためではない(日本語 83 文字ぶんあり、普段は触れない)。
道具が出す名前は**常にファイル名として有効**であることを守る。

**リネームは持たない。** ネイティブなら技術的には可能だが、mmm は文書の
**中身**を扱う道具で、ファイルの管理はしない。名前を変えたいときはエクスプローラで
変える — 次に開けば新しい名前で認識される。`Mod+Shift+S` は別名で保存する操作で、
元のファイルはそのまま残る。

### レイアウト規則

- `#` 見出しは**いくつあってもよい**。2 つ目以降はそれぞれが**独立した別ツリー**になり、
  マップ下部に順に積まれる(以前は構造から外していたが、テキストに在るのにマップから
  消えて選択も移動もできなかったため改めた)
- `#` より**前**に書かれたノード群も同じく**別ツリー**として下部に表示される
- レイアウトは**左右の水平展開のみ**

#### `---` による左右の振り分け

`---` は「**そこから下のルート直下ノードは、左右が入れ替わる**」という印。
区切りが無ければ全部右、タイトル直後に 1 本置けば全部左。途中に置けば
そこで切り替わる。複数あれば、そのたびに切り替わる（パーサーはどの `---` も
一律に読む）。

区切りとして有効なのは、次の 5 つをすべて満たすときだけ。

1. フェンスの外にある
2. 直前の行が本文の行でない(CommonMark では段落の直後の `-` だけの行は
   setext 見出しの下線 = `##` と等価なので、区切りにしてはいけない。
   `***` や `- - -` は本文直後でも水平線)
3. 次に来る非空白が見出しである(本文が挟まればただの水平線)
4. その見出しが `##` 以下である(`#` は常に別ツリーなので振り分ける先がない)
5. ルート(最初の `#`)が既に現れている位置にある

`***` `___` `- - -` も同じ扱い(CommonMark ではこの 3 つは同一の thematic break)。
front matter の区切り線は 5 によって自動的に除外される。区切り行はどのノードの
範囲にも属さないので、コピーや削除に付いてくることはない。
区切りの直後の見出しは、書かれた深さに関わらずルートの子として読む。

```md
# ルート

## 右に出るノード

---

## 左に出るノード

### その子(側は親に従う)
```

マップ側は左右の振り分けだけを描く。区切り線や区間ごとの余白は持たない —
`---` は「どちら側に置くか」を決める印であって、まとまり(グループ)を作る
記法ではない。同じ側に並んだノードは、区切りを跨いでいても 1 つの列。

##### 読みは寛容に、書きは保守的に

パーサーは複数の `---` を受け入れるが、**マップの操作が区切りを書くのは
「空の左側へ最初のノードを置く」ときの 1 本だけ**。それ以外の操作
(合流・移動・削除)はすべて既存ノードの隣への局所編集で、区切りを増やさない。
つまり道具が書いた文書の `---` は常に 1 本以下で、複数あるならそれは
人間が意図して書いたもの。

消すときは逆向きの注意がある。`---` を 1 本消すと、そこから下の左右が
全部反転してしまう。そのためノードの移動や削除で中身の無くなった区間の
区切りは、**下の左右が変わらないように偶数本ずつ**片付ける
(中間の区間なら両脇の 2 本。末尾なら手前の 1 本だけ — 下に何も無いので
反転しない。先頭の区間が空いて残る「タイトル直後の `---`」は
「全部左」の正しい表現なので消さない)。

**編集**

|---|---|
| `Mod+Enter` / `i` `a` `A` / ダブルクリック | 編集開始(カーソルは末尾) |
| `I` | 編集開始(カーソルは先頭) |
| `Enter` / `Esc` / `Mod+Enter` | 編集確定(キャンセルは存在しない。編集中の `Tab` は無効) |
| 編集中ノードのクリック | カーソル移動(確定しない) |

**新規作成**(作成後そのまま編集開始)

| 操作 | 動作 |

| `Enter` / `o` | 下の兄弟 |
| `O` | 上の兄弟 |
| `Tab` | 子要素(`Ctrl+Tab` はブラウザ予約と衝突する場合あり) |
| `Shift+Tab` | 親要素を作成(現ノードを包む) |
| ルートのホバー `+` | 右 `+` = 右側の末尾に子、左 `+` = 左側の末尾に子(左が空なら `---` を書いて開く) |

### コンテンツカード(リンク / コード / SVG / 画像)

ノードの**添付コンテンツ**(見出し直下の本文)は、内容に応じてノード下部に
カード行として縦に積まれる(あわせて最大 4 行):

- `[タイトル](URL)` または素の URL の行 → リンクカード。`↗` クリックで新しい
  タブで開く(外部通信はしない)。ラベル自体が URL のノードはただのテキスト
- ` ``` ` フェンスのコードブロック → モノスペースのプレビュー(6 行まで、
  以降は `…`。言語はツールチップ)
- `<svg>…</svg>` ブロック → そのまま描画(data URL 経由の静的表示)
- `![](相対パス)` → 画像サムネイル(下記)

ポップアップからも追加できる: ノードを選択して `Shift+L`(リンク)/
`Shift+C`(コード)/ `Shift+D`(お絵描き — canvas に描いて WebP として保存)。
確定は `Mod+Enter` かボタン、キャンセルは `Esc`。挿入は 1 回の Undo で戻せる。

### 画像(ローカルファースト)

画像は md の**相対パス**で書き(`![](./x.webp)`、`![](../pics/y.png)`)、
現在の md のある場所を基準に、ネイティブ本体が解決する。基準は md の位置
そのものなので、フォルダの許可も指定も要らない — ブラウザで格闘した
「隣の画像に辿れない」問題は、ネイティブでは存在しない。

**画像ファイルをノードの上にドロップする**のが一番手軽:

- md の木の中(隣・サブフォルダ)にある画像は、**複製せずそのまま指す**
  (`./x.webp` や `./sub/x.png`)
- 木の外(別ドライブや `../` の外)から来た画像だけ、md の隣に複製する
- 何枚まとめて落としても、取り消しは 1 回

ノードの外に落としたものは受け取らない — どこに付いたか分からない貼り方は
しない。`.md` を落としたときはその md を開く。

クリップボードから貼るときは、ノードを選択して `Mod+V`:

1. 画像名を入力(`/` を含めるとサブフォルダ、`assets/shot` など)
2. WebP に変換して md からの相対パスへ保存し、添付コンテンツに
   `![](./名前.webp)` を挿入(1 回の Undo で戻せる)
3. マップ側は添付コンテンツ内の `![](相対パス)` 行をサムネイルとして表示

どちらも現在ファイルを保存済みであることが要る(未保存だと相対パスの基準に
なる場所が無い)。読み込めない画像は点線のプレースホルダにファイル名で
表示される。`https://` の画像は外部通信になるため表示しない。md 側の記述は
ただの相対パス画像なので、他のエディタや GitHub でもそのまま表示できる。

### Hide/Show = 折り畳み(コメントアウトで無効化)

`Shift+H`(または右クリックメニュー)で選択ノードのサブツリー全体を
`<!--` / `-->` の行で包む。md としてはただの HTML コメントなので
**GitHub などの外部レンダラでは消える**。

マップ上では**折り畳みを兼ねる**:

- 対象ノードは小さく薄く表示され、`+3` のように**折り畳んだ子孫の数**が付く
- **子孫はマップから消える**(レイアウトからも外れるので場所を取らない)
- そのノードで `Shift+H` をもう一度押すか、右クリックメニューの
  「再表示」で戻る

マーカーの判定は**エディタや GitHub と同じ**にしてある: `<!--` は追加の
ハイフンが付いていてもよく(`<!---`)、閉じ側は 2 個以上のハイフン + `>`
なら閉じる(`-->` `--->` いずれも可)。ハイフン 1 個の差で「閉じたつもりが
閉じておらず以降が全部消える」のを避けるため。コードフェンス内は対象外。
入れ子の Hide は不可(既にマーカーを含むサブツリーの Hide は無視される)。

### ペインの表示/非表示

ヘッダーの **MD** / **マップ** ボタン(押されている側は塗りつぶし、
オフ側は取り消し線)で各ペインを隠して片方を全幅表示できる
(最後の 1 枚を隠すと反対側が表示される)。スプリッタの**ダブルクリック**でも
MD ペインを折り畳める。`Mod+/` は隠れているペインを再表示してフォーカスする。
どちらを出しているかは覚えない — 起動は毎回、両方から。

### エクスポート

ヘッダーの **SVG** / **WebP** ボタンでマップ全体を画像として保存できる
(スタイル・サムネイルを埋め込んだ自己完結ファイル。選択状態は含まれない)。
それぞれの隣の **⧉** ボタンでダウンロードの代わりにクリップボードへコピー
(SVG はテキスト、WebP は PNG 画像としてコピーされる)。

### 改行の扱い

アプリの中では**常に LF** で持つ。CRLF の .md を開いた場合は読み込み時に LF へ
正規化し、**保存するときだけ元の CRLF へ書き戻す**。改行種別はそのファイルを
読んだときに決まる(覚えておかない — 読み直せば分かることなので)。

CodeMirror は読み込んだ文書の改行を内部で LF に正規化するのに対し、コアは
渡されたバイト列をそのまま保持する。両者に別々の改行を渡すと文字位置が
ずれて、打鍵が見当違いの場所に書き込まれる。これを避けるための統一。

改行が混在したファイルは、保存時に元ファイルの主たる改行へ揃えられる。

### その他

- ヘッダーのロゴをクリックするとブランドカラーを変更できる(favicon にも反映、保存される)
- ヘッダーの ◑ でライト/ダークテーマ切り替え(初期値は OS 設定、不明ならダーク)
- localStorage に残すのは**ブランドカラーとテーマだけ**。本文の控えは持たない
  — 持てばディスクの .md と二重の真実になる
- 覚えているのは**最後に編集していたファイルのパス**だけ(Rust の app-config)。
  起動時に**ディスクからそのファイルを読み直す**。ファイルが消えていれば
  まっさらから始まる。未保存のスクラッチは残らない
- 保存・読み込みの失敗はヘッダーのファイル名欄に表示される(キャンセルは無表示)

### 全体

`Mod+Z` / `Mod+Shift+Z` … Undo / Redo(両ペイン共通の単一スタック)、`Mod+/` … ペイン切り替え
